# Generated Reports

These reports are auto-generated by the framework's tools to demonstrate project visibility.

## Available Reports

### 📊 dashboard.txt
**Command:** `bash .agentic/tools/dashboard.sh`

Quick overview of project status, current focus, and next priorities.

### 📈 feature-report.txt
**Command:** `bash .agentic/tools/report.sh`

Summary of feature status (shipped, in_progress, planned) with actionable tips.

### 🔗 feature-graph.md
**Command:** `python3 .agentic/tools/feature_graph.py`

Mermaid diagram showing feature dependencies. Paste into GitHub/Markdown viewer to visualize.

### 🏥 health-check.txt
**Command:** `python3 .agentic/tools/doctor.py`

Project health check identifying incomplete templates, potential issues, and suggested next steps.

### ✅ spec-verification.txt
**Command:** `python3 .agentic/tools/verify.py`

Validates cross-references between specs, checks for broken links, and ensures acceptance files exist.

### 📝 test-coverage.txt
**Command:** `python3 .agentic/tools/coverage.py`

Shows which features have code annotations (`@feature F-####`) and test coverage per feature.

## How to Regenerate

From the project root:

```bash
# Individual reports
bash .agentic/tools/dashboard.sh
bash .agentic/tools/report.sh
python3 .agentic/tools/feature_graph.py
python3 .agentic/tools/doctor.py
python3 .agentic/tools/verify.py
python3 .agentic/tools/coverage.py

# Or save to reports/ directory
bash .agentic/tools/dashboard.sh > reports/dashboard.txt
python3 .agentic/tools/feature_graph.py > reports/feature-graph.md
# etc.
```

## When to Run

- **dashboard.sh**: Anytime (quick status check)
- **report.sh**: After feature status changes
- **feature_graph.py**: When adding/changing feature dependencies
- **doctor.py**: Weekly or before retrospectives
- **verify.py**: Before commits (catch broken refs early)
- **coverage.py**: After adding `@feature` annotations to code

## Integration

These tools help:
- **Humans**: Quickly understand project state without reading all specs
- **AI Agents**: Get structured project info for context-efficient sessions
- **Teams**: Share project status in standups/reports
- **Retrospectives**: Identify patterns and issues

## Note

These are **demo snapshots** showing what the tools output. In a real project, you'd run these commands as needed rather than committing the output files (unless you want historical snapshots).
