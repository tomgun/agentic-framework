# F-0002: localStorage Persistence

## User Story
As a user, my tasks persist across browser sessions so I don't lose my work.

## Acceptance Criteria

### Save
- [ ] Tasks are saved to localStorage after any change (create/update/delete)
- [ ] Save operation is atomic (uses temp + replace pattern)
- [ ] Save failures show user-friendly error message
- [ ] App remains functional even if storage fails (in-memory fallback)

### Load
- [ ] Tasks load automatically on app start
- [ ] Corrupted JSON data shows error and starts fresh (doesn't crash app)
- [ ] Empty/missing storage file loads as empty task list
- [ ] Load time <100ms even with 1000 tasks

### Edge Cases
- [ ] localStorage quota exceeded: show warning, offer export
- [ ] Private browsing mode (storage unavailable): show warning, use in-memory
- [ ] Multiple tabs open: last write wins (no conflict resolution in MVP)
- [ ] Browser clears localStorage: graceful empty state

## Performance
- Save operation: <10ms
- Load operation: <50ms
- No UI blocking during save/load

## Out of Scope
- Multi-tab sync (future)
- Cloud backup (future)
- Storage migration/versioning (future)
