# F-0131: Settings-Over-Profiles Architecture

## Acceptance Criteria

### Infrastructure
- [ ] `.agentic/lib/settings.sh` exists with `get_setting()` function
- [ ] `.agentic/lib/settings.py` exists with `get_setting()` function
- [ ] `.agentic/presets/profiles.conf` defines discovery and formal presets
- [ ] `.agentic/presets/constraints.conf` defines constraint rules
- [ ] `STACK.template.md` has `## Settings` section

### Resolution Chain
- [ ] Explicit value in STACK.md `## Settings` section takes priority
- [ ] Profile preset from profiles.conf is used when no explicit value
- [ ] Fallback default is used when neither explicit nor preset exists
- [ ] Backward compatibility: STACK.md without `## Settings` section still works (whole-file search)

### ag set Command
- [ ] `ag set --show` displays all resolved settings with sources
- [ ] `ag set --validate` checks constraint rules
- [ ] `ag set --migrate` adds `## Settings` section to existing STACK.md
- [ ] `ag set <key> <value>` updates settings in STACK.md
- [ ] Enum value validation rejects invalid values (e.g., `ag set profile bogus`)

### Conversion Completeness
- [ ] No remaining `profile == "formal"` / `profile == "discovery"` branching in framework logic (except profile resolution itself)
- [ ] All bash scripts source `settings.sh` and use `get_setting()`
- [ ] All python scripts import `settings.py` and use `get_setting()`

### Settings Inventory
- [ ] `feature_tracking` (yes/no) controls feature ID and spec requirements
- [ ] `acceptance_criteria` (blocking/recommended/off) controls spec enforcement level
- [ ] `wip_before_commit` (blocking/warning) controls WIP gate behavior
- [ ] `pre_commit_checks` (full/fast/off) controls pre-commit gate level
- [ ] `git_workflow` (pull_request/direct) controls branch policy
- [ ] `plan_review_enabled` (yes/no) controls plan-review loop
- [ ] `spec_directory` (yes/no) controls spec/ directory requirement
- [ ] `max_files_per_commit` (integer) controls batch size limit
- [ ] `max_added_lines` (integer) controls added lines limit
- [ ] `max_code_file_length` (integer) controls file length limit

### Bash/Python Parity
- [ ] Both libraries resolve the same values for the same input
- [ ] Both use same whitespace trimming (no `tr -d ' '` vs `.strip()` mismatch)
- [ ] Python library caches parsed results within same process

### Tests
- [ ] Framework validation tests cover: file existence, function existence, resolution chain, backward compat, constraints
- [ ] LLM behavioral tests verify agents respond to individual settings (not profile names)
- [ ] phase_detect.py unit tests updated for new return values

### Upgrade Path
- [ ] `upgrade.sh` copies `lib/` and `presets/` directories
- [ ] `upgrade.sh` adds `## Settings` section migration step
- [ ] `scaffold.sh` creates proper `## Settings` section for new projects
