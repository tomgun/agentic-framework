# F-0021: Session Start Protocol - Acceptance Criteria

**Feature**: Mandatory steps when starting a work session

**Version**: 0.6.0

---

## Acceptance Criteria

### Checklist Exists

- [x] **AC-001**: `session_start.md` exists in `.agentic/checklists/`
- [x] **AC-002**: Checklist is first step in agent_operating_guidelines.md

### WIP Check (FIRST!)

- [x] **AC-010**: WIP check is the FIRST mandatory step
- [x] **AC-011**: If .agentic/WIP.md exists, agent follows recovery protocol
- [x] **AC-012**: If .agentic/WIP.md is stale (>60 min), treat as interrupted work

### Context Reading

- [x] **AC-020**: Checklist requires reading CONTEXT_PACK.md
- [x] **AC-021**: Checklist requires reading STATUS.md (or PRODUCT.md in Core)
- [x] **AC-022**: Checklist requires reading recent JOURNAL.md entries
- [x] **AC-023**: Checklist requires checking HUMAN_NEEDED.md for blockers

### Proactive Context

- [x] **AC-030**: Agent identifies planned work (from STATUS or FEATURES)
- [x] **AC-031**: Agent surfaces any outstanding blockers
- [x] **AC-032**: Agent presents "what's next" to user

### Hook Enforcement

- [x] **AC-040**: `session-start.sh` hook enforces mandatory reading
- [x] **AC-041**: Hook exits 1 if WIP detected without recovery
- [x] **AC-042**: Hook is profile-aware (Core vs Core+PM)

---

## Validation Commands

```bash
# Check session_start.md exists
cat .agentic/checklists/session_start.md

# Check session-start.sh hook
cat .agentic/hooks/session-start.sh

# Test WIP detection
touch .agentic/WIP.md
bash .agentic/hooks/session-start.sh  # Should warn about WIP
rm .agentic/WIP.md
```

## Test Scenarios

### Scenario 1: Clean Session Start

**Given**: No .agentic/WIP.md, project in good state
**When**: Agent starts session
**Then**: Reads context files, presents "what's next" to user

### Scenario 2: Interrupted Work Detected

**Given**: .agentic/WIP.md exists from previous session
**When**: Agent starts session
**Then**: Agent runs `wip.sh check`, follows recovery.md

### Scenario 3: Blockers Exist

**Given**: HUMAN_NEEDED.md has unresolved items
**When**: Agent starts session
**Then**: Agent surfaces blockers: "Before we start, these need attention..."

### Scenario 4: Core Profile

**Given**: Project using Core profile (no spec/)
**When**: Agent starts session
**Then**: Reads PRODUCT.md instead of STATUS.md, adapts accordingly
