# F-0092: Phase Detection - Acceptance Criteria

## AC-001: Script Exists and Runs

**Given** the framework
**When** checking `.agentic/tools/`
**Then** `phase_detect.py` exists with:
- Executable permissions
- Python 3 compatible
- No external dependencies required

## AC-002: Phase Detection Logic

**Given** a project using the framework
**When** running `python3 .agentic/tools/phase_detect.py`
**Then** it detects one of these phases:
- `start`: No active work (no .agentic/WIP.md, no in_progress features)
- `planning`: Feature started but needs acceptance criteria
- `implement`: Has acceptance criteria, coding in progress
- `complete`: Ready for final verification
- `blocked`: Has unresolved blockers in HUMAN_NEEDED.md

## AC-003: Detection Based on Project State

**Given** various project states
**When** phase_detect.py analyzes the project
**Then** it correctly identifies:
- `start` when: no .agentic/WIP.md, no features in_progress
- `planning` when: feature in_progress but no acceptance file
- `implement` when: acceptance exists, impl-state != complete
- `complete` when: impl-state = complete, tests = complete
- `blocked` when: HUMAN_NEEDED.md has open items

## AC-004: Output Format

**Given** phase_detect.py
**When** run with different options
**Then** it supports:
- Plain text output (default): just the phase name
- JSON output (--json): structured data with phase and reasons
- Verbose output (-v): explanation of why phase was detected

## AC-005: Integration with Doctor.sh

**Given** doctor.sh with --phase option
**When** phase is not specified
**Then** doctor.sh calls phase_detect.py to auto-detect phase
