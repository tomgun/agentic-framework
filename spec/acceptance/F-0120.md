# F-0120: Plan-Review Loop - Acceptance Criteria

## Overview
Iterative planning with critical review before implementation. Two-agent loop (planner + reviewer) catches issues before code is written.

## Acceptance Criteria

### AC-1: Configuration in STACK.md
- [ ] `plan_review_enabled` setting (yes/no)
- [ ] `plan_review_max_iterations` setting (default: 3)
- [ ] `plan_review_auto_for` setting (planning/implement/both)
- [ ] Optional `plan_review_reviewer_model` override
- [ ] Defaults: enabled for Core+PM, disabled for Core

### AC-2: Plan Artifact
- [ ] Plans written to `.agentic-state/plans/F-XXXX-plan.md`
- [ ] Plan format includes: Context, Approach, Steps, Files, Testing, Risks
- [ ] Status tracking: DRAFT → REVIEWING → REVISION_NEEDED → APPROVED
- [ ] Iteration counter increments on each revision
- [ ] Review history preserved in plan file

### AC-3: Planner Agent Behavior
- [ ] Reads acceptance criteria and CONTEXT_PACK before planning
- [ ] Creates comprehensive plan following template
- [ ] On revision: addresses all CRITICAL/IMPORTANT issues
- [ ] Documents how each issue was addressed

### AC-4: Reviewer Agent Behavior
- [ ] Adopts adversarial/critical mindset
- [ ] Checks plan against acceptance criteria
- [ ] Categorizes issues: CRITICAL, IMPORTANT, SUGGESTION
- [ ] Sets verdict: APPROVED, REVISION_NEEDED, or ESCALATE
- [ ] Does not rubber-stamp (finds real issues)

### AC-5: Loop Behavior
- [ ] Loop continues until APPROVED or max_iterations reached
- [ ] On max_iterations: status becomes ESCALATED, human notified
- [ ] On ESCALATE verdict: loop stops, human notified
- [ ] Human can edit plan and set APPROVED to bypass

### AC-6: Integration with ag Commands
- [ ] `ag plan F-XXXX` triggers plan-review loop (when enabled)
- [ ] `ag plan --no-review` skips review loop
- [ ] `ag implement` checks for approved plan first (when auto_for includes implement)
- [ ] If no approved plan, runs plan-review loop before implementation

### AC-7: Claude Code Support
- [ ] Task tool spawns planner with Plan subagent type
- [ ] Task tool spawns reviewer with general-purpose type
- [ ] Models selected based on agent_mode in STACK.md
- [ ] Plan file passed between agents correctly

### AC-8: Cursor Support
- [ ] Plan agent role defined in .cursor/agents/
- [ ] Review agent role defined in .cursor/agents/
- [ ] Orchestrator can coordinate the loop

## Out of Scope
- Parallel planning (multiple plans for same feature)
- Automated plan comparison/selection
- Integration with external planning tools

## Test Scenarios

1. **Happy path**: Plan approved after 1 revision
2. **Multiple iterations**: Plan needs 2-3 revisions before approval
3. **Escalation**: Reviewer escalates, human intervenes
4. **Max iterations**: Hits limit, human notified
5. **Skip review**: `--no-review` flag works
6. **No plan exists**: `ag implement` creates plan first
