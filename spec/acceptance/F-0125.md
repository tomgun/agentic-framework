# F-0125: Unified Drift Detection (`ag sync`)

## Acceptance Criteria

### 5-Phase Detection
- [x] Phase 1 (Memory): Detects stale/missing memory seed via `memory-check.sh`
- [x] Phase 2 (State freshness): Detects stale JOURNAL.md and STATUS.md (>24h since last update)
- [x] Phase 3 (Feature reconciliation): Detects feature status mismatches between FEATURES.md and code
- [x] Phase 4 (Spec/doc drift): Detects spec and documentation inconsistencies
- [x] Phase 5 (Tool parity): Detects tool files missing trigger tables or other framework patterns

### Modes
- [x] `ag sync` — full sync: detect + auto-fix safe errors (e.g., STATUS.md inference)
- [x] `ag sync --check` — dry run: detect only, no modifications
- [x] `ag sync --quiet` — probe mode: single-line summary for `ag start` integration

### Integration
- [x] `ag.sh` dispatches `sync` command to `sync.sh`
- [x] `ag start` runs `--quiet` probe and shows yellow warning if issues found
- [x] Help text updated for both Discovery and Formal profiles

### Design Constraints
- [x] User-initiated only (not auto-run every session — token cost)
- [x] Safe fixes applied automatically; everything else is report-only with suggested commands
- [x] Exit code 0 when clean, non-zero when issues detected
