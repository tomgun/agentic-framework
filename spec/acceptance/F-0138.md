# F-0138: Documentation Impact Tracking - Acceptance Criteria

**Feature**: Systematic documentation update process wired into feature completion

---

## Acceptance Criteria

### CONTEXT_PACK.md Template

- [x] **AC-001**: `.agentic/init/CONTEXT_PACK.template.md` contains a `## Documentation` section
- [x] **AC-002**: Template section includes a comment explaining its purpose (5-8 entries, helps agents know where to add new content)
- [x] **AC-003**: Framework's own `CONTEXT_PACK.md` has a populated `## Documentation` section with 8 entries covering all key docs

### STACK.md & Profiles

- [x] **AC-004**: `.agentic/init/STACK.template.md` `## Settings` comments include `docs_gate` with values `off | warning | blocking`
- [x] **AC-005**: `.agentic/presets/profiles.conf` has `discovery.docs_gate=off` and `formal.docs_gate=blocking`
- [x] **AC-006**: Framework's `STACK.md` has `docs_gate: blocking` set in `## Settings`

### ag done Integration

- [x] **AC-007**: `ag done F-####` on formal profile (docs_gate=blocking) runs `drift.sh --docs --manifest F-####` and prints drift results
- [x] **AC-008**: With `docs_gate: blocking`, after printing drift results, agent is prompted to confirm before marking complete
- [x] **AC-009**: With `docs_gate: warning`, drift results are printed but no confirmation required
- [x] **AC-010**: With `docs_gate: off` (discovery default), no doc check runs at all
- [x] **AC-011**: `ag done` without feature ID (or missing manifest) falls back to `drift.sh --docs` without manifest flag
- [x] **AC-012**: `ag set docs_gate <value>` validates values as `off | warning | blocking`

### auto_orchestration.md

- [x] **AC-013**: `auto_orchestration.md` Enforced Gates table includes `docs_gate` row with Formal=blocking, Discovery=off

### Documentation Agent

- [x] **AC-014**: `documentation-agent.md` includes concrete process: read CONTEXT_PACK.md docs list → run drift.sh → update flagged + new-content docs
- [x] **AC-015**: Documentation agent process explicitly calls out to check README.md for user-facing changes even if not flagged by drift.sh

### Validation

- [x] **AC-016**: `bash tests/validate_framework.sh` passes with all changes in place (15 new F-0138 tests)

## LLM Behavioral Tests (tests/llm/test_definitions.json)

- **LLM-062** (`062_doc_update_uses_context_pack`): Agent updating docs after a feature references `CONTEXT_PACK.md ## Documentation` to find what docs exist and mentions running `drift.sh`
- **LLM-063** (`063_docs_gate_blocking_awareness`): Agent can explain that `docs_gate` + `ag done` enforce doc updates, and knows about the off/warning/blocking values
