# F-0091: Gate-Based Verification - Acceptance Criteria

## AC-001: Doctor.sh Single Entry Point

**Given** the framework
**When** running `bash .agentic/tools/doctor.sh`
**Then** it performs basic health checks and returns:
- Clear pass/fail output for each check
- Exit code 0 for success, non-zero for failures
- Summary of issues found

## AC-002: Full Verification Mode

**Given** the framework
**When** running `bash .agentic/tools/doctor.sh --full`
**Then** it runs ALL verification checks including:
- Spec validation (replaces standalone verify.sh)
- Spec-to-code consistency
- Format validation
- Untracked files check
- WIP check
- Unified output report

## AC-003: Phase-Specific Mode

**Given** the framework
**When** running `bash .agentic/tools/doctor.sh --phase X`
**Then** it runs checks appropriate for phase X:
- `start`: WIP check, context files exist
- `planning`: Acceptance criteria exists
- `implement`: Tests exist, code compiles
- `complete`: All criteria met, docs updated
- `commit`: Pre-commit validations

## AC-004: Pre-Commit Mode

**Given** the framework
**When** running `bash .agentic/tools/doctor.sh --pre-commit`
**Then** it runs fast checks suitable for git pre-commit hook:
- WIP cleared
- No untracked project files
- Batch size warning
- Quick validation

## AC-005: Doctor.py Integration

**Given** `.agentic/tools/doctor.py`
**When** imported or run
**Then** it provides programmatic access to verification with:
- Function-based API for each check type
- JSON output option
- Integration with phase detection

## Verification

- [ ] AC-001: doctor.sh runs basic checks
- [ ] AC-002: doctor.sh --full runs comprehensive checks
- [ ] AC-003: doctor.sh --phase runs phase-appropriate checks
- [ ] AC-004: doctor.sh --pre-commit runs fast pre-commit checks
- [ ] AC-005: doctor.py provides programmatic access
