# F-0103: Agent Mode Selection (Quality vs Cost)

## Overview
Allow users to choose an agent quality/cost tradeoff mode that affects model selection across all agent tasks. Support model customization for fine-tuning.

## Acceptance Criteria

### AC1: STACK.md supports agent_mode setting
**Given** a project with STACK.md
**When** the user adds `agent_mode: full_steam|premium|balanced|economy`
**Then** agents read this setting and adjust model selection accordingly

### AC2: Default mode is balanced
**Given** a project without explicit agent_mode setting
**When** an agent starts a session
**Then** it uses balanced mode (opus for planning, sonnet for implementation)

### AC3: Planning/speccing always uses best available in mode
**Given** any agent mode (full_steam, premium, balanced, economy)
**When** an agent performs planning, architecture, or spec writing tasks
**Then** it uses the best model for that mode:
- full_steam/premium/balanced: opus
- economy: sonnet

### AC4: Mode affects implementation model selection
**Given** agent_mode is set in STACK.md
**When** an agent performs implementation tasks
**Then** model selection follows the mode:
- full_steam: opus
- premium: sonnet
- balanced: sonnet
- economy: haiku

### AC5: full_steam mode uses best for everything
**Given** agent_mode is set to full_steam
**When** an agent performs ANY task (including search/exploration)
**Then** it uses opus (best) for all tasks

### AC6: Model customization supported
**Given** a project with STACK.md
**When** the user adds a `models:` section with task-specific overrides
**Then** agents use the custom models instead of mode defaults
**Example**:
```yaml
- models:
    planning: opus
    implementation: sonnet
    search: haiku
```

### AC7: Documentation reflects mode-aware recommendations
**Given** CLAUDE.md and agent_operating_guidelines.md
**When** a user reads the delegation documentation
**Then** they see:
- Clear mode descriptions (including full_steam)
- Model recommendations per mode per task type
- Guidance on when to use each mode
- How to customize models

### AC8: Dedicated documentation exists
**Given** the framework
**When** a user wants to understand agent_mode in depth
**Then** they can read `.agentic/workflows/agent_mode.md` which explains:
- What agent_mode is and why it matters
- All available modes with use cases
- How to customize models
- Cost comparison guidance

### AC9: STACK.template.md includes agent_mode and models
**Given** a new project installation
**When** scaffold.sh creates STACK.md
**Then** it includes:
- `agent_mode: balanced` with comment explaining options
- Commented `models:` section for customization

### AC10: LLM behavioral tests exist
**Given** the test suite
**When** running LLM tests
**Then** tests verify:
- Agent reads agent_mode from STACK.md
- Agent selects correct model based on mode
- full_steam mode uses opus for everything

## Test Scenarios

### Scenario 1: full_steam mode delegation
```
Given STACK.md contains "agent_mode: full_steam"
When agent needs to perform any task
Then it uses opus model for everything
- Planning: opus
- Implementation: opus
- Search: opus
```

### Scenario 2: Premium mode delegation
```
Given STACK.md contains "agent_mode: premium"
When agent needs to plan architecture
Then it uses opus model
And implementation uses sonnet
And exploration uses haiku
```

### Scenario 3: Economy mode delegation
```
Given STACK.md contains "agent_mode: economy"
When agent needs to plan architecture
Then it uses sonnet model (not opus)
And implementation uses haiku
And exploration uses haiku
```

### Scenario 4: Default behavior
```
Given STACK.md does not contain agent_mode
When agent reads STACK.md
Then it defaults to balanced mode
```

### Scenario 5: Custom model override
```
Given STACK.md contains:
  agent_mode: economy
  models:
    planning: opus
When agent needs to plan architecture
Then it uses opus (override) instead of sonnet (economy default)
```

## Notes

- **Philosophy**: Planning and speccing set direction for everything. Bad specs = wasted implementation tokens. Worth spending on quality there.
- **Mode names**: "full_steam" = maximum quality, "premium" = high quality, "balanced" = good default, "economy" = cost saving
- **Balanced default**: Most users want good results without excessive cost
- **Customization**: Users can fine-tune models per task type for optimal workflow
