# F-0192: Review Subagent Delegation - Acceptance Criteria

**Feature**: The /review skill delegates work to a fresh-context subagent instead of running inline.

---

## Behavior (what the user needs — technology-agnostic)

When a user triggers `/review`, the review work (reading diffs, source files, checklists, plan files) happens in a subagent with its own context window. The main conversation receives only a compact structured report of findings. This prevents review artifacts from bloating the main context.

---

## Acceptance Criteria

### Core Behavior (P1 — MVP)
**Verify independently**: Trigger `/review` and confirm subagent is launched

- [ ] **AC-001**: When `/review` is triggered, the skill instructs the main agent to launch a subagent (via Agent tool) rather than performing review steps inline
- [ ] **AC-002**: The subagent receives the full review checklist, scope (diff target or PR number), and plan file path if applicable
- [ ] **AC-003**: The subagent returns a structured findings report (Must Fix / Should Fix / Consider) to the main context
- [ ] **AC-004**: The main context does NOT contain raw diffs, file contents, or checklist references from the review — only the summary

### Edge Cases

- [ ] **AC-005**: When reviewing a specific PR number (`/review PR #42`), the PR number is passed to the subagent correctly
- [ ] **AC-006**: When no changes exist to review, the subagent reports "no changes found" rather than erroring

---

## Verification

### Tests

#### Behavioral / LLM Tests
- [ ] **TEST-001**: `/review` prompt → agent should spawn a subagent (not read diffs inline)
- [ ] **TEST-002**: Subagent output should contain severity-grouped findings format

---

## Out of Scope

- Changing the review checklist content itself
- Adding new review dimensions
- Modifying the context-for-role manifest (review-agent.yaml) — that's for multi-agent pipelines, not skill invocation
