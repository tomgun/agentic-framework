# F-0066: Template Quality - Acceptance Criteria

**Feature**: All templates are well-documented with examples and clear placeholders

**Version**: 0.1.0

---

## Acceptance Criteria

### Templates Exist

- [x] **AC-001**: `STACK.template.md` exists with all config options
- [x] **AC-002**: `PRODUCT.template.md` exists for Core profile
- [x] **AC-003**: `FEATURES.template.md` exists for feature tracking
- [x] **AC-004**: `HUMAN_NEEDED.template.md` exists for blockers

### Placeholder Quality

- [x] **AC-010**: Placeholders use clear format: `<!-- fill -->` or `[description]`
- [x] **AC-011**: Each placeholder has context explaining what to fill
- [x] **AC-012**: Required vs optional fields are distinguished

### Examples Provided

- [x] **AC-020**: Templates include example content (commented or in .reference.md)
- [x] **AC-021**: Examples are realistic and helpful
- [x] **AC-022**: Complex sections have inline guidance

### Usability

- [x] **AC-030**: Templates are not overwhelming (start simple)
- [x] **AC-031**: Root templates are minimal (examples in .reference.md)
- [x] **AC-032**: Templates work out-of-box with minimal editing

---

## Validation Commands

```bash
# Check templates exist
ls -la .agentic/init/*.template.md
ls -la .agentic/spec/*.template.md

# Check placeholders are clear
grep -n "<!-- " .agentic/init/STACK.template.md | head -10

# Check reference files exist
ls -la .agentic/spec/*.reference.md
```

## Test Scenarios

### Scenario 1: First-Time Setup

**Given**: Developer initializing new project
**When**: They open STACK.template.md
**Then**: They understand what to fill and have examples to follow

### Scenario 2: Feature Definition

**Given**: Developer adding new feature
**When**: They use FEATURES.template.md
**Then**: They know required fields, have format examples

### Scenario 3: Minimal Start

**Given**: Developer wants quick start
**When**: They use templates
**Then**: Templates work with minimal changes (sensible defaults)
