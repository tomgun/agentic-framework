# Acceptance Criteria: F-0134 — DEVELOPER_GUIDE Rewrite

## Must have
- [ ] User-facing sections use natural workflow language, not internal script commands
- [ ] `ag` commands mentioned only where user would actually run them (e.g., `ag set`)
- [ ] Agent-facing scripts (`ag implement`, `ag plan`, `ag commit`) described as "behind the scenes" or in an agent reference appendix, not as user instructions
- [ ] Settings system documentation is accurate for v0.27.0 (profiles as presets, `ag set` overrides)
- [ ] No stale references to removed features or old architecture
- [ ] Table of contents / navigation is coherent after restructure

## Should have
- [ ] Clear separation: "How to work with the framework" (user) vs "How the agent works" (reference)
- [ ] Examples showing natural user prompts → what happens behind the scenes
- [ ] Quick start section that gets a user productive in <2 minutes of reading

## Must not
- [ ] Tell users to memorize feature IDs or spec file paths
- [ ] Assume users have read FEATURES.md or spec/acceptance/
- [ ] Duplicate content that belongs in other docs (PRINCIPLES.md, INSTRUCTION_ARCHITECTURE.md)
