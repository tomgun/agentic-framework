# F-0103: Agent Mode Selection (Quality vs Cost)

## Overview
Allow users to choose an agent quality/cost tradeoff mode that affects model selection across all agent tasks. Support model customization for fine-tuning.

## Acceptance Criteria

### AC1: STACK.md supports agent_mode setting
**Given** a project with STACK.md
**When** the user adds `agent_mode: premium|balanced|economy`
**Then** agents read this setting and adjust model selection accordingly

### AC2: Default mode is balanced
**Given** a project without explicit agent_mode setting
**When** an agent starts a session
**Then** it uses balanced mode (opus for planning, sonnet for implementation/review)

### AC3: Four task types with distinct model selection
**Given** any agent mode
**When** an agent performs tasks
**Then** tasks are categorized into: planning, implementation, review, search
- planning: Architecture, specs, critical decisions
- implementation: Writing production code
- review: Code review, testing, refactoring
- search: Codebase exploration, finding files

### AC4: Mode affects model selection per task type
**Given** agent_mode is set in STACK.md
**When** an agent performs tasks
**Then** model selection follows the mode:

| Mode | planning | implementation | review | search |
|------|----------|----------------|--------|--------|
| premium | opus | opus | opus | sonnet |
| balanced | opus | sonnet | sonnet | haiku |
| economy | sonnet | haiku | haiku | haiku |

### AC5: Model customization supported
**Given** a project with STACK.md
**When** the user adds a `models:` section with task-specific overrides
**Then** agents use the custom models instead of mode defaults
**Example**:
```yaml
- models:
    planning: opus
    implementation: sonnet
    review: sonnet
    search: haiku
```

### AC6: Documentation reflects mode-aware recommendations
**Given** CLAUDE.md and agent_operating_guidelines.md
**When** a user reads the delegation documentation
**Then** they see:
- Clear mode descriptions (premium, balanced, economy)
- Model recommendations per mode per task type
- Guidance on when to use each mode
- How to customize models

### AC7: Dedicated documentation exists
**Given** the framework
**When** a user wants to understand agent_mode in depth
**Then** they can read `.agentic/workflows/agent_mode.md` which explains:
- What agent_mode is and why it matters
- All available modes with use cases
- Task type to agent mapping
- How to customize models
- Cost comparison guidance

### AC8: STACK.template.md includes agent_mode and models
**Given** a new project installation
**When** scaffold.sh creates STACK.md
**Then** it includes:
- `agent_mode: balanced` with comment explaining options
- Commented `models:` section for customization

### AC9: Init questions include agent_mode
**Given** a new project initialization
**When** the agent asks init questions
**Then** it asks about preferred agent_mode (premium/balanced/economy)

### AC10: LLM behavioral tests exist
**Given** the test suite
**When** running LLM tests
**Then** tests verify:
- Agent reads agent_mode from STACK.md
- Agent selects correct model based on mode

## Notes

- **Philosophy**: Planning sets direction for everything. Bad specs = wasted implementation tokens. Worth spending on quality there.
- **Mode names**: "premium" = best quality, "balanced" = good default, "economy" = cost saving
- **Task types**: 4 intuitive categories that map to 25+ specialized agents internally
- **Customization**: Users can fine-tune models per task type for optimal workflow
