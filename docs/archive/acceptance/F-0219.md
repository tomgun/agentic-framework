# F-0219: NFR Health Dashboard & Scale - Acceptance Criteria

**Feature**: Comprehensive NFR health view with dashboard integration, scale handling for 20+ NFRs via priority filtering and applicability caching.

---

## Behavior (what the user needs — technology-agnostic)

Projects with many NFRs can see at a glance which are healthy, drifting, or untested. The session-start dashboard shows NFR status. `ag nfr` is the single entry point for all NFR operations. Priority filtering prevents AC bloat.

---

## Acceptance Criteria

### Health Tool (P1 — MVP)
**Verify independently**: Run `nfr-health.sh` in various modes

- [x] **AC-001**: `nfr-health.sh` shows per-NFR report: status (met/partial/violated), coverage (feature count), staleness, test coverage
- [x] **AC-002**: `nfr-health.sh --summary` outputs one-line status (e.g., "4 defined, 3 met, 1 partial") — parses NFR.md status fields only, no cross-referencing
- [x] **AC-003**: `nfr-health.sh --json` outputs machine-readable JSON
- [x] **AC-004**: `nfr-health.sh --coverage-only` preserves same output format as `nfr-coverage.sh`
- [x] **AC-005**: `nfr-health.sh --component <name>` filters by component
- [x] **AC-006**: Both `## NFR Compliance` and `### NFR Constraints` section formats recognized

### Dashboard Integration (P1 — MVP)
**Verify independently**: Run `dashboard.sh` with and without NFR.md

- [x] **AC-007**: `dashboard.sh` shows NFR health line when NFR.md exists (uses `--summary`)
- [x] **AC-008**: No NFR line shown when NFR.md doesn't exist
- [x] **AC-009**: Dashboard NFR check adds minimal latency (summary mode only, no cross-referencing)

### Subcommand Hub (P1 — MVP)
**Verify independently**: Run `ag nfr` with various subcommands

- [x] **AC-010**: `ag nfr health` routes to `nfr-health.sh`
- [x] **AC-011**: `ag nfr sync F-XXXX` routes to `nfr-propagate.sh sync`
- [x] **AC-012**: `ag nfr test-check F-XXXX` routes to `nfr-test-check.sh`
- [x] **AC-013**: `ag nfr capture "statement"` routes to `nfr-capture.sh`
- [x] **AC-014**: `ag nfr coverage` routes to `nfr-health.sh --coverage-only` (backward-compatible alias)

### Scale Features (P2 — better but optional)
**Verify independently**: Test with 10+ NFR fixtures

- [ ] **AC-015**: `nfr-applicable.sh` caches results at `.agentic/session/.nfr-cache.json`, invalidated on NFR.md/FEATURES.md mtime change
- [ ] **AC-016**: `nfr-applicable.sh --p1-only` returns only P1-priority NFRs
- [ ] **AC-017**: `nfr-applicable.sh --all` returns all priorities (default for audits)

### NFR Constraints (P1 — required)

- [x] **AC-018**: Max 10 files per commit (NFR-0003)
- [x] **AC-019**: Spec-first: this acceptance file exists before implementation code (NFR-0004)
