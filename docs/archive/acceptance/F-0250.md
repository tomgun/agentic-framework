# F-0250: Git-Deferred Mode

## Acceptance Criteria

### AC-1: Init defaults — no auto git init for discovery/formal
- Given a new project initialized with `ag init --profile discovery` or `--profile formal`
- When scaffold.sh runs
- Then `git init` is NOT executed automatically
- And STACK.md contains `git_mode: deferred`
- And `.git/` directory does NOT exist
- And Claude hooks (`.claude/hooks.json`) ARE set up and functional

### AC-2: Init defaults — autonomous_formal defaults to active
- Given a new project initialized with `ag init --profile autonomous_formal`
- When scaffold.sh runs
- Then `git init` IS executed (default behavior preserved)
- And STACK.md contains `git_mode: active`
- And `core.hooksPath` is set to `.agentic/hooks`

### AC-3: Init asks user about git preference
- Given the init playbook runs (interactive mode)
- When the agent reaches the git configuration step
- Then it asks whether to initialize git now or defer
- And the user's choice overrides the profile default

### AC-4: ag git-init — safe git activation
- Given a project in `git_mode: deferred`
- When `ag git-init` is run
- Then git is initialized (if not already)
- And stack-aware `.gitignore` is generated BEFORE any git add
- And ONLY framework scaffold files are committed (STACK.md, STATUS.md, FEATURES.md, CONTEXT_PACK.md, OVERVIEW.md, CLAUDE.md, .gitignore)
- And user source code is NOT auto-committed
- And `core.hooksPath` is set to `.agentic/hooks`
- And STACK.md is updated to `git_mode: active`
- And the command prints what was committed and what wasn't

### AC-5: ag git-init — idempotent
- Given a project where `ag git-init` has already been run (git_mode: active)
- When `ag git-init` is run again
- Then it prints "Git already active" and exits cleanly (no error)

### AC-6: Git-dependent commands gated
- Given a project in `git_mode: deferred` or `none`
- When `ag commit`, `ag merge`, `ag auto task`, or `ag auto epic` is run
- Then a clear message is shown: "Git not active. Run `ag git-init` to enable version control."
- And the command exits without error (informational, not failure)

### AC-7: Framework works without git
- Given a project in `git_mode: deferred`
- When the user runs `ag plan`, `ag implement`, `ag verify`, `ag done`, `ag status`, `ag backlog`
- Then all commands work (using in-place work instead of worktrees)
- And Claude hooks (PreToolUse, PostToolUse, etc.) fire correctly

### AC-8: Stack-aware .gitignore generation
- Given STACK.md lists TypeScript + pnpm as the stack
- When `ag git-init` generates `.gitignore`
- Then it includes: `node_modules/`, `.pnpm-store/`, `dist/`, `build/`, `.env`
- And it includes framework patterns: `.agentic/session/`, `.agentic/pipeline/`, `.agentic/local/`
- And it does NOT duplicate entries if `.gitignore` already exists

### AC-9: Dashboard deferred-mode display
- Given a project in `git_mode: deferred` with source files present
- When `dashboard.sh` runs
- Then it shows git_mode status (not "Dirty state" or git-related errors)
- And it shows a nudge: "Run `ag git-init` when ready to track changes"
- And git-dependent sections are suppressed (no "uncommitted files" count)

### AC-10: Upgrade path for existing projects
- Given an existing project with `.git/` and commits
- When the framework is upgraded
- Then STACK.md has `git_mode: active` added automatically
- And behavior is unchanged from before the upgrade

### AC-11: git_mode: none — all git disabled
- Given a project with `git_mode: none`
- When git-dependent commands are run
- Then same gating as deferred (clear message, no error)
- And `ag git-init` is available to transition to active
