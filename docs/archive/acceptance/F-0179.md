# F-0179: Component Registry and Scoped Context

**ADR**: ADR-001, Phase 2, Section 1
**Dependencies**: F-0177

## Acceptance Criteria

- [x] **AC-001**: STACK.md supports optional `## Components` table with columns: name | path | type | test_command
- [ ] **AC-002**: FEATURES.md entries support optional `Component` field linking feature to a component _(PARTIAL: parsed by code but not in FEATURES.template.md)_
- [x] **AC-003**: `context-for-role.sh` filters files/specs/tests to the specified component's path when `--component` flag is provided
- [ ] **AC-004**: `discover.py` auto-detects components in monorepos by scanning for `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod` in subdirectories _(PARTIAL: function exists in components.py but not wired into discover.py)_
- [x] **AC-005**: `query_features.py` supports `--component <name>` filter to list features for a specific component
- [ ] **AC-006**: State machine gates use component-specific `test_command` from the registry when verifying component-scoped features _(PARTIAL: advisory warning only, does not execute test command)_
- [x] **AC-007**: Omitting the `## Components` section preserves all existing behavior (purely additive)
- [x] **AC-008**: `components.py` validates that referenced component paths exist on disk
- [x] **AC-009**: Unit tests cover registry parsing, validation, path resolution, and component-scoped gate behavior
