# F-0235: Auto-Review After PR Creation

## Acceptance Criteria

### Settings & Configuration (P1 — MVP)

- [ ] **AC-001**: `review_pr` setting exists with values `critical_agent | human | skip`, resolved via `get_setting()` with profile defaults: discovery=skip, formal=critical_agent, autonomous_formal=critical_agent
- [ ] **AC-002**: `pr_fix_max_attempts` setting exists with integer value (default 2), profile defaults: discovery=0, formal=2, autonomous_formal=2

### Review Agent (P1 — MVP)

- [ ] **AC-003**: `PRReviewer` class in `pr_review.py` spawns a review agent that reads PR diff (via `gh pr diff`), AC file, and plan file to produce structured review output
- [ ] **AC-004**: Review agent output is parsed into `PRReviewResult` with verdict (approved|request_changes|needs_discussion|skipped), summary, must_fix list, and should_fix list
- [ ] **AC-005**: When `review_pr: skip`, `review_and_fix()` returns immediately with verdict="skipped"

### Auto-Fix Loop (P1 — MVP)

- [ ] **AC-006**: When review returns REQUEST_CHANGES and fix attempts remain, a fix agent is spawned to address must_fix + should_fix items, commit, and push
- [ ] **AC-007**: After fix agent pushes, a fresh review agent re-reviews the updated PR diff
- [ ] **AC-008**: Fix loop terminates after `pr_fix_max_attempts` fix cycles, regardless of verdict
- [ ] **AC-009**: Fix agent runs in the worktree directory (same project_root as TaskRunner), on the PR branch

### GitHub Integration (P1 — MVP)

- [ ] **AC-010**: Final verdict is applied to GitHub: APPROVE via `gh pr review --approve`, REQUEST_CHANGES via `gh pr review --request-changes`, NEEDS_DISCUSSION via `gh pr comment`
- [ ] **AC-011**: When final verdict is not APPROVED, a HUMAN_NEEDED entry is created via `blocker.sh`

### TaskRunner Integration (P1 — MVP)

- [ ] **AC-012**: PR review fires AFTER `result.success` is computed in `task.py` — `result.success` reflects implementation correctness only and is NOT modified by PR review
- [ ] **AC-013**: `TaskResult` extended with `pr_review_verdict`, `pr_review_summary`, `pr_fix_attempts` fields, included in `to_dict()` output

### Scheduler Integration (P1 — MVP)

- [ ] **AC-014**: Scheduler routes `pr_review_verdict` of request_changes/needs_discussion to `review_blocked` status with `review_blocked_at = "pr_review"`
- [ ] **AC-015**: Scheduler polling loop checks GitHub review state via `gh pr view --json reviewDecision` for PR-review-blocked features

### Human Review Mode (P1 — MVP)

- [ ] **AC-016**: When `review_pr: human`, no automated review runs; a lightweight PR review block JSON is written to `pending_reviews/` and HUMAN_NEEDED entry created
- [ ] **AC-017**: PR review block uses `{feature_id}_pr_review.json` filename pattern, picked up by existing `_is_review_blocked()` glob

### Parallel Epic (P2 — Enhancement)

- [ ] **AC-018**: Each worktree's TaskRunner creates its own PR and runs review independently — no coordinator-level changes needed
