# F-0140: Proactive WIP Creation in Agent Instructions

## Tests

### Structural (S10_wip_start_in_instructions.sh)
- All instruction files (claude, cursor, copilot, codex) reference `wip.sh check` or WIP.md BLOCK
- All instruction files reference `creates WIP` or `wip.sh start`
- memory-seed.md references both WIP check and WIP creation

### Structural (validate_framework.sh)
- Existing S07 memory-seed consistency still passes
- Existing S08 CLAUDE.md line limit still passes

### Manual
- doctor.py `--phase implement` checks `.agentic-state/WIP.md` (not `.agentic/WIP.md`)

## Acceptance Criteria

### AC-1: Plan-mode-exit trigger chains to `ag implement`
- **Given** any instruction file (claude, cursor, copilot, codex)
- **When** the "Exited plan mode" trigger row is read
- **Then** it mentions `ag implement` (which creates WIP tracking)

### AC-2: Build trigger annotates WIP creation
- **Given** any instruction file
- **When** the "Build / implement" trigger row is read
- **Then** it includes `(creates WIP)` after the `ag implement` mention

### AC-3: Memory seed documents WIP creation
- **Given** memory-seed.md
- **When** the "After exiting plan mode" section is read
- **Then** it includes a step for `ag implement` with WIP explanation
- **And** the "build something" section notes `ag implement` auto-creates WIP

### AC-4: doctor.py uses correct WIP path
- **Given** doctor.py implement phase check
- **When** checking for WIP.md existence
- **Then** it checks `.agentic-state/WIP.md` (not `.agentic/WIP.md`)

### AC-5: Checklists reference WIP
- **Given** feature_start.md and feature_implementation.md
- **When** read by an agent
- **Then** feature_start has "Run `ag implement` (creates WIP)" in After Gates Pass
- **And** feature_implementation has WIP tracking checkbox in prerequisites
