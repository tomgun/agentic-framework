# F-0215: Autonomous Framework Verification Loop

## Acceptance Criteria

### AC-001: Core Verification Loop
`ag auto verify-framework --project todo-app` spawns Claude to build a todo app from scratch using framework commands in an isolated worktree. HARD GUARD: no mutation of main or real feature branches.

### AC-002: Self-Healing
Framework bugs (errors in `.agentic/lib/`) trigger self-healing: classify → fix in VW → validate_framework.sh passes → commit to ephemeral branch → restart scenario from scratch.

### AC-003: Fix Delivery
Accumulated fixes delivered as single PR against main at completion. Zero fixes → no PR, just report. Max fixes reached → PR with partial results. Push failure → preserve local branch, warn user.

### AC-004: Declarative Scenarios
Scenario definitions are declarative YAML in `.agentic/lib/auto/scenarios/` with `type: single | monorepo | multirepo`.

### AC-005: Settings Matrix
Settings matrix covers at least discovery + autonomous_formal profiles.

### AC-006: Trunk Branch Configurability
5 scripts accept `AG_TRUNK_BRANCH` env var (string comparison and show-ref patterns as appropriate; both lines in critical_agent.py). Without it, behavior unchanged.

### AC-007: Cleanup
Verification worktree + ephemeral branches cleaned up on exit (success or failure) using `--force` for dirty state. Branch preserved if push or PR creation failed.

### AC-008: Error Classification
Agent errors (bad Claude choices) distinguished from framework bugs. Agent errors → retry, not fix. Timeouts → agent_error (not framework_bug).

### AC-009: Bounded Retries
Max retries (3/scenario) + max total fixes (20) prevent infinite loops. At max_total_fixes: stop, create PR with partial results, report untested scenarios.

### AC-010: JSON Output
`--json` flag provides machine-readable results.

### AC-011: Monorepo Scenario
Monorepo scenario creates a multi-component project with `## Components` table in STACK.md, features scoped to components via `**Component**:` field, and integration verification across components.

### AC-012: Multi-Repo Scenario
Multi-repo scenario creates an umbrella repo + separate component repos with `## Contracts` section, cross-repo component resolution, and contract validation.

## Tests

- `tests/test_self_heal.py` — unit tests for SelfHealEngine, failure classification, fix agent constraints
