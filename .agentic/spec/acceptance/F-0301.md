# F-0301: Completion Gate: Block New Work When Previous Feature Unfinished

## Acceptance Criteria

### P1 — Core

- [x] AC-1: `ag implement F-XXXX` checks the backlog for any item ahead of F-XXXX that has commits on main (via `git log --oneline --grep="F-YYYY"`) but is not marked "shipped" in FEATURES.md — blocks with actionable error message
- [x] AC-2: `ag start` (session start) warns when the current backlog item has merged implementation but is still marked "planned" — surfaces in dashboard output
- [x] AC-3: The check uses `feature.sh` or equivalent to read FEATURES.md status (not grep heuristics) — respects the canonical status field
- [x] AC-4: When blocked, the error message names the stale feature and tells the user exactly what to run: `ag done F-YYYY`
- [x] AC-5: `--force` flag on `ag implement` bypasses the gate (escape hatch for legitimate cases like partial implementations)

### P2 — Edge Cases

- [x] AC-6: Features with status "partial" or "in_progress" do NOT trigger the block — only "planned" with commits triggers it
- [x] AC-7: Empty backlog or first item in backlog does not trigger false positives
- [x] AC-8: The commit-detection heuristic handles both "F-XXXX" in commit messages and feature branch names (feat/F-XXXX-*)
