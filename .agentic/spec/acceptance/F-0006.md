# F-0006: Acceptance-Driven Development - Acceptance Criteria

**Feature**: Primary development methodology - implement then verify

**Version**: 0.7.0

---

## Acceptance Criteria

### Methodology Definition

- [x] **AC-001**: PRINCIPLES.md documents Acceptance-Driven Development as primary approach
- [x] **AC-002**: agent_operating_guidelines.md instructs agents to follow this approach
- [x] **AC-003**: TDD is documented as optional alternative

### Workflow Steps

- [x] **AC-010**: Workflow defines: Define feature + acceptance criteria (rough OK)
- [x] **AC-011**: Workflow allows AI to implement large chunks
- [x] **AC-012**: Workflow requires acceptance tests to verify criteria
- [x] **AC-013**: Workflow requires updating specs with discoveries

### Spec Evolution

- [x] **AC-020**: `spec_evolution.md` workflow document exists
- [x] **AC-021**: Document explains when to update specs during implementation
- [x] **AC-022**: Document shows how to mark discoveries: `[Discovered]`
- [x] **AC-023**: Document emphasizes including spec updates in commits

### Agent Compliance

- [x] **AC-030**: Agents read acceptance criteria before implementing
- [x] **AC-031**: Agents can implement features without micro-TDD (no red-green per line)
- [x] **AC-032**: Agents update specs when discovering edge cases
- [x] **AC-033**: Agents commit code + spec updates together

## Test Scenarios

### Scenario 1: Agent Follows Acceptance-Driven Workflow

**Given**: Feature with rough acceptance criteria "User can log in"
**When**: Agent implements feature
**Then**: Agent implements full login flow, writes acceptance tests, updates specs with discoveries

### Scenario 2: Spec Evolution During Implementation

**Given**: Agent implementing feature
**When**: Agent discovers edge case (e.g., rate limiting needed)
**Then**: Agent adds `[Discovered] Rate limiting required` to acceptance criteria

### Scenario 3: TDD Alternative

**Given**: Project with `development_mode: tdd` in STACK.md
**When**: Agent implements feature
**Then**: Agent follows red-green-refactor cycle instead
