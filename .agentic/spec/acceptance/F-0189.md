# F-0189: Doc Enforcement at Feature Acceptance

Wire existing doc drift detection into feature acceptance and merge gates.

## Acceptance Criteria

### P1: Core enforcement

- [ ] **AC-01**: `drift.sh --docs --check` returns non-zero exit code when documentation drift is detected
- [ ] **AC-02**: `drift.sh --docs --check` returns zero when no drift is detected
- [ ] **AC-03**: `gate_verified_to_documented` reads `docs_gate` setting via `get_setting()`
- [ ] **AC-04**: With `docs_gate: blocking` and stale docs, gate returns `GateResult.blocked()`
- [ ] **AC-05**: With `docs_gate: warning` and stale docs, gate returns `GateResult.ok(warnings=[...])`
- [ ] **AC-06**: With `docs_gate: off`, gate returns `GateResult.ok()` (skips all checks)
- [ ] **AC-07**: Implementing-features skill has explicit doc update step pointing to `docs.sh --list` and `drift.sh --docs`
- [ ] **AC-08**: Reviewing-code skill doc dimension references `docs.sh --list` and `drift.sh --docs` with actionable guidance

### P2: Autonomode integration

- [ ] **AC-09**: `task.py` runs `drift.sh --docs --check` after verify loop, before PR creation
- [ ] **AC-10**: When drift detected in task.py, spawns Claude to update flagged docs
- [ ] **AC-11**: `engine.py` AC implementation prompt includes doc update instruction

## Tests

- Unit tests for gate in `tests/test_gates.py`: AC-03 through AC-06
- Smoke test: `drift.sh --docs --check` exit codes: AC-01, AC-02
- Framework validation: `tests/validate_framework.sh`
