# F-0209: TDD Mode — Structural Test-First Enforcement — Acceptance Criteria

## AC-001: `--phase` flag on wip.sh checkpoint
`wip.sh checkpoint --phase RED|GREEN|REFACTOR "note"` prefixes the progress entry (e.g., `"RED: note"`). Case-insensitive input, stored uppercase. Invalid phases rejected with error. Omitting `--phase` works unchanged (backward compatible). Both AGENTS.json and WIP.md fallback paths handle the prefix identically.

## AC-002: `check-tdd-phases` command in agents_helpers.py
`python3 agents_helpers.py --project-root . check-tdd-phases` validates progress array ordering. Exit 0 = valid, exit 2 = GREEN before RED (ordering violation), exit 3 = zero phase entries. Every GREEN must be preceded by at least one RED at an earlier index. REFACTOR has no ordering constraint.

## AC-003: TDD gate on `wip.sh complete`
When `development_mode: tdd` in STACK.md, `wip.sh complete` calls `check-tdd-phases` before deleting the AGENTS.json entry. Blocks completion on exit 2 or 3. `SKIP_TDD=1` escape hatch bypasses (blocked on main/master).

## AC-004: Pre-commit Check #20 (safety net)
`pre-commit-check.sh` has Check #20 that calls `check-tdd-phases` when `development_mode: tdd` and not fast mode. Blocks commit on exit 2/3. Exit 1 (no active entries) passes silently. `SKIP_TDD=1` added to main/master escape hatch guard.

## AC-005: Implementing-features skill conditional TDD branch
Both SKILL.md copies (template + framework-dev) have Step 4 conditional: if `development_mode: tdd`, per-AC red-green-refactor cycle with `wip.sh checkpoint --phase` commands. If `standard`, current behavior unchanged.

## AC-006: Feature implementation checklist updated
`feature_implementation.md` TDD section strengthened from "optional" to "mandatory when `development_mode: tdd`" with `--phase` commands and completion gate note.
