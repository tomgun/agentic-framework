# F-0217: NFR-Aware Test Writing - Acceptance Criteria

**Feature**: Make the writing-tests workflow check applicable NFRs before designing test plans, catching gaps where features pass their own ACs but violate NFRs.

---

## Behavior (what the user needs — technology-agnostic)

When writing tests for a feature, the agent automatically checks which NFRs apply and whether existing tests cover them. If gaps exist, the agent includes NFR constraints in the test plan. The spec audit can report NFR test coverage across all shipped features.

---

## Acceptance Criteria

### Test Check Tool (P1 — MVP)
**Verify independently**: Run `nfr-test-check.sh` against features with known NFR references

- [ ] **AC-001**: `nfr-test-check.sh F-XXXX` lists applicable NFRs for the feature
- [ ] **AC-002**: Tool reports which applicable NFRs have test references in the AC file and which are missing
- [ ] **AC-003**: Exit code 0 when all covered, exit code 1 when gaps found
- [ ] **AC-004**: NFR reference extraction is scoped to `## Acceptance Criteria`, `### NFR Constraints`, and `## NFR Compliance` sections only (not whole-file grep)
- [ ] **AC-005**: Both legacy `## NFR Compliance` and new `### NFR Constraints` section formats are recognized

### Skill Integration (P1 — MVP)
**Verify independently**: Check skill files contain the new step

- [ ] **AC-006**: writing-tests SKILL.md (both root and template) has Step 1.5: "Run `nfr-test-check.sh F-XXXX`"
- [ ] **AC-007**: implementing-features SKILL.md (both root and template) notes NFR test check at Step 4

### Spec Audit Enhancement (P2 — better but optional)
**Verify independently**: Run `spec-audit.sh --nfr-test-coverage`

- [ ] **AC-008**: `spec-audit.sh --nfr-test-coverage` reports NFR test coverage for all shipped features with NFR references

### NFR Constraints (P1 — required)

- [ ] **AC-009**: Max 10 files per commit (NFR-0003)
- [ ] **AC-010**: Spec-first: this acceptance file exists before implementation code (NFR-0004)
