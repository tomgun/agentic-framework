# F-0082: Tier-Based Model Selection - Acceptance Criteria

## AC-001: No Hardcoded Model Names in Recommendations

**Given** any subagent definition file  
**When** reading the "Recommended Model" section  
**Then** it uses tier terminology:
- "Cheap/Fast" (with examples like haiku, gpt-4o-mini)
- "Mid-tier" (with examples like sonnet, gpt-4o)
- "Powerful" (with examples like opus, o1)
- NOT just "haiku" or "sonnet" without tier context

## AC-002: Model Selection Principle Documented

**Given** each subagent definition  
**When** reading the model recommendation  
**Then** it includes a "Model selection principle" explaining WHY that tier is appropriate for that task type.

## AC-003: Agent Operating Guidelines Updated

**Given** `agent_operating_guidelines.md`  
**When** reading the "Agent Delegation Guidelines" section  
**Then** it includes:
- Tier-based model selection table
- Note that model names change frequently
- Guidance to focus on tier, not specific names

## AC-004: CLAUDE.md Updated

**Given** `CLAUDE.md` (template or framework's own)  
**When** reading the "Agent Delegation" section  
**Then** it uses tier-based language consistently.

## AC-005: Future-Proof Documentation

**Given** all agent-related documentation  
**When** searching for model recommendations  
**Then** each instance includes:
- Current example model names (in parentheses)
- Tier classification
- Note about evolution
