# F-0229: Code Annotation Enforcement

## Acceptance Criteria

### Pre-Commit Gate (P1 — MVP)

- [ ] **AC-001**: Pre-commit Check 22 runs `coverage.py --json` when `annotation_enforcement` != `off`; parses output to detect features transitioning to `shipped` in the current commit that lack `@feature F-XXXX` annotations
- [ ] **AC-002**: When `annotation_enforcement: advisory` — Check 22 prints a warning for unannotated shipped features but does NOT increment `FAILURES` (commit proceeds)
- [ ] **AC-003**: When `annotation_enforcement: blocking` — Check 22 increments `FAILURES` for unannotated shipped features (commit blocked until annotations added)
- [ ] **AC-004**: When `annotation_enforcement: off` (default) — Check 22 is skipped entirely; 157 existing shipped features are grandfathered

### Settings & Profiles (P1 — MVP)

- [ ] **AC-005**: `annotation_enforcement` setting added to `profiles.conf` — `discovery: off`, `formal: advisory`, `autonomous_formal: blocking`; overridable via STACK.md `## Settings`
- [ ] **AC-006**: `get_setting annotation_enforcement off` returns correct value from profile or STACK.md override

### Scope Control (P2 — Enhancement)

- [ ] **AC-007**: Only features whose status changes to `shipped` in the staged diff are checked — not all 157+ already-shipped features (grandfathering)
- [ ] **AC-008**: Check 22 is skipped in `--mode fast` (discovery profile uses fast mode)

### Workflow Guidance (P2 — Enhancement)

- [ ] **AC-009**: `code_annotations.md` updated with enforcement section explaining the three modes, how to add annotations, and how to override the setting

## Verification

- **Automated**: `bash tests/validate_framework.sh` (framework validation)
