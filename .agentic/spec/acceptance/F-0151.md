# F-028: User-Extension Directory — Acceptance Criteria

**Feature**: Upgrade-safe `.agentic-local/extensions/` directory for project-specific custom skills, quality gates, hooks, and rules.

---

## Behavior (what the user needs — technology-agnostic)

Users can customize the framework with project-specific skills, quality gates, and rules that survive framework upgrades. Extensions use the same formats as framework components — no new concepts to learn. Custom gates block commits on failure (same exit-1 pattern). Custom skills appear in Claude Code alongside framework skills.

---

## Acceptance Criteria

### Directory Creation (P1 — scaffold integration)
**Verify independently**: Run `bash .agentic/init/scaffold.sh --non-interactive` in test project
- [ ] **AC-001**: `scaffold.sh` creates `.agentic-local/extensions/` with skills/, gates/, hooks/, rules/ subdirs
- [ ] **AC-002**: `scaffold.sh` creates `.agentic-local/extensions/README.md` from template

### Tool Integration (P1 — script changes)
**Verify independently**: Check generate-skills.sh, pre-commit-check.sh, upgrade.sh
- [ ] **AC-003**: `generate-skills.sh` scans `.agentic-local/extensions/skills/` and copies to `.claude/skills/`
- [ ] **AC-004**: `pre-commit-check.sh` runs custom gates from `.agentic-local/extensions/gates/`
- [ ] **AC-005**: `upgrade.sh` explicitly preserves `.agentic-local/` directory
- [ ] **AC-006**: Backward compat: existing `subagents-project/` mechanism continues to work

### Edge Cases
- [ ] **AC-007**: `generate-skills.sh --validate` still passes with extension skills present
- [ ] **AC-008**: Empty `.agentic-local/extensions/` dirs don't cause errors in any script
