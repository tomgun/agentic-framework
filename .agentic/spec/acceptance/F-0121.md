# F-0121: Tool-Specific Instructions Parity

## Description

Ensure Cursor, Codex, and Copilot templates in `.agentic/agents/` have feature parity with Claude template for constitutional rules (trigger table, token scripts, behavioral rules). Structurally-enforced content (gates, escape hatches, delegation) lives in the playbook (`auto_orchestration.md`), not in instruction files.

## Acceptance Criteria

- [ ] **AC-001**: All templates have trigger words table with "implement entire" / "full system" scope detection
- [ ] **AC-002**: All templates have "Small Batch Development" section with "TOO BIG" response pattern
- [ ] **AC-003**: All templates have token-efficient scripts section
- [ ] **AC-004**: All templates have playbook pointer referencing `auto_orchestration.md` or `ag` commands
- [ ] **AC-005**: `/CODEX.md` extends template (follows `/CLAUDE.md` pattern, not a stub)
- [ ] **AC-006**: `tests/validate_framework.sh` includes parity check
- [ ] **AC-007**: Gates table, escape hatches, delegation, and session protocols exist in `auto_orchestration.md`

## Architecture Note

Per `docs/INSTRUCTION_ARCHITECTURE.md`, instruction files are the **constitutional layer** (~40-50 lines). Structurally-enforced content (gates, escape hatches) moved to the **playbook layer** (`auto_orchestration.md`) since `pre-commit-check.sh` enforces gates regardless of whether they appear in instruction files.
