# F-0251: Formal Spec Lifecycle Enforcement

## Acceptance Criteria

### AC-1: PreToolUse blocks code writes when all features are "planned"
- Given a formal or autonomous_formal project with features in FEATURES.md
- When ALL features have status "planned" (none in "implementing" or later)
- And the agent attempts to write/edit files in source directories (src/, lib/, app/, etc.)
- Then PreToolUse injects a warning: "No feature is in implementation state. Run `ag implement F-XXXX` first."
- And the write is blocked (exit 2) in blocking mode, or warned in advisory mode

### AC-2: ACs must exist for all features before implementation
- Given a formal project with 6 features in FEATURES.md
- When `ag implement F-0001` is run
- Then the gate checks that F-0001 has an AC file in `spec/acceptance/F-0001.md`
- And the AC file has at least 1 acceptance criterion (not just a stub)

### AC-3: Discovery profile is not affected
- Given a discovery profile project
- When the agent writes code to source directories
- Then no enforcement fires (discovery has no spec lifecycle requirement)

### AC-4: Code writes to non-source directories are not affected
- Given a formal project with all features "planned"
- When the agent writes to `.agentic/`, `docs/`, `STACK.md`, or other non-source files
- Then no enforcement fires (spec/config files are always writable)

### AC-5: At least one feature in "implementing" allows code writes
- Given a formal project with F-0001 in "implementing" and F-0002 through F-0006 in "planned"
- When the agent writes code to source directories
- Then no enforcement fires (at least one feature is being implemented)
