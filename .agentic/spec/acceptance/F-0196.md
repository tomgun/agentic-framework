# F-0196: Fluent State File Commits (`ag flush`) - Acceptance Criteria

**Feature**: One command (`ag flush`) commits + pushes state-only changes directly to main without a PR, while code changes still require PRs.

---

## Behavior (what the user needs — technology-agnostic)

After running token-efficient tools (status.sh, journal.sh, backlog.sh, etc.), state files accumulate as dirty. Today, committing them requires creating a branch + PR — disproportionate overhead for bookkeeping changes. With `ag flush`, the user can persist state changes to main in one command, without losing the PR gate for code changes.

---

## Acceptance Criteria

### Core Behavior (P1 — MVP)
**Verify independently**: Run `ag flush` on main with dirty state files

- [ ] **AC-001**: `ag flush` commits dirty state files (STATUS.md, TODO.md, HUMAN_NEEDED.md, BACKLOG.json, JOURNAL.md, CONTRIBUTIONS.md) directly to main and pushes
- [ ] **AC-002**: `ag flush` rejects any non-allowlist files — if non-state files are staged or dirty, the entire commit is rejected with a clear error listing the offending files
- [ ] **AC-003**: `ag flush --dry-run` shows what would be committed without committing
- [ ] **AC-004**: `ag flush --check` exits 0 if dirty state files exist, exits 1 if clean (used by dashboard)
- [ ] **AC-005**: `ag flush` is rejected when not on main/master (feature branches, detached HEAD)
- [ ] **AC-006**: `ag flush` is rejected from worktrees (even if on main) — uses `git worktree list` comparison

### FEATURES.md Special Handling (P1)
**Verify independently**: Modify FEATURES.md status via feature.sh, then run `ag flush --features`

- [ ] **AC-007**: `ag flush --features` includes .agentic/spec/FEATURES.md but validates every changed line matches `**Status**:` pattern
- [ ] **AC-008**: `ag flush --features` rejects FEATURES.md if any non-status content line was changed

### Safety & Recovery (P1)
**Verify independently**: Test push failure and conflict scenarios

- [ ] **AC-009**: If `git push` fails (non-fast-forward), script runs `git reset --soft HEAD~1` and aborts with "Re-run: ag flush"
- [ ] **AC-010**: If `git pull --rebase` conflicts, script runs `git rebase --abort` and exits with clear instructions
- [ ] **AC-011**: BACKLOG.json is validated as valid JSON before commit; invalid JSON is rejected
- [ ] **AC-012**: Remote existence is checked before pull/push; no remote → commit locally with warning

### Integration (P2)
**Verify independently**: Run `ag start` and `ag done`

- [ ] **AC-013**: Dashboard (dashboard.sh) shows count of dirty state files with "Run: ag flush" suggestion
- [ ] **AC-014**: `ag flush` is dispatched via `ag.sh` case statement and appears in help text
- [ ] **AC-015**: Completing-work skill includes Step 4c to flush state after completion
- [ ] **AC-016**: Committing-changes skill notes that state files can be committed separately via `ag flush`

### Instruction File Delivery (P2)
**Verify independently**: Grep all instruction files for `ag flush`

- [ ] **AC-017**: `ag flush` appears in Quick Commands in CLAUDE.md template and root CLAUDE.md
- [ ] **AC-018**: memory-seed.md has trigger rule for dirty state files + `--no-verify` exception carve-out
- [ ] **AC-019**: All instruction files (.cursorrules, copilot-instructions, codex-instructions, agent_operating_guidelines, auto_orchestration) reference `ag flush`
- [ ] **AC-020**: DEVELOPER_GUIDE.md and HOW_IT_WORKS.md document the feature

### Edge Cases

- [ ] **AC-021**: Partial state (only some state files dirty) → only dirty files committed
- [ ] **AC-022**: `git_workflow: direct` → works but prints helpful tip
- [ ] **AC-023**: Commit message uses `chore(state): update <file1>, <file2>` format
- [ ] **AC-024**: VERSION is NOT in the allowlist — version bumps go through PRs
