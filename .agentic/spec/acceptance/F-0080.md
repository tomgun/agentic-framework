# F-0080: Upgrade Marker System - Acceptance Criteria

**Feature**: Efficient upgrade detection via marker file

**Version**: 0.8.1

---

## Acceptance Criteria

### Marker File Creation

- [x] **AC-001**: `upgrade.sh` creates `.agentic/.upgrade_pending` after upgrade
- [x] **AC-002**: Marker contains from_version
- [x] **AC-003**: Marker contains to_version
- [x] **AC-004**: Marker contains upgrade_date
- [x] **AC-005**: Marker contains changelog_url
- [x] **AC-006**: Marker contains TODO list for agent

### Session Start Detection

- [x] **AC-010**: `session_start.md` checks for `.upgrade_pending`
- [x] **AC-011**: Instructions to handle upgrade if marker exists
- [x] **AC-012**: Instructions to delete marker when done

### Efficiency

- [x] **AC-020**: No version comparison every session (only file existence check)
- [x] **AC-021**: Marker is one-time (deleted after handling)
- [x] **AC-022**: Fast detection (file exists check is O(1))

### Agent Guidance

- [x] **AC-030**: `agent_operating_guidelines.md` has "After Framework Upgrade" section
- [x] **AC-031**: Clear post-upgrade checklist in guidelines

---

## Validation Commands

```bash
# Check upgrade.sh creates marker
grep -q "upgrade_pending" .agentic/tools/upgrade.sh && echo "✓ upgrade.sh creates marker"

# Check session_start.md checks for marker
grep -q "upgrade_pending" .agentic/checklists/session_start.md && echo "✓ session_start checks marker"

# Check agent guidelines have upgrade section
grep -q "After Framework Upgrade" .agentic/agents/shared/agent_operating_guidelines.md && echo "✓ Guidelines have upgrade section"
```
