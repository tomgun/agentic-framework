# F-0094: Version-Aware Upgrade Features - Acceptance Criteria

## AC-001: Feature Registry Exists

**Given** `.agentic/tools/upgrade.sh`
**When** reading the script
**Then** it contains a FEATURE_REGISTRY array with:
- Format: "version:name:command:description"
- Version when each feature was introduced
- User-visible features only (not internal changes)

## AC-002: Version Comparison Logic

**Given** upgrade.sh
**When** upgrading from version A to version B
**Then** it correctly compares versions:
- Uses `sort -V` for semantic version comparison
- Handles major.minor.patch format
- 0.10.0 > 0.5.0 (not string comparison)

## AC-003: Feature Filtering

**Given** a user upgrading from 0.10.0 to 0.11.2
**When** upgrade.sh generates .upgrade_pending
**Then**:
- Features introduced in 0.5.0 are NOT shown (already past)
- Features introduced in 0.11.0 ARE shown (new to user)
- Features introduced in 0.11.2 ARE shown (new to user)

## AC-004: No Repeated Prompts

**Given** a user who upgraded from 0.10.0 to 0.11.0 previously
**When** they upgrade from 0.11.0 to 0.11.2
**Then**:
- Only 0.11.1 and 0.11.2 features are shown
- 0.5.0 features (sub-agents, pipeline) are NOT shown again
- No "new features" section if nothing is new

## AC-005: Adding New Features Process

**Given** a developer adding a new user-visible feature
**When** they want it shown during upgrade
**Then** they add to FEATURE_REGISTRY:
```bash
"X.Y.Z:Feature Name:command to setup:Description"
```
And it will only show to users upgrading from < X.Y.Z

## Verification

- [ ] AC-001: FEATURE_REGISTRY array exists in upgrade.sh
- [ ] AC-002: Version comparison works correctly
- [ ] AC-003: Features filtered based on from-version
- [ ] AC-004: No repeated prompts on subsequent upgrades
- [ ] AC-005: Process for adding new features is documented
