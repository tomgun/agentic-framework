# F-0182: Critical Review Agent

**ADR**: ADR-001, Phase 4, Section 5.1
**Dependencies**: F-0180

## Acceptance Criteria

- [ ] **AC-001**: `CriticalAgent` class spawns a separate Claude instance with an adversarial review prompt
- [ ] **AC-002**: Critical agent is read-only: can approve, request-changes, or escalate — cannot modify code or specs
- [ ] **AC-003**: Review verdicts are structured (status, reasoning, specific issues, recommendation) and stored as artifacts
- [ ] **AC-004**: Critical agent uses the `review` model from STACK.md `## Model customization` section
- [ ] **AC-005**: Adversarial mandate: prompt instructs agent to find problems, not rubber-stamp. Includes "if in doubt, escalate" instruction
- [ ] **AC-006**: Escalation creates a HUMAN_NEEDED entry with the critical agent's concerns and reasoning
- [ ] **AC-007**: Error handling: API unavailable → retry once, then fall back to `human` mode. Rate limited → backoff and retry. Timeout → fall back to `human`
- [ ] **AC-008**: `review.py` `critical_agent` mode now delegates to CriticalAgent instead of falling back to human
- [ ] **AC-009**: Critical agent has access to specs, NFRs, and style guidelines for context during review
- [ ] **AC-010**: Unit tests cover spawn, verdict parsing, escalation, model selection, and error handling
