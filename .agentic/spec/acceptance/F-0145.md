# F-0145: Periodic Check System (Lifecycle Triggers)

## Acceptance Criteria

### Core: Frequency-Gated Periodic Checks
- [ ] `periodic-checks.sh` exists with load/save state, frequency evaluation, session counter
- [ ] State file `.agentic-state/sync-state.conf` tracks last-run per check (flat key=value)
- [ ] `should_run_check()` evaluates `every_session`, `every_N_sessions`, `off` frequencies
- [ ] Session counter increments on each sync run
- [ ] Supports `--increment` (bump counter, return count) and `--quiet` (suppress non-issue output) modes

### Orphaned Plan Detection
- [ ] Detects plans in `~/.claude/plans/` matching project fingerprint or feature IDs
- [ ] Project fingerprint: `git remote get-url origin` or `basename $(pwd)`
- [ ] Feature IDs extracted from `spec/FEATURES.md` (grep `F-[0-9]+`)
- [ ] Compares against `.agentic-journal/plans/` to find orphans
- [ ] Reports orphans without auto-copying
- [ ] Graceful when `~/.claude/plans/` doesn't exist
- [ ] Graceful when `spec/FEATURES.md` doesn't exist (fingerprint-only matching)

### Retro Check Migration
- [ ] Retro due check moved from session_start.md to periodic-checks.sh
- [ ] Gated by `periodic_retro_check` frequency setting

### Agent Freshness Check
- [ ] `check_agent_freshness()` detects stale project agents (STACK.md changed since last generation)
- [ ] Gated by `periodic_agent_refresh` frequency setting
- [ ] Suggests `ag agents generate` when stale

### Integration
- [ ] sync.sh Phase 7 calls periodic-checks.sh
- [ ] profiles.conf has periodic_* defaults per profile (discovery: retro off, agent refresh off; formal: all enabled)
- [ ] STACK.template.md has periodic settings in ## Settings

### Tests
- [ ] `test_periodic_checks.sh` covers state read/write, frequency eval, session counter, state format
- [ ] `validate_framework.sh` passes
