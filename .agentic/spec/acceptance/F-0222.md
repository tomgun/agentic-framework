# F-0222: State Machine Enforcement = Blocking

## Acceptance Criteria

- [ ] AC1: `ag implement F-XXXX` exits non-zero when `state_enforcement: blocking` and a gate check fails (e.g., missing AC file for planned→specced transition)
- [ ] AC2: `ag done F-XXXX` exits non-zero when `state_enforcement: blocking` and a gate check fails during the verified→documented→committed→shipped transition loop
- [ ] AC3: `state_enforcement: off` (discovery default) skips state machine transitions entirely — no gate checks, no warnings, no errors
- [ ] AC4: SKIP_TRANSITIONS (planned→implementing, planned→shipped, implementing→shipped, implementing→committed) succeed in blocking mode — they are structurally valid and not subject to gate blocking
- [ ] AC5: Blocked transition output includes: (a) the specific gate failure reason from gates.py, and (b) a bypass hint pointing to `state_enforcement: advisory` in STACK.md
- [ ] AC6: Formal and autonomous_formal profiles default to `state_enforcement: blocking` in profiles.conf; discovery remains `off`
- [ ] AC7: Existing features already in a state (e.g., implementing with no AC file) are not retroactively broken — enforcement only applies when attempting a new transition
- [ ] AC8: The `ag transition` CLI passthrough still works without `--enforce` by default, preserving it as an escape hatch for manual overrides

## Verification

- **Automated**: `pytest tests/test_state_machine.py::TestBlockingEnforcement -v`
- **Automated**: `bash tests/validate_framework.sh` (profiles.conf validation)
- **Manual**: Set `state_enforcement: blocking` in STACK.md, run `ag implement` on feature missing AC file, confirm blocked with reason + bypass hint
- **Profile**: Formal, Autonomous Formal
