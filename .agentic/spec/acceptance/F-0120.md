# F-004: Plan-Review Loop - Acceptance Criteria

## Overview
Iterative planning with critical review before implementation. Two-agent loop (planner + reviewer) catches issues before code is written.

## Acceptance Criteria

### AC-1: Configuration in STACK.md
- [x] `plan_review_enabled` setting (yes/no)
- [x] `plan_review_max_iterations` setting (default: 3)
- [x] `plan_review_auto_for` setting (planning/implement/both)
- [x] Optional `plan_review_reviewer_model` override
- [x] Defaults: enabled for Formal, disabled for Discovery

### AC-2: Plan Artifact
- [x] Plans written to `.agentic-journal/plans/F-XXXX-plan.md`
- [x] Plan format includes: Context, Approach, Steps, Files, Testing, Risks
- [x] Status tracking: DRAFT → REVIEWING → REVISION_NEEDED → APPROVED
- [x] Iteration counter increments on each revision
- [x] Review history preserved in plan file

### AC-3: Planner Agent Behavior
- [x] Reads acceptance criteria and CONTEXT_PACK before planning
- [x] Creates comprehensive plan following template
- [x] On revision: addresses all CRITICAL/IMPORTANT issues
- [x] Documents how each issue was addressed

### AC-4: Reviewer Agent Behavior
- [x] Adopts adversarial/critical mindset
- [x] Checks plan against acceptance criteria
- [x] Categorizes issues: CRITICAL, IMPORTANT, SUGGESTION
- [x] Sets verdict: APPROVED, REVISION_NEEDED, or ESCALATE
- [x] Does not rubber-stamp (finds real issues)

### AC-5: Loop Behavior
- [x] Loop continues until APPROVED or max_iterations reached
- [x] On max_iterations: status becomes ESCALATED, human notified
- [x] On ESCALATE verdict: loop stops, human notified
- [x] Human can edit plan and set APPROVED to bypass

### AC-6: Integration with ag Commands
- [x] `ag plan F-XXXX` triggers plan-review loop (when enabled)
- [x] `ag plan --no-review` skips review loop
- [x] `ag implement` checks for approved plan first (when auto_for includes implement)
- [x] If no approved plan, shows warning to user (manual trigger)

### AC-7: Claude Code Support
- [x] Task tool spawns planner with Plan subagent type
- [x] Task tool spawns reviewer with general-purpose type
- [x] Models selected based on agent_mode in STACK.md
- [x] Plan file passed between agents correctly

### AC-8: Cursor Support
- [x] Plan agent role defined in .cursor/agents/
- [x] Review agent role defined in .cursor/agents/
- [x] Agents can be invoked manually to run the loop

## Out of Scope
- Parallel planning (multiple plans for same feature)
- Automated plan comparison/selection
- Integration with external planning tools
- Auto-triggering plan-review loop from `ag implement` (currently warns only)
- Cursor orchestrator automated coordination (manual invocation works)

## Test Scenarios

1. **Happy path**: Plan approved after 1 revision
2. **Multiple iterations**: Plan needs 2-3 revisions before approval
3. **Escalation**: Reviewer escalates, human intervenes
4. **Max iterations**: Hits limit, human notified
5. **Skip review**: `--no-review` flag works
6. **No plan exists**: `ag implement` creates plan first
