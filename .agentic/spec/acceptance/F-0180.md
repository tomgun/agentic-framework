# F-0180: Review Checkpoint Framework

**ADR**: ADR-001, Phase 3, Section 5.1
**Dependencies**: F-0177

## Acceptance Criteria

- [ ] **AC-001**: Three review modes supported: `human`, `critical_agent`, `auto`
- [ ] **AC-002**: Review mode is configurable per transition and per profile via STACK.md settings (`review_spec`, `review_criteria`, `review_plan`, `review_code`, `review_merge`, `review_decomposition`, `review_regression`, `review_taste`)
- [ ] **AC-003**: When review mode is `human`, `state_machine.transition()` blocks and creates a HUMAN_NEEDED entry
- [ ] **AC-004**: When review mode is `auto`, transition proceeds without review
- [ ] **AC-005**: When review mode is `critical_agent`, falls back to `human` with a log message until Phase 4 (F-0182) ships
- [ ] **AC-006**: `ag review F-XXXX <transition>` command resolves a pending human review and unblocks the transition
- [ ] **AC-007**: Review verdicts are stored as structured artifacts alongside the feature
- [ ] **AC-008**: Profile switching mid-feature: pending reviews keep their original mode, new transitions use the new profile
- [ ] **AC-009**: Default review settings are sensible per profile (see ADR-001 Phase 3 table)
- [ ] **AC-010**: Unit tests cover review routing, mode resolution, fallback behavior, and blocking/unblocking
