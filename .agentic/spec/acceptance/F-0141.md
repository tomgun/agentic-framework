# F-0141: Explicit Settings in STACK.md

## Acceptance Criteria

### AC-1: Template has all profile settings explicit
- STACK.template.md `## Settings` section lists all `profiles.conf` keys uncommented with values
- Each setting has an inline `# ... Profile defaults` comment showing both profiles
- Discovery defaults are used as template values (scaffold.sh replaces for formal)

### AC-2: Scaffold sets all profile values
- `scaffold.sh` reads `profiles.conf` and sets ALL settings (not just git_workflow)
- Fresh scaffold with `--profile discovery` produces all 12 settings with discovery values
- Fresh scaffold with `--profile formal` produces all 12 settings with formal values

### AC-3: Smart profile cascade preserves customizations
- `ag set profile formal` only overwrites settings that match the OLD profile's defaults
- User-customized settings are preserved during profile switch
- Validates constraints once at end (not per-setting)
- Reports how many settings changed vs preserved

### AC-4: Upgrade populates missing settings
- `upgrade.sh` adds missing explicit settings from profile defaults
- Existing explicit values are not overwritten
- Works for both discovery and formal profiles

### AC-5: pre_commit_hook validation
- `ag set pre_commit_hook invalid` returns an error
- Valid values: `fast`, `full`, `no`

### AC-6: Framework dogfooding
- Root `STACK.md` uses explicit format with formal profile values
- No duplicate settings outside `## Settings` section

### AC-7: Template-profiles sync tests
- `validate_framework.sh` checks every `profiles.conf` key has a matching template line
- `validate_framework.sh` checks every template setting has a matching `profiles.conf` key
- Drift between template and profiles.conf is caught automatically
