# F-0300: Framework Enforcement Gaps

## Acceptance Criteria

### AC-1: Hook installation completeness (R0)
- [ ] `ag auto init` installs `.claude/hooks.json` alongside `settings.json` permissions
- [ ] `ag hooks status` command reports which hooks are registered and functional
- [ ] Projects initialized via any path (scaffold, auto init, manual) can verify hook state

### AC-2: Pre-write gate blocks untracked work in deferred git (R1)
- [ ] When `git_mode=deferred` and no active work item exists in AGENTS.json, `gate_pretool` DENIES code writes to source directories (not `.agentic/`, `tests/`, `docs/`)
- [ ] When `state_enforcement=blocking`, denial is hard; when `advisory`, it warns
- [ ] When a specific feature_id is resolved, its ACs must exist before code writes

### AC-3: Batch work triggers route to ag auto (R3)
- [ ] Memory-seed contains trigger mapping for "churn/batch/all tasks/build everything/implement everything"
- [ ] CLAUDE.md template contains rule: "NEVER write code for multiple features outside ag auto commands"
- [ ] UserPromptSubmit.sh detects batch-work patterns and emits advisory warning
- [ ] All instruction files (cursorrules, copilot, codex) include the batch-work rule

### AC-4: FEATURES.md format enforcement (R4)
- [ ] Init playbook includes explicit heading-format template with format warning
- [ ] `feature.sh add F-XXXX "Name" domain` creates new feature entries in correct heading format
- [ ] Format comment `<!-- format: features-v2.0.0 -->` included in template

### AC-5: ag auto works with deferred git (R5)
- [ ] `auto.sh` gate changed from hard block to conditional warning for `git_mode != active`
- [ ] `task.py` skips `_create_branch()`, `_commit_ac()`, `_create_pr()` when git not active
- [ ] `crunch.py` and `scheduler.py` wrap git ops in `git_mode == active` guards
- [ ] Core pipeline (plan → spec → implement → test → verify) executes without git
- [ ] `implement.sh` always fires Gate 0 (plan), Gate 0.5 (ACs), registers AGENTS.json regardless of git mode

### AC-6: Test quality gate independent of git (R6)
- [ ] `gates.py` has gate delegating to `check_verification_passes` for `implementing → verified` transition
- [ ] `state_machine.py` wires the gate into transitions
- [ ] UserPromptSubmit.sh warns when "done/finished" is said without verification record
- [ ] Crunch pipeline calls `ag verify` between features

### AC-7: Spawned agents receive enforcement rules (R2)
- [ ] `task.py` `_spawn_claude_implement()` prompt includes AC existence check, plan check, single-criterion scope
- [ ] `crunch.py` spawned prompts include same enforcement rules
- [ ] UserPromptSubmit.sh detects autonomous work patterns (multiple source writes without `ag` commands)

## Verification

**Automated**: `bash tests/validate_framework.sh`
**Structural**: LLM tests for trigger words (R3), gate enforcement (R1, R6)
**Integration**: `ag auto crunch` in test project with `autonomous_formal` + `git_mode=deferred`
