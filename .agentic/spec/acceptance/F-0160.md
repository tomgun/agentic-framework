# F-030: Autonomous Engine Foundation — Acceptance Criteria

**Feature**: Python engine core with control plane, settings generation, AC handling, and decomposition.

---

## Acceptance Criteria

### P1 — Control Plane

- [x] **AC-001**: Engine creates Unix domain socket at `.agentic/session/auto.sock` on startup
- [x] **AC-002**: Engine writes PID to `.agentic/session/auto.pid` on startup
- [x] **AC-003**: `ag auto pause` sends pause command, engine acks and pauses
- [x] **AC-004**: `ag auto resume` sends resume command, engine acks and resumes
- [x] **AC-005**: `ag auto stop` sends stop command, engine acks and begins shutdown
- [x] **AC-006**: `ag auto feedback AC-XXX "text"` queues feedback for a specific AC
- [x] **AC-007**: `ag auto status` returns full engine state (current AC, progress, decomposed ACs)
- [x] **AC-008**: Engine deletes socket + PID file on exit (normal, SIGTERM, SIGINT, atexit)
- [x] **AC-009**: Stale socket from dead process is detected and cleaned up on startup
- [x] **AC-010**: Invalid JSON over socket returns error response (no crash)
- [x] **AC-011**: Unknown commands return error response with command name

### P1 — Settings & Permissions

- [x] **AC-012**: `ag auto init` generates `.claude/settings.json` from STACK.md
- [x] **AC-013**: Tier 1 (sandboxed) settings allow all, deny nothing
- [x] **AC-014**: Tier 2 (scoped) settings include file ops, git, test runners, framework scripts
- [x] **AC-015**: Tier 2 settings deny `rm -rf`, `sudo`, pipe-to-bash
- [x] **AC-016**: Tier 2 settings include project-specific rules from STACK.md (language + package manager)
- [x] **AC-017**: Tier 3 (interactive) settings are empty (normal approval prompts)
- [x] **AC-018**: `ag auto init --dry-run` prints settings without writing
- [x] **AC-019**: Settings template stored at `.agentic/lib/auto/settings-template.json`

### P1 — AC Loading & Complexity

- [x] **AC-020**: Engine loads acceptance criteria from `spec/acceptance/F-XXXX.md`
- [x] **AC-021**: ACs with explicit IDs (AC-001, AC-002) are parsed correctly
- [x] **AC-022**: ACs without explicit IDs get auto-generated sequential IDs
- [x] **AC-023**: Missing AC file returns empty list (no crash)
- [x] **AC-024**: Pre-flight complexity estimation classifies ACs as SMALL/MEDIUM/LARGE

### P1 — Decomposition

- [x] **AC-025**: LARGE ACs trigger auto-decomposition into sub-tasks
- [x] **AC-026**: Sub-tasks are recorded in engine state with per-subtask status tracking
- [x] **AC-027**: All sub-tasks must pass for parent AC to be marked passed
- [x] **AC-028**: Decomposition is engine-internal — the AC spec file is NOT modified
- [x] **AC-029**: If a sub-task also exhausts context, one more level of decomposition is attempted

### P1 — State Management

- [x] **AC-030**: Engine state is thread-safe (concurrent reads/writes don't corrupt)
- [x] **AC-031**: Engine persists state to `auto-state.json` after each AC status change
- [x] **AC-032**: State includes: engine state, feature ID, mode, current AC, progress, decomposed ACs
- [x] **AC-033**: `auto.sock`, `auto.pid`, `auto-state.json` are gitignored

### P2 — CLI Integration

- [x] **AC-034**: `ag auto --help` shows all subcommands and tiers
- [x] **AC-035**: `ag auto` commands appear in both discovery and formal help text

## Tests

  - TestControlServer: AC-001 through AC-011
  - TestSettingsGeneration: AC-012 through AC-019
  - TestACHandling: AC-020 through AC-029
  - TestFormatStatus: AC-007 display formatting
- `tests/validate_framework.sh` — structural checks (AC-033, AC-034, AC-035)
- LLM tests: 070_auto_help, 071_auto_init_dryrun
