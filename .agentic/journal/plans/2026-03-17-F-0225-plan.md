# F-0225: Spec Evolution Metrics — Implementation Plan

**Status**: APPROVED
**Feature**: F-0225
**Complexity**: Low (5 files, ~250 lines new code)

## Context

The framework tracks acceptance criteria but has no visibility into *how specs evolve* during implementation. `[Discovered]` markers exist (added when agents find new requirements mid-implementation) but nothing aggregates them. Similarly, spec churn (repeated AC file modifications) indicates scope uncertainty but isn't surfaced. This feature closes that gap, and its data feeds F-0210's task-type heuristics later.

## Approach

New standalone analysis tool (`spec-metrics.sh`) following the `spec-audit.sh` pattern: sources `ac-parse.sh`, multiple modes via flags, exit 0 always (advisory). Integrates via existing `ag audit --metrics` gateway.

## Files to Create/Modify

### 1. NEW: `.agentic/lib/tools/spec-metrics.sh`
Core metrics engine with these modes:
- `(default)` / `F-XXXX` — both metrics for all shipped or single feature
- `--discovery` — count `[Discovered]` markers per feature
- `--churn` — git log commit counts per AC file, bucketed into high/medium/low
- `--json` — machine-readable output for F-0210
- `--summary-line` — one-liner for dashboard

Key functions:
- `get_shipped_features()` — grep FEATURES.md for shipped status (same as spec-audit.sh)
- `count_discovered_markers(file)` — `grep -c '\[Discovered\]'`
- `count_churn_commits(fid)` — `git log --oneline -- <ac-file> | wc -l`
- Sources `ac-parse.sh` for AC counting, `paths.sh` for file locations

### 2. MODIFY: `.agentic/lib/tools/ag.sh`
- Add `--metrics)` case to `cmd_audit()` (~line 3960), delegates to `spec-metrics.sh`
- Update help text (2 locations: ~lines 185, 266)

### 3. MODIFY: `.agentic/lib/checklists/retrospective.md`
- Add "Spec Evolution Review" section after "Spec Verification Audit" (~line 194)
- Checklist items: run metrics, review discovery patterns, review high-churn specs, compare to complexity, process improvement

### 4. MODIFY: `.agentic/lib/tools/dashboard.sh`
- Data collection: `D_SPEC_METRICS=$(bash spec-metrics.sh --summary-line)` after AC drift block
- Render: conditional line `"📊 Spec evolution  $D_SPEC_METRICS"` only when non-empty
- Raw mode: `===SPEC_METRICS===` section

### 5. NEW: `tests/test_spec_metrics.sh`
Structural test with temp dir, synthetic AC files, git repo. Covers:
- Discovery counting (with/without markers, single feature)
- Churn analysis (initial + after modification)
- JSON output validation
- Edge cases: no features, no git, no discoveries
- Summary line behavior

### 6. NEW: `.agentic/spec/acceptance/F-0225.md`
4 P1 ACs (discovery, churn, ag audit --metrics, retrospective) + 2 P2 (dashboard, JSON).

## Risks

- **Performance**: `git log` per feature for churn. ~1.5s for 150 features — acceptable since dashboard already does per-feature AC drift scanning. Skip churn in `--summary-line` if it becomes an issue.
- **Non-git environments**: Churn functions gracefully return 0 if git unavailable.
- **`get_shipped_features()` duplication**: Same logic in spec-audit.sh. Acceptable; F-0221 (ag.sh decomposition) will extract shared helpers.
