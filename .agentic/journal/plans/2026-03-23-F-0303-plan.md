# F-0303: Multi-Session Plan Tracking

**Status**: APPROVED

## Context

When a multi-phase plan is approved, phases exist only as markdown headers. No tool tracks their completion. `ag done` marks the entire feature shipped even if only 1 of 5 phases is complete (happened with F-0302). The dashboard can't show progress like "3/5 phases complete."

**Root cause**: Plan approval produces design intent but no trackable work structure. Phases are prose, not data.

**Design constraint**: Push, not pull — work structure is created at plan approval time, not retroactively scanned.

**Integration with F-0302 D3**: F-0302's plan (lines 193-223, 621-646) designed a task system where fine-grained tasks map to assertions and live in `tasks.yaml`. This feature builds the top level of that design (phases from plans). D3's assertion-linked tasks nest inside phases as a future extension — same file, no duplication.

**Capability description**: Approved multi-phase plans produce a trackable work structure that surfaces progress in the dashboard and gates feature completion.

---

## Data Model: `tasks.yaml`

Uses the filename from F-0302 D3. Phases are the top-level structure; tasks nest inside (empty for now, filled by D3 extension later).

```yaml
# .agentic/work/F-XXXX/tasks.yaml
feature: F-0302
source_plan: .agentic/journal/plans/2026-03-22-F-0302-plan.md
created: "2026-03-23"

phases:
  - id: "0"
    title: "Feature Consolidation & Triage"
    status: complete        # pending | active | complete | dropped
    sessions_estimate: "2-3"
    completed_at: "2026-03-20"
    tasks: []               # D3 extension: [{id, description, assertions, status}]

  - id: "1"
    title: "Contract Infrastructure"
    status: complete
    sessions_estimate: "2"
    completed_at: "2026-03-21"
    tasks: []

  - id: "4"
    title: "Protection & V2 Cleanup"
    status: pending
    sessions_estimate: "2"
    completed_at: null
    tasks: []               # Future: ag task add F-0302 "description" --phase 4 --assertions AC-001
```

**Why `tasks.yaml` not `phases.yaml`**: Matches D3's naming. When D3's task-level tracking is built, it populates the `tasks` lists inside each phase. One file, two levels of granularity.

**Ephemeral**: Cleaned up after feature ships (per D3: "process tracking, cleaned up after shipping").

## Implementation

### Step 1: `phases.py` — Core logic (NEW)

**File**: `.agentic/lib/auto/phases.py` (~150 lines)

Functions:
- `extract_phases_from_plan(plan_path) -> list[dict]` — regex-parse `## Phase N: Title (estimate)` headers. Empty list if no phases found (single-phase plans).
- `create_tasks_file(project_root, feature_id, phases, plan_path) -> Path` — write `.agentic/work/F-XXXX/tasks.yaml`. Atomic write. Each phase gets empty `tasks: []` for D3 forward-compatibility.
- `load_tasks_file(project_root, feature_id) -> dict | None` — load tasks.yaml, None if missing.
- `update_phase_status(project_root, feature_id, phase_id, new_status) -> bool` — valid transitions: pending→active, pending→dropped, active→complete, active→dropped. Sets `completed_at`.
- `get_progress_summary(project_root, feature_id) -> str | None` — returns "2/5 phases complete" or None.
- `has_incomplete_phases(project_root, feature_id) -> tuple[bool, str]` — for done.sh gate.
- `sync_phases_with_plan(project_root, feature_id, plan_path) -> dict` — reconcile after plan revision.

**Regex** (covers all observed formats in codebase):
```python
r'^## Phase (\d+[A-Za-z]?)\s*:?\s+(.+?)(?:\s*\(([^)]+)\))?\s*$'
```
Post-process: strip ` ✅ COMPLETE`, ` — NEXT`, etc. from title.

### Step 2: Hook into plan approval

**File**: `.agentic/lib/auto/plan_convergence.py`

After `_update_plan_status(plan_path, "APPROVED")` at **line 316** (autonomous convergence) and **line 246** (review disabled):

```python
from auto.phases import extract_phases_from_plan, create_tasks_file
phases = extract_phases_from_plan(Path(plan_path))
if phases:
    create_tasks_file(self.project_root, feature_id, phases, plan_path)
```

**Fallback in implement.sh**: If plan is APPROVED but no tasks.yaml exists (plan approved outside convergence loop), extract phases at implement time.

### Step 3: `phase.sh` — CLI command (NEW)

**File**: `.agentic/lib/tools/commands/phase.sh` (~90 lines)

```

ag phase active F-XXXX 3    # Mark phase 3 as active
ag phase drop F-XXXX 4      # Mark phase 4 dropped

```

Output for `list`:

### Step 4: Gate in `done.sh`

**File**: `.agentic/lib/tools/commands/done.sh`

Insert after plan backstop gate (line 243), before automated verification (line 245):

- Check `.agentic/work/{feature_id}/tasks.yaml`
- If exists and has incomplete phases → BLOCK with progress message
- Options: `ag phase done`, `ag phase drop`, or `ag done F-XXXX --force-phases`
- All phases complete/dropped → print "✓ All phases complete"
- No tasks.yaml → skip (works as before)

## D3 Forward-Compatibility

This design integrates with F-0302 D3's task system:

| Concept | Built Now | D3 Extension (Later) |
|---|---|---|
| **File** | `tasks.yaml` | Same file |
| **Top level** | `phases:` with status tracking | Same |
| **Nested** | `tasks: []` (empty placeholder) | Populated: `[{id, description, assertions, status}]` |
| **Commands** | `ag phase list/done/active/drop/sync` | `ag task add/done/list` |
| **Gate** | `ag done` checks all phases complete | Also checks all tasks within phases |
| **Dashboard** | "3/5 phases complete" | "Phase 3: 2/4 tasks complete" |
| **Backlog** | Feature-level only | Task-level entries per D3 design |

No separate file, no parallel tracking. One system, two granularity levels.

---

## What This Does NOT Change

- State machine (phases are orthogonal to feature lifecycle states)
- BACKLOG.json (phases are not features)
- Contracts (phases are process, not spec)
- AGENTS.json (phases don't affect multi-agent coordination)
- Plans without `## Phase N` headers → no tasks.yaml → everything works as before

## Verification

1. Create plan with 3 phases → approve → tasks.yaml created with 3 phase entries + empty task lists
2. `ag phase list F-XXXX` shows all phases as pending
3. `ag phase done F-XXXX 1` marks phase 1 complete
4. `ag done F-XXXX` blocks: "1/3 phases complete"
5. `ag done F-XXXX --force-phases` bypasses gate
6. All phases complete → `ag done` succeeds
7. Dashboard shows "1/3 phases — Phase 2: Title next"
8. Plan with no phases → no tasks.yaml → `ag done` unchanged
9. `ag phase sync F-XXXX` after plan revision reconciles correctly
10. tasks.yaml has `tasks: []` in each phase (D3 forward-compatible)
