**Status**: APPROVED

## Context: The Pattern That Keeps Repeating

In a prior session, 3 PRs were merged without running `ag dogfood` — despite rules in completing-work Step 6, memory-seed, auto-memory, and CLAUDE.md. The same session built the doc decision tree to fix the same class of problem (agents skipping behavioral steps).

The pattern across the framework's history:
1. Agent skips step X → We add X to more instruction files → Agent still skips X → We add structural enforcement → X never gets skipped again

Evidence:
- **Pre-commit checks (13 blocking gates)**: ZERO bypasses. They're scripts.
- **`ag merge` → `ag done` chain**: When used, dogfood runs automatically. 100% reliable.
- **Behavioral rules in instruction files**: Periodic failures. 20+ doc update skips. 3+ instruction file skips. Dogfood skips.

Framework principle D2: *"Critical behavior is enforced by scripts and gates, not by documentation and hope."*

## Root Cause: The LLM Bypassed the Entry Point

Failure chain:
1. User said "merge the prs systematically"
2. Agent used `gh pr merge 170` — raw GitHub CLI
3. Because `ag merge` was bypassed, `ag done` chain never fired
4. Dogfood/VERSION/flush never ran

## Deliverables

### 1. UserPromptSubmit detection: "merged but not done"

Add detection #5 to `.agentic/lib/claude-hooks/UserPromptSubmit.sh`:

- On main/master branch
- Extract F-XXXX IDs from last 5 commit messages (catches recent squash merges)
- For each F-ID: check if in FEATURES.md but NOT shipped
- If not shipped → warn: `"⚠️ F-XXXX was merged but ag done was not run. Run: ag done F-XXXX"`

### 2. PostToolUse detection: "gh pr merge" without "ag merge"

New hook script `.agentic/lib/hooks/shared/on-bash-merge-detect.sh`:

- Matcher: `Bash` tool in hooks.json
- Fast exit: if tool input doesn't contain `gh pr merge` → exit 0 immediately (<1ms)
- If `gh pr merge` detected → output warning about using `ag merge` instead
- Wire into both `.claude/hooks.json` and `.agentic/lib/claude-hooks/hooks.json`

### 3. Codify enforcement hierarchy in PRINCIPLES.md

Add subsection to D2 (Deterministic Enforcement):

> **Enforcement Hierarchy** (most to least reliable):
> 1. **Automated chaining**: Action A structurally triggers Action B
> 2. **Blocking gates**: Script exits non-zero
> 3. **State-based detection**: Hook warns on bad state
> 4. **Behavioral guidance**: Concrete instructions
>
> **Promotion rule**: If a behavioral rule has been skipped 3+ times, promote it to a higher level.

### 4. Audit & promote known repeat offenders

Documented in this plan — deliverables #1 and #2 implement the promotions.
