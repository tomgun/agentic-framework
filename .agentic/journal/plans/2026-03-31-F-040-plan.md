# F-040: App Store Publishing

## Context

The framework has no mobile app publishing capabilities. Users building mobile apps (iOS, Android, React Native, Flutter) must manually handle app store submission, screenshot generation, metadata management, and code signing — processes that are error-prone, repetitive, and perfect for framework orchestration.

The goal is to add `ag publish` commands that provide a **generic publisher abstraction** supporting multiple backends (Fastlane, custom scripts) with platform auto-detection, preflight validation, phased execution with state tracking, and automated screenshot generation.

## Design: Provider-Based Architecture

Define a **publisher provider** interface. The framework orchestrates the workflow; providers handle platform-specific mechanics.

```
ag publish ios
    ├── detect.sh             → reads STACK.md + project files (bash)
    ├── preflight.sh          → validates provider, signing, credentials (bash)
    ├── publish.py            → orchestration + state management (Python)
    │   └── providers/        → dispatches to configured backend
    │       ├── fastlane.sh   → wraps fastlane deliver/supply/snapshot
    │       └── custom.sh     → runs user-defined scripts from publish.yaml
    └── status.sh             → displays phase progress (bash)
```

**Key revision from review**: Orchestration and state management in **Python** (following engine.py/scheduler.py pattern). Provider wrappers remain **bash** (thin tool wrappers). Dropped `direct.sh` provider — users wanting direct API access use the `custom` provider.

**Provider selection** in STACK.md:
```
- publish_provider: fastlane  # fastlane | custom
```

## Provider Interface

Each provider implements shell functions sourced by the Python orchestrator:

```bash
provider_capabilities()  # Returns supported phases: "build screenshots metadata submit status"
provider_preflight()     # Validate provider-specific prerequisites
provider_build()         # Build app artifact (IPA/AAB/APK)
provider_screenshots()   # Generate screenshots
provider_metadata()      # Validate store metadata
provider_submit()        # Upload to store
provider_status()        # Check submission/review status
```

The `provider_capabilities()` function lets the orchestrator **skip unsupported phases** gracefully rather than requiring stub implementations. The `custom.sh` provider declares only the capabilities for which the user has defined scripts.

## New Commands

| Command | Description |
|---------|-------------|
| `ag publish init` | Scaffold publishing config (STACK.md + `.agentic/publish.yaml`) |
| `ag publish preflight` | Validate prerequisites (provider, signing, credentials, OS) |
| `ag publish ios [--skip-screenshots] [--dry-run]` | Full iOS pipeline |
| `ag publish android [--skip-screenshots] [--dry-run]` | Full Android pipeline |
| `ag publish screenshots [--ios\|--android]` | Generate screenshots only |
| `ag publish metadata [--validate]` | Validate store metadata completeness |
| `ag publish status` | Show publishing progress + review status |

**Key revision from review**: Added `--dry-run` flag (runs full pipeline without submitting). Each phase is **independently runnable** (not a rigid sequence). The orchestrator checks `provider_capabilities()` and skips phases the provider doesn't support.

## Platform Detection (`publish/detect.sh`)

Reads `mobile_platform` from STACK.md first, then file-system heuristics:

| Signal | Platform |
|--------|----------|
| `*.xcodeproj` / `*.xcworkspace` | Native iOS |
| `build.gradle(.kts)` + `AndroidManifest.xml` | Native Android |
| `package.json` with `react-native` dep | React Native (ios + android) |
| `pubspec.yaml` with `flutter` dep | Flutter (ios + android) |

**Key revision from review**: Preflight also detects **host OS** — iOS commands fail immediately with clear message on non-macOS. Android works on macOS and Linux.

## Credential Management

**Rule: Environment variables only.** Structural test enforces no hardcoded secrets.

| Platform | Required Env Vars |
|----------|-------------------|
| iOS (App Store Connect) | `APP_STORE_CONNECT_API_KEY_ID`, `APP_STORE_CONNECT_API_ISSUER_ID`, `APP_STORE_CONNECT_API_KEY_PATH` |
| iOS (signing via match) | `MATCH_PASSWORD`, `MATCH_GIT_URL` |
| Android (Play Store) | `GOOGLE_PLAY_JSON_KEY_PATH` |
| Android (signing) | `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` |

**Key revision from review**:
- Preflight validates file existence at key paths (not just env var presence)
- Provider output is sanitized — log lines matching credential patterns (`-----BEGIN`, key IDs, etc.) are redacted
- STACK.md template includes link to CI secret management guidance

## State Tracking (`publish-state.json`)

Managed by Python orchestrator in `.agentic/session/publish-state.json`:

```json
{
  "platform": "ios",
  "provider": "fastlane",
  "started_at": "2026-03-31T10:00:00Z",
  "dry_run": false,
  "phases": {
    "preflight": { "status": "passed" },
    "build": { "status": "passed", "artifact": "build/MyApp.ipa" },
    "screenshots": { "status": "skipped", "reason": "provider lacks capability" },
    "metadata": { "status": "running" },
    "submit": { "status": "pending" },
    "monitor": { "status": "pending" }
  },
  "retry_policy": { "max_retries": 3, "backoff": "exponential" }
}
```

Resumable: detects existing state and offers to resume from last incomplete phase. Follows `engine.py` atomic-write pattern (write `.tmp`, rename).
