# F-036: Workflow Definition File — Implementation Plan

**Status**: APPROVED
**Feature**: F-036 — Workflow Definition File
**Date**: 2026-03-28

## Context

`state_machine_af.yaml` claims to be the "single source of truth" for the workflow but is never read by Python code. `state_machine.py` and `gates.py` hardcode all states, transitions, and gates using v1 state names. The YAML uses v2 state names (a different, more compact workflow design). A full v1→v2 migration touches 82+ files and is out of scope.

**Goal:** Make the YAML loadable and validated, so it IS the source of truth for pure-data config (modes, profiles, artifacts, verification, docs policy) and consistency-validated for transitions.

## Approach

Three batches, each independently safe with graceful degradation.

### Batch 1: Foundation (4 files, no behavior change)

1. **`.agentic/state_machine_af.yaml`** — Add missing `engine: v1` field (required by JSON schema)

2. **`.agentic/lib/paths.py`** — Add `self.workflow_file = self.agentic_root / "state_machine_af.yaml"`

3. **`.agentic/lib/auto/workflow.py`** (NEW, ~200 lines) — YAML loader + typed dataclasses:
   - `WorkflowDefinition` with nested dataclasses: `WorkflowConfig`, `Transition`, `ModeConfig`, `ProfileConfig`, `VerifyCommand`, `DocsPolicyConfig`, `ArtifactDef`
   - `WorkflowDefinition.load(yaml_path)` classmethod — lazy yaml import, `yaml.safe_load()`
   - `get_workflow(project_root)` — module-level cached loader
   - `validate_consistency(v1_forward, v1_regression)` — cross-checks YAML transitions against Python tables using `state_mapping` inversion; returns list of discrepancy messages
   - Pattern: follow `contracts.py` `from_dict()` approach

4. **`tests/test_workflow.py`** (NEW, ~150 lines) — Unit tests:
   - Load real `state_machine_af.yaml`, check all sections parsed
   - Mode configs (formal: no escape hatches; lean: has skip transitions)
   - Profile configs (3 profiles, expected gate assignments)
   - Artifact definitions (plan.md, spec.md, etc.)
   - Verification commands (name, run, timeout)
   - State mapping covers all v1 FeatureState values
   - Consistency validation detects mismatches when fed wrong data
   - Caching works (second call returns same instance)

### Batch 2: Validation Script (2 files, no behavior change)

5. **`.agentic/lib/tools/workflow-validate.sh`** (NEW, ~100 lines):
   - Checks YAML exists and is parseable
   - Required sections present (workflow, modes, profiles, artifacts)
   - All states in transitions exist in states list
   - All artifacts in modes.required_artifacts exist in artifacts section
   - All gate names in profiles are referenced in transitions
   - State mapping covers all v1 states
   - Cross-validation via `workflow.py validate_consistency()`
   - Supports `--quiet` flag for CI integration

6. **`tests/validate_framework.sh`** — Add F-036 section after existing V2-001:
   - `workflow.py` exists
   - `workflow-validate.sh` exists and passes
   - `engine` field present in YAML

### Batch 3: Integration (1 file, graceful degradation)

7. **`.agentic/lib/auto/state_machine.py`** — Minimal changes:
   - Load `WorkflowDefinition` in `__init__` with try/except (fallback to None)
   - Add `workflow` property (read-only access)
   - Add `validate_yaml_consistency()` method delegating to `workflow.validate_consistency()`
   - All existing behavior unchanged — YAML is optional enrichment

## NOT in scope

- Migrating v1→v2 state names across 82+ files
- Loading transitions from YAML at runtime (requires v2 migration)
- `get_gate_reviewer()` in gates.py (YAML profiles ≠ profiles.conf profiles — different systems)
- `get_skip_transitions_for_mode()` (ambiguous reverse mapping makes this unsafe in v1)
- The `engine: v2` runtime switch

## Key Design Decisions

1. **YAML profiles (hands_on/guided/autonomous) stay separate from profiles.conf (discovery/formal/autonomous_formal).** They serve different purposes: YAML profiles define gate reviewer assignments; profiles.conf defines 40+ operational settings. Merging them is a future concern.

2. **Validation, not loading, for transitions.** The v1→v2 state mapping is many-to-one (specced + criteria_set → spec), making reverse mapping ambiguous. Transitions stay hardcoded in Python; the YAML is validated for consistency.

3. **Graceful degradation everywhere.** If PyYAML is missing or YAML is malformed, all code falls back to current hardcoded behavior. The YAML loader is never on the critical path.
