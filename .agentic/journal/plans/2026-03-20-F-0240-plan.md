# F-0240: Framework Execution Log — Implementation Plan

**Status**: APPROVED

## Context

When something goes wrong in the agentic framework (commit blocked, gate fails, command exits unexpectedly), there's no unified trace. Diagnostic output scrolls away in the terminal. Users can't answer "why did my commit fail?" after the fact.

F-0240 creates a structured, append-only execution log at `.agentic/session/framework.log`. It's the foundation for F-0242 (Simulation Testing — needs phase detection from the log) and DEV-0243 (Complexity Tier Experiments — needs execution traces per profile).

Phase 1 instruments the three choke points (ag.sh, pre-commit, Claude hooks) for ~80% command coverage.

## Log Format: Pipe-Delimited Text

```
TIMESTAMP | SCRIPT | VERB | ARGS | RESULT
```

Example:
```
2026-03-20T10:45:23Z | ag.sh        | implement    | F-0042                   | start
2026-03-20T10:45:24Z | ag.sh        | implement    | F-0042                   | end:0
2026-03-20T10:46:01Z | pre-commit   | run          | full                     | start
2026-03-20T10:46:01Z | pre-commit   | check        | 1 (wip)                  | pass
2026-03-20T10:46:02Z | pre-commit   | check        | 6 (tests)                | fail
2026-03-20T10:46:03Z | pre-commit   | run          | 1 failure                | end:1
2026-03-20T10:46:10Z | hook:stop    | fire         |                          | start
```

**Rationale**: Pipe-delimited is human-readable (`cat framework.log`), machine-parseable (`split('|')`), and matches F-0242's PhaseChecker needs (pattern match on `ag.sh | implement`). JSON Lines adds quoting overhead without benefit for this use case.

## Files to Create/Modify

### Phase 1: Core Logger + Paths (4 files)

**CREATE: `.agentic/lib/tools/fwlog.sh`** (~30 lines)
- `flog()` function: takes script, verb, args, result
- Append-only: `printf >> "$FRAMEWORK_LOG" 2>/dev/null || true`
- Fail-open: logging errors never break operations; `mkdir -p` session dir on first call
- UTC timestamps via `date -u +%Y-%m-%dT%H:%M:%SZ`
- No padding in output (machine-first; consumers must `strip()` if whitespace added later)
- Guard: `_AGENTIC_FWLOG_LOADED` against double-sourcing

**MODIFY: `.agentic/lib/paths.sh`** (1 line after line 123)
- Add `FRAMEWORK_LOG="$(_resolve_path "$AGENTIC_ROOT/session/framework.log" "$PROJECT_ROOT/.agentic-state/framework.log")"` in session section (use `_resolve_path` for backward-compat consistency)

**MODIFY: `.agentic/lib/paths.py`** (1 line after line 123)
- Add `self.framework_log = self.session_dir / "framework.log"` in session section

**MODIFY: `.gitignore`** (2 lines)
- Add `.agentic/session/framework.log` and `.agentic/session/framework.log.prev` entries (fully qualified, matching existing convention)

### Phase 2: ag.sh Instrumentation (1 file)

**MODIFY: `.agentic/lib/tools/ag.sh`** (~8 lines)
- Source `fwlog.sh` after existing sources (line 15)
- Capture args early: `_AG_CMD="${1:-help}"` and `_AG_ARG="${2:-}"` before case statement
- Before case statement: `flog "ag.sh" "$_AG_CMD" "$_AG_ARG" "start"`
- EXIT trap to log `flog "ag.sh" "$_AG_CMD" "$_AG_ARG" "end:$?"` with real exit code

### Phase 3: Pre-commit Instrumentation (1 file)

**MODIFY: `.agentic/lib/hooks/pre-commit-check.sh`** (~6 lines)
- Source fwlog.sh after paths.sh
- Log `pre-commit | run | full/fast | start` after mode detection (`_FAST_MODE=0` → "full", `_FAST_MODE=1` → "fast")
- Use EXIT trap (not per-exit-point) to log `pre-commit | run | <result> | end:$?` — cleaner than instrumenting 3+ exit points
- NOT logging each individual check (F-0242 needs phase detection, not per-check detail)

- `Stop.sh` — source fwlog.sh, log fire
- `PostToolUse.sh` — source fwlog.sh, log fire
- `UserPromptSubmit.sh` — source fwlog.sh, log fire
- `PreCompact.sh` — source fwlog.sh, log fire

## Acceptance Criteria

### P1 (blocking)
- **AC-1**: `fwlog.sh` provides `flog()` — calling it appends a pipe-delimited line to `framework.log`
- **AC-2**: Every `ag <cmd>` produces start + end log entries
- **AC-3**: Pre-commit produces start + end log entries with failure count
- **AC-4**: Fail-open — unwritable log path doesn't crash any script
- **AC-5**: Log is gitignored
- **AC-6**: F-0242-parseable format — `split('|')` extracts structured fields

### P2 (should have)
- **AC-7**: Session rotation — SessionStart.sh rotates to `.prev`
- **AC-8**: All 5 Claude hooks log fire events
- **AC-9**: `FRAMEWORK_LOG` in both paths.sh and paths.py

## Risks

- **EXIT trap in ag.sh**: Could interfere with `set -e`. Mitigated: trap runs after exit code is set, only does a printf.
- **Pre-commit timing**: Adding a source + 3 flog calls adds ~10ms. Negligible vs test execution.
- **Concurrent writes**: Append-only writes < PIPE_BUF (4096 bytes) are atomic on POSIX. Each line is ~80 bytes.
- **Rotation race**: Concurrent SessionStart.sh could overwrite `.prev`. Acceptable for Phase 1 — single-session is primary use case.
- **PostToolUse volume**: Could produce thousands of entries per session. Acceptable — bounded by session rotation.

## Review Refinements Applied (from dialectical review 2026-03-20)

1. Use `_resolve_path` for `FRAMEWORK_LOG` in paths.sh (backward-compat consistency)
2. Use fully-qualified `.agentic/session/` paths in `.gitignore` (match existing convention)
3. Capture `_AG_CMD`/`_AG_ARG` explicitly in ag.sh (variables don't exist otherwise)
4. Use EXIT trap in pre-commit instead of per-exit-point logging (3+ exit points, cleaner)
5. Add `mkdir -p` in `flog()` for fresh-clone case (session dir may not exist)
6. No padding in log format (machine-first; remove ambiguity from example)
