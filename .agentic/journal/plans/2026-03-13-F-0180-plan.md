# F-0180: Review Checkpoint Framework — Implementation Plan

## Context

ADR-001 defines review checkpoints as a cross-cutting concern: transitions where output must be reviewed before proceeding. Currently the state machine (`state_machine.py`) has gates (precondition checks) but no review layer. This feature adds configurable review modes (human/critical_agent/auto) per transition, with blocking behavior, pending review tracking, and an `ag review` command to resolve blocked transitions.

## Architecture

Review checks happen **after gates pass, before the transition writes**. Gates validate structural preconditions ("does the AC file exist?"). Reviews validate quality ("is this spec good enough?"). Flow:

```
can_transition() → gate check → [pass] → review check → [auto: proceed | human: block] → _update_feature_status()
```

## Files to Create/Modify

### 1. NEW: `.agentic/lib/auto/review.py` (~250 lines)

Core module. Contains:

- **`ReviewMode` enum**: `HUMAN`, `CRITICAL_AGENT`, `AUTO`
- **`TRANSITION_REVIEW_MAP`**: Maps `(from_state, to_state)` → setting key
  - `(planned, specced)` → `review_spec`
  - `(specced, criteria_set)` → `review_criteria`
  - `(tests_written, implementing)` → `review_plan`
  - `(documented, committed)` → `review_code`
  - `(committed, shipped)` → `review_merge`
  - All regressions → `review_regression`
  - Skip transitions → most restrictive review they jump over:
    - `(planned, implementing)` → `review_plan` (jumps over spec+criteria+tests)
    - `(planned, shipped)` → `review_merge` (jumps over everything)
    - `(implementing, shipped)` → `review_merge` (jumps over verified+documented+committed)
    - `(implementing, committed)` → `review_code` (jumps over verified+documented)
  - Unmapped forward transitions (`criteria_set→tests_written`, `implementing→verified`, `verified→documented`) → default `auto` (already have structural gates)
- **`get_review_mode(project_root, from_state, to_state)`**: Resolves mode via `settings.get_setting()`
- **`check_review(project_root, feature_id, from_state, to_state)`** → `(can_proceed, messages)`:
  - First checks if a verdict artifact already exists for `(feature_id, to_state)` → if so, returns `(True, [])` (already reviewed — prevents re-review loop when `resolve_review` triggers `transition()`)
  - `auto`: returns `(True, [])`
  - `human`: creates pending review JSON + HUMAN_NEEDED entry, returns `(False, [instructions])`
  - `critical_agent`: logs fallback message, behaves like `human` (AC-005)
- **`create_pending_review()`**: Writes JSON to `.agentic/session/reviews/{feature_id}_{to_state}.json`, calls `blocker.sh add`. Captures HN-ID from blocker.sh stdout via regex `r"HN-\d{4}"`.
- **`resolve_review(project_root, feature_id, target_state, verdict, reasoning)`**: (1) Stores verdict artifact first, (2) deletes pending review JSON, (3) calls `blocker.sh resolve`, (4) calls `sm.transition()`. Since the verdict artifact now exists, `check_review()` sees it and returns `(True, [])`, preventing a re-review loop.
- **`get_pending_reviews(project_root, feature_id=None)`**: Lists pending reviews
- **`has_pending_review(project_root, feature_id, to_state)`**: Check for specific pending review
- **CLI `main()`**: Entry point for `ag review` dispatch

Pending review JSON format (in `.agentic/session/reviews/`):
```json
{
  "feature_id": "F-0042",
  "from_state": "planned",
  "to_state": "specced",
  "review_setting": "review_spec",
  "review_mode": "human",
  "hn_id": "HN-0025",
  "created_at": "2026-03-08T14:30:00Z"
}
```

Verdict artifact format (in `.agentic/spec/reviews/F-0042/`):
```markdown
# Review: F-0042 planned → specced
- **Verdict**: approved
- **Reviewer**: human
- **Date**: 2026-03-08
- **Setting**: review_spec (mode: human)

## Reasoning
[Free-form text]
```

## Key Design Decisions

- **Reviews after gates**: Gates check "is it structurally ready?" Reviews check "is it good enough?" Gates first avoids reviewing incomplete work.
- **Reviews always hard-block (even in advisory mode)**: Unlike structural gates which are demoted to warnings when `enforce=False`, review checkpoints are quality gates that always block. A human/critical_agent review request is intentional — advisory mode should not bypass it. This is an intentional asymmetry.
- **Pending reviews as JSON files**: One file per `(feature_id, to_state)` in `.agentic/session/reviews/`. Filename encodes lookup key. Session-scoped (ephemeral, not git-tracked). Directory created with `mkdir(parents=True, exist_ok=True)` on first use.
- **Verdict artifacts as markdown**: Git-tracked in `.agentic/spec/reviews/F-XXXX/`. Permanent record. Also serves as "already reviewed" marker to prevent re-review loops.
- **Mode snapshotted at creation** (AC-008): When a pending review is created, the review mode is saved in the JSON. Profile changes don't affect pending reviews.
- **critical_agent → human fallback** (AC-005): Until F-0182 ships, critical_agent logs a message and behaves as human. Clean separation for future wiring.
- **Skip transitions map to most restrictive skipped review**: `(implementing, shipped)` maps to `review_merge`, not `auto`. Prevents bypassing quality gates via skip transitions.
- **review_taste/review_decomposition**: Settings exist in profiles.conf and STACK.md but aren't wired to transitions yet (future features).
- **blocker.sh output parsing**: HN-ID captured from stdout via `r"HN-\d{4}"` regex. Dependency on blocker.sh output format documented.
