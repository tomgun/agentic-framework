# F-0229: Code Annotation Enforcement — Implementation Plan

**Status**: APPROVED
**Feature**: F-0229
**Date**: 2026-03-17
**Revised**: 2026-03-18 (post-dialectical review, round 3)

## Context

The framework has 157+ shipped features but code annotation coverage is spotty. `coverage.py` already detects missing `@feature F-XXXX` annotations, but nothing enforces adding them. This feature wires that detection into pre-commit as Check 22, so newly-shipped features are required to have annotations before committing. Existing shipped features are grandfathered.

## Design

### Core Challenge: Grandfathering

Running `coverage.py --json` reports ALL 157+ shipped features missing annotations. We only want to gate **features transitioning to shipped in the current commit**.

**Approach**: Parse `git diff --cached` on FEATURES.md to find features whose `**Status**` is changing to `shipped`. Then cross-reference with `coverage.py --json` output to check only those features for annotations.

### Check 22 Flow

```
1. Read annotation_enforcement setting (default: off)
2. If off → skip entirely
3. If fast mode → skip (AC-008)
4. Parse staged diff for FEATURES.md → extract feature IDs transitioning to shipped
5. If no features transitioning → skip (nothing to check)
6. Run coverage.py --json → get missing_annotation feature list
7. Intersect: newly-shipped features ∩ missing annotations = violations
8. If advisory → print warning per violation
9. If blocking → print error + increment FAILURES per violation
```

## Implementation Details

### Staged Diff Parsing

```bash
# Extract features being set to shipped in this commit
NEWLY_SHIPPED=()
STAGED_DIFF=$(git diff --cached --unified=10 -- ".agentic/spec/FEATURES.md" 2>/dev/null || true)
if [[ -n "$STAGED_DIFF" ]]; then
  CURRENT_FEATURE=""
  while IFS= read -r line; do
    if [[ "$line" =~ ^[\ +]##\ (F-[0-9]{4,}): ]]; then
      CURRENT_FEATURE="${BASH_REMATCH[1]}"
    fi
    if [[ "$line" =~ ^\+\*\*Status\*\*:\ *shipped ]] && [[ -n "$CURRENT_FEATURE" ]]; then
      NEWLY_SHIPPED+=("$CURRENT_FEATURE")
    fi
  done <<< "$STAGED_DIFF"
fi
```

### Coverage.py Integration

**Critical**: `coverage.py --json` exits 1 when issues are found (line 613:
`return 1 if (missing or orphaned) else 0`). Since this repo has 150+ missing
annotations, it *always* exits 1. The capture pattern must preserve stdout
regardless of exit code.

Three patterns and why only one works:

```bash
# WRONG pattern 1 — $(cmd || echo fallback) concatenates two JSON objects
COVERAGE_JSON=$(python3 ... --json 2>/dev/null || echo '{"issues":[]}')
# Result: "{ real json }\n{\"issues\":[]}" — invalid JSON, parser fails

# WRONG pattern 2 — $(cmd) || VAR=fallback discards real output on exit 1
COVERAGE_JSON=$(python3 ... --json 2>/dev/null) || COVERAGE_JSON='{"issues":[]}'
# Result: COVERAGE_JSON='{"issues":[]}' — real output thrown away

# CORRECT — || true inside subshell suppresses exit code, preserves stdout
COVERAGE_JSON=$(python3 .agentic/lib/tools/coverage.py --json 2>/dev/null || true)
# Result: COVERAGE_JSON contains the real JSON output, exit 0
```

Fallback for empty output (tool missing or broken):
```bash
if [[ -z "$COVERAGE_JSON" ]]; then
  COVERAGE_JSON='{"issues":[]}'
fi
```

Since the environment may not have `jq`, use Python for JSON parsing:
```bash
MISSING_FEATURES=$(echo "$COVERAGE_JSON" | python3 -c "
import sys, json
data = json.load(sys.stdin)
for issue in data.get('issues', []):
    if issue['type'] == 'missing_annotation':
        print(issue['feature'])
" 2>/dev/null || true)
```

### Intersection Logic

```bash
for fid in "${NEWLY_SHIPPED[@]}"; do
  if echo "$MISSING_FEATURES" | grep -q "^${fid}$"; then
    # This newly-shipped feature has no annotations
    if [[ "$ANNOTATION_ENFORCEMENT" == "blocking" ]]; then
      echo "  ❌ $fid: no @feature annotations found in codebase"
      FAILURES=$((FAILURES + 1))
    else
      echo "  ⚠ $fid: no @feature annotations found in codebase (advisory)"
    fi
  else
    echo "  ✓ $fid: has @feature annotations"
  fi
done
```

## Test Strategy

Tests are structural with synthetic data (per AC Verification section). Key additions from dialectical review:

1. **JSON parsing path test**: Feed synthetic `coverage.py --json` output through the real Python parsing one-liner. Validates the actual parsing code that runs in Check 22 — catches malformed JSON, wrong field names, etc.
2. **Exit-code preservation test**: A command that outputs real data and exits 1 (mimicking `coverage.py`) must have its output preserved by the capture pattern. Tests the `|| true` inside-subshell pattern vs the two wrong patterns.
3. **All behavioral paths tested via `run_check22()` helper**: Uses isolated git repos with staged diffs. The helper mirrors Check 22's diff-parsing and intersection logic.
4. **Profile defaults validated**: Reads actual `profiles.conf` to ensure settings are wired.
5. **Hook registration validated**: Checks `pre-commit-check.sh` has Check 22 in header, fast-skip list, and implementation body. Asserts the correct `|| true)` pattern is present.
