# Implementation Plan: F-033 Auto-Sync Addition

**Status**: APPROVED
**Feature**: F-033 — Project-Specific Customization Layer (Auto-Sync scope, formerly F-034)
**Date**: 2026-03-28

---

## 1. Scope

Auto-sync only. The base customization layer (conventions.md, workflow-directions.md, done-checks, policies, lifecycle hooks) is already shipped (AC-001 through AC-007).

**What this delivers**:
1. upgrade.sh detects whether `.agentic/local/` files have been customized vs. still being bare templates
2. When framework templates change, upgrade.sh syncs updated templates while preserving user edits
3. Three-way merge for text files; conflict markers when automatic merge fails
4. New extension subdirectories created if added in newer framework versions
5. Extensions README refreshed when unchanged by the user

**What this does NOT deliver**:
- No runtime sync (upgrade-time only)
- No sync for purely user-authored scripts in extensions/skills/, gates/, hooks/, etc.

---

## 2. Current State

**upgrade.sh today**:
- Step 4 replaces all framework directories (lib/, init/, hooks/, tools/)
- Explicitly preserves `.agentic/local/`, `.agentic/journal/`, `.agentic/session/`
- No template-to-local reconciliation: if templates improve, users never see it
- No new extension subdirectory creation for existing projects

**Template-derived local files** (the files that need sync):

| Template (framework) | Local file (user) |
|---|---|
| `lib/init/conventions-local.template.md` | `local/conventions.md` |
| `lib/init/workflow-directions.template.md` | `local/workflow-directions.md` |
| `lib/init/extensions-readme.md` | `local/extensions/README.md` |

**Existing helper**: `file_looks_like_template()` in scaffold.sh detects unedited templates.

---

## 3. Approach

### 3a. Template Manifest

Introduce `.agentic/local/.template-manifest` recording which template + hash generated each local file:

```
# format: local_path|template_path|template_hash_at_generation
conventions.md|lib/init/conventions-local.template.md|abc123...
workflow-directions.md|lib/init/workflow-directions.template.md|def456...
extensions/README.md|lib/init/extensions-readme.md|789abc...
```

**Bootstrap for existing projects**: When no manifest exists, use backup directory (Step 3 of upgrade.sh already creates one) to compute old template hashes. If backup unavailable, use `file_looks_like_template()` heuristic.

### 3b. Classification

For each template-derived file:
1. **Unmodified**: local hash == old template hash → safe to replace
2. **Customized**: local hash differs → needs merge
3. **Unknown** (no manifest): use heuristic

### 3c. Sync Strategy

- **Text files** (conventions.md, workflow-directions.md): Three-way merge via `diff3 -m`. Clean merge → apply. Conflicts → write conflict markers + warn.
- **README**: Unmodified → replace. Customized → keep, write `.new` for user review.
- **Directories**: `mkdir -p` for any new extension subdirectories. Always safe.

### 3d. Integration Point

New Step 5a in upgrade.sh between "replace framework files" and "regenerate artifacts":
- Old templates available from backup (Step 3)
- New templates just copied (Step 5)
- Sync runs, writes updated manifest

## 7. Risks

| Risk | Mitigation |
|---|---|
| diff3 unavailable | Fall back to "keep + .new" strategy |
| No manifest on first upgrade | Reconstruct from backup or use heuristic |
| Conflict markers confuse agents | Standard git-style markers; agents handle these |
| Cross-platform SHA-256 | Try sha256sum then shasum -a 256 |

**Open questions**:
1. Should .template-manifest be committed? (Rec: yes, small and useful for teams)
2. Add `--no-local-sync` flag? (Rec: yes, safety valve)
