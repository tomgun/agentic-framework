# Implementation Plan: F-033 Auto-Sync Addition

**Status**: APPROVED
**Feature**: F-033 — Project-Specific Customization Layer (Auto-Sync scope, formerly F-034)
**Date**: 2026-03-28

> **Simplification note**: The original draft proposed manifest tracking and three-way
> merge via `diff3`. During review this was simplified to heuristic detection +
> `.new` fallback. No manifest, no shared utility library, no scaffold.sh changes.

---

## 1. Scope

Auto-sync only. The base customization layer (conventions.md, workflow-directions.md, done-checks, policies, lifecycle hooks) is already shipped (AC-001 through AC-007).

**What this delivers**:
1. upgrade.sh detects whether `.agentic/local/` files have been customized vs. still being bare templates
2. When framework templates change, upgrade.sh replaces unmodified templates and preserves customized files (writing `.new` for manual review)
3. New extension subdirectories created if added in newer framework versions
4. Extensions README refreshed when unchanged by the user

**What this does NOT deliver**:
- No runtime sync (upgrade-time only)
- No sync for purely user-authored scripts in extensions/skills/, gates/, hooks/, etc.

---

## 2. Current State

**upgrade.sh today**:
- Step 4 replaces all framework directories (lib/, init/, hooks/, tools/)
- Explicitly preserves `.agentic/local/`, `.agentic/journal/`, `.agentic/session/`
- No template-to-local reconciliation: if templates improve, users never see it
- No new extension subdirectory creation for existing projects

**Template-derived local files** (the files that need sync):

| Template (framework) | Local file (user) |
|---|---|
| `lib/init/conventions-local.template.md` | `local/conventions.md` |
| `lib/init/workflow-directions.template.md` | `local/workflow-directions.md` |
| `lib/init/extensions-readme.md` | `local/extensions/README.md` |

**Existing helper**: `file_looks_like_template()` in scaffold.sh detects unedited templates.

---

## 3. Approach

### 3a. Heuristic Detection

Use `_file_looks_like_template()` (inline in upgrade.sh, same logic as scaffold.sh) to classify each local file:
1. **Unmodified**: heuristic says template → safe to replace with new version
2. **Customized**: heuristic says not template → preserve, write `.new` if template differs
3. **Missing**: create from template

No manifest tracking needed — the heuristic is reliable for the small set of template-derived files.

### 3b. Sync Strategy

- **All template-derived files**: Unmodified → replace. Customized + template changed → keep, write `.new`. Customized + template unchanged → no action.
- **Directories**: `mkdir -p` for any new extension subdirectories. Always safe and idempotent.

### 3c. Integration Point

New Step 5a in upgrade.sh between "replace framework files" (Step 5) and "regenerate artifacts" (Step 5b). New templates are already in place after Step 5.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Heuristic misclassifies a customized file as template | Safe direction: only replaces if file matches template markers. Worst case: customized file preserved when it could have been updated. |
| `.new` files accumulate across upgrades | Each upgrade overwrites previous `.new`. User warned in upgrade output. |
