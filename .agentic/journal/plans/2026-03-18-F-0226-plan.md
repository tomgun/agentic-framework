# Plan: F-0226 — Post-Merge Dogfooding

**Status**: APPROVED (R2 — both Critic and Advocate approve)
**Feature**: F-0226
**Created**: 2026-03-18

## Problem

After merging framework PRs, root instruction files (CLAUDE.md, .cursorrules, copilot, codex) can drift from their canonical templates in `.agentic/lib/agents/`. Memory-seed can go stale when workflow rules change. Currently this is a manual checklist item in `feature_complete.md` (line 328) with no automation — drift gets discovered sessions later, if at all. The feedback memory (`feedback_post_merge_dogfood_sync.md`) explicitly calls for this to be automatic.

**Evidence of active drift**: Right now, root `.cursorrules` is missing trigger rows that the template has (Verify framework, Feedback, Formalize), and the template's "Done" trigger has richer content than root's version.

## Approach

Create a `dogfood-sync.sh` script and wire it into `ag done` on main (framework-dev only).

**Architecture**:
- New script `dogfood-sync.sh` — 3-phase detection using sentinel-based comparison
- Runs automatically as part of `ag done` on main **only when `FRAMEWORK_DEVELOPMENT.md` exists** (framework-dev guard)
- Reuses existing `instruction-sync.sh` (Phase 1) and `memory-check.sh` (Phase 3) — no duplication
- Phase 2 is the only new detection logic: per-file sentinel checking for shared content drift
- Reports drift as advisory (not blocking) with actionable fix suggestions per item
- `ag dogfood` subcommand for manual pre-commit spot-checking

**Why advisory, not blocking**: Root files intentionally diverge from templates (framework-dev-only content). The script detects _missing shared content_ but can't auto-merge safely. Blocking `ag done` would generate false positives. Instead: report clearly with fix suggestions, let the agent act.

## Phase 2 Algorithm: Sentinel-Based Content Drift Detection

Rather than parsing/extracting markdown sections (fragile, breaks on reorganization), Phase 2 uses **per-file sentinel lists** — key strings that MUST appear in both root and template. This mirrors the proven pattern from `memory-check.sh` (which uses 4 sentinels).

### File Pairs and Comparison Modes

| Root File | Template | Mode | Rationale |
|-----------|----------|------|-----------|
| `CLAUDE.md` | `.agentic/lib/agents/claude/CLAUDE.md` | Full sentinel check | High structural similarity — shared sections are contiguous |
| `.github/copilot-instructions.md` | `.agentic/lib/agents/copilot/copilot-instructions.md` | Full sentinel check | High structural similarity |
| `.codex/instructions.md` | `.agentic/lib/agents/codex/codex-instructions.md` | Full sentinel check | High structural similarity |
| `.cursorrules` | `.agentic/lib/agents/cursor/cursorrules.txt` | Reduced check (Quick Commands + trigger table only) | Root is intentionally a lean wrapper per FRAMEWORK_DEVELOPMENT.md |

### Sentinel Categories

Sentinels are grouped by category. Each sentinel is a grep-able string:

```bash
# Quick Commands (must appear in all root files that have them)
SENTINELS_QUICK_COMMANDS=(
    "ag start"
    "ag sync"
    "ag implement"
    "ag commit"
    "ag done"
    "ag plan"
    "ag backlog"
    "ag review"
    "ag dogfood"   # added by this feature
)

# Core Rules (full-check files only)
SENTINELS_CORE_RULES=(
    "show changes to human before committing"
    "PR by default"
    "Spec + code + tests + docs = done"
    "Shipped specs are contracts"
    "Keep changes small and scoped"
)

# Token-Efficient Scripts (full-check files only)
SENTINELS_SCRIPTS=(
    "status.sh focus"
    "journal.sh"
    "blocker.sh"
    "feature.sh"
    "todo.sh"
)
```

### Detection Logic

For each file pair:
1. Read template, check which sentinels are present
2. For each sentinel present in template, check if present in root
3. If sentinel is in template but NOT in root → report as drift
4. If sentinel is in root but NOT in template → skip (framework-dev-specific, expected)

### Suppression

Lines containing `<!-- dogfood:ignore -->` in root files are excluded from sentinel checking. This handles intentional divergence that would otherwise be flagged on every run.

### Output Per Drift Item

Each reported drift includes a fix suggestion:
```
⚠ CLAUDE.md missing sentinel: "ag dogfood"
  Present in template at line 16
  Suggestion: Add to Quick Commands section (~line 12)
```

## What `dogfood-sync.sh` Does

```
Phase 1: AG Command Parity (delegates to instruction-sync.sh --brief)
  → Are all ag commands documented in all instruction files?
  → Already tested/proven tool — just invoke and report

Phase 2: Sentinel-Based Content Drift (NEW — the core value of this feature)
  → For each root-template pair:
    - Select sentinel list based on comparison mode (full vs. reduced)
    - Check each sentinel: present in template? present in root?
    - Report missing sentinels with fix suggestions
  → Per-file comparison modes handle .cursorrules asymmetry

Phase 3: Memory-Seed Freshness (delegates to memory-check.sh)
  → Version current? Sentinels intact?
  → Already tested/proven tool — just invoke and report
```

Output modes:
- Default: full report with per-item fix suggestions
- `--brief`: one-line summary per phase (used inside `ag done`)

Exit code: 0 = clean, 1 = drift found.

**Dropped from R1**: `--json` mode (no programmatic consumer exists), Phase 4 / Skill Reference Freshness (under-specified, not in original feedback — defer to follow-up feature).

## Integration into `ag done`

In `cmd_done()`, after VERSION bump + flush block (line ~1980), before intent clear:

```bash
# Post-merge dogfood sync (framework-dev only)
if [ -f "$ROOT_DIR/FRAMEWORK_DEVELOPMENT.md" ]; then
    echo ""
    echo -e "${BOLD}=== Dogfood Sync ===${NC}"
    bash "$SCRIPT_DIR/dogfood-sync.sh" --brief || true
fi
```

## `ag dogfood` Subcommand

Manual invocation for pre-commit spot-checking during development:
```bash
ag dogfood           # Full report with fix suggestions
ag dogfood --brief   # One-line summary per phase
```

**Why keep this as a subcommand**: Enables framework developers to check for drift *before* creating a PR, shifting detection left. The instruction file updates are required anyway (this feature adds content to those files regardless), so the marginal cost of adding `ag dogfood` to quick command lists is one line per file.

## Acceptance Criteria

1. `dogfood-sync.sh` Phase 1 detects missing ag commands in instruction files (delegates to instruction-sync.sh)
2. `dogfood-sync.sh` Phase 2 detects when sentinel strings present in a template are absent from the corresponding root file, using per-file comparison modes (full for CLAUDE.md/copilot/codex, reduced for .cursorrules)
3. `dogfood-sync.sh` Phase 3 detects stale memory-seed (delegates to memory-check.sh)
4. `ag done` on main automatically runs dogfood sync when `FRAMEWORK_DEVELOPMENT.md` exists
5. `ag done` on main skips dogfood sync when `FRAMEWORK_DEVELOPMENT.md` doesn't exist (user projects)
6. `ag dogfood` subcommand available for manual invocation with full report and `--brief` mode
7. Drift is reported as advisory (doesn't block `ag done`) with actionable fix suggestions per item
8. Root files can suppress false positives with `<!-- dogfood:ignore -->` on specific lines
9. Tests use controlled mock template/root fixtures with known drift to validate all 3 phases

## Test Strategy

`tests/test_dogfood_sync.sh` creates temporary directories with mock root/template file pairs:

- **Test 1: Clean state** — root and template have identical sentinels → exit 0
- **Test 2: Missing sentinel** — template has "ag backlog", root doesn't → exit 1, reports drift
- **Test 3: Suppressed drift** — root missing sentinel but line has `<!-- dogfood:ignore -->` → exit 0
- **Test 4: Reduced mode** — .cursorrules mock only checks Quick Commands sentinels, not Core Rules → exit 0 even though Core Rules differ
- **Test 5: Phase 1 delegation** — verifies instruction-sync.sh is called (mock with stub)
- **Test 6: Phase 3 delegation** — verifies memory-check.sh is called (mock with stub)
- **Test 7: --brief output** — verifies one-line-per-phase format

## Risks

- **Sentinel maintenance**: When new shared content is added to templates, the sentinel list needs updating. Mitigation: sentinels are defined in a single array at the top of `dogfood-sync.sh`, easy to find and extend. The tool itself will catch missing sentinels when run.
- **False positives on wording variants**: Root might use slightly different wording than template for the same concept. Mitigation: sentinels are chosen as distinctive key phrases (command names, script paths) not prose.
- **Scope creep**: Auto-fix is tempting but risky. Keep detection-only for v1; `--fix-safe` for trivial cases (e.g., appending missing ag commands to Quick Commands) can be a follow-up.

## Alternatives Considered

1. **Full auto-sync** — automatically overwrite root shared sections from template. Rejected: too risky, root has framework-dev additions interleaved.
2. **Pre-commit gate** — block commits if root/template diverge. Rejected: would block every commit, not just post-merge. Too noisy.
3. **Extend sync.sh as Phase 11** — add dogfood checking to existing sync.sh with `--post-merge` flag. Rejected: sync.sh is already 10 phases / 1084 lines and runs at session start where speed matters. Dogfood sync is semantically different (post-merge verification vs. session reconciliation) and warrants its own script. `ag done` calls it directly; no flag-passing complexity.
4. **Section extraction / markdown parsing** — parse sections by header and diff them. Rejected: fragile, breaks on reorganization, root `.cursorrules` has completely different structure from template. Sentinel approach is simpler, more robust, and follows the proven `memory-check.sh` pattern.
