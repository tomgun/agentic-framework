# Plan: F-0235 + F-0236 — Auto-Review After PR & Autonomous Plan Convergence Loop

**Status**: CONVERGED (pending user approval)
**Iteration**: 5

## Context

Two gaps in the autonomous pipeline:

1. **After `ag auto task` creates a PR, nothing reviews it.** The reviewing-code skill exists but is only triggered manually. Teams using `git_workflow: pull_request` automate implementation but leave review manual. This should be default behavior when PR mode is on.

2. **The plan review loop requires human input per iteration.** Planner → Critic+Advocate → Synthesis → *user decides* → repeat. This blocks autonomous workflows and prevents `ag auto task/epic` from running plan review end-to-end. Additionally, reviewer roles are fixed to Critic+Advocate with no domain expertise (security, UX, DB, etc.).

Both features are independent. No dependency between them.

### Hook Point

`task.py` line ~206, after `_create_pr()` returns. Each TaskRunner handles its own review — parallel epic gets it for free (each worktree runs a full TaskRunner).

**Parallel epic behavior**: `ParallelDispatcher` spawns independent `TaskRunner` subprocesses per worktree. Each worktree runs a full `TaskRunner` that creates its own PR — `review_and_fix_pr()` fires naturally per-worktree via the `task.py` hook. There is NO coordinator-level PR creation. No changes needed in `ParallelDispatcher` or `parallel.py`. When `--skip-branch` is used (subprocess internal flag), the TaskRunner still creates PRs from its own branch — the flag only skips branch creation (branch is already created by the worktree setup).

**Worktree tool access**: The fix/review agents use `spawn_claude()` with the worktree as `project_root` — the same pattern used by existing `_spawn_claude_implement()` (task.py:257) and `VerifyLoop._spawn_claude_fix()` (verify.py:731) which already work in worktrees. No special handling needed for `.claude/settings.json` — worktrees contain the full repo checkout including `.claude/`.

### Interaction with `review_code` gate

`review_pr` (new, post-PR-creation) is **distinct** from `review_code` (existing, pre-commit state machine gate). They fire at different pipeline stages:
- `review_code`: gates the `documented → committed` transition, fires BEFORE PR creation
- `review_pr`: fires AFTER PR creation, reviews the complete diff on GitHub

When both are `critical_agent`: no conflict — they serve different purposes (pre-commit quality vs post-PR holistic review). When `review_code: human`: human reviews code in worktree, then `review_pr: critical_agent` does automated PR review — complementary, not duplicate. The plan does NOT create HUMAN_NEEDED entries for `review_pr: critical_agent` when the verdict is APPROVED.

### Auto-Fix Loop (review → fix → re-review)

When review returns REQUEST_CHANGES or NEEDS_DISCUSSION, the agent **automatically fixes the issues** before escalating to human:

```
┌──────────┐     ┌──────────┐     ┌───────────┐
│ PR       │────▶│ Review   │────▶│ Verdict   │
│ Created  │     │ Agent    │     │           │
└──────────┘     └──────────┘     └─────┬─────┘
                                        │
                              APPROVED ──┤── REQUEST_CHANGES / NEEDS_DISCUSSION
                                  │      │
                                  ▼      ▼
                             ┌────────┐ ┌────────────┐
                             │ Done   │ │ Fix Agent   │
                             └────────┘ │ (auto-fix)  │
                                        └──────┬─────┘
                                               │
                                        ┌──────▼─────┐
                                        │ Push fixes  │
                                        │ Re-review   │◀─┐
                                        └──────┬─────┘   │
                                               │         │
                                          Still fails? ──┘
                                          (max 2 fix attempts)
                                               │
                                          Escalate to human
```

**Flow**:
1. Review agent posts findings on PR
2. Fix agent receives `must_fix` + `should_fix` items, the diff, and AC context
3. Fix agent makes changes, commits, pushes to PR branch
4. Re-review with fresh review agent (max `pr_fix_max_attempts: 2`)
5. If still not approved after max attempts → HUMAN_NEEDED entry + `review_blocked`

- `formal.pr_fix_max_attempts=2`

### `review_pr: human` Behavior

When `review_pr: human`: no automated review or fix loop runs. Instead, use a **lightweight PR-review-specific mechanism** (NOT the state machine's `create_pending_review()`/`resolve_review()` — PR review is a post-pipeline concern, not a state transition).

**Why not `create_pending_review()`**: `resolve_review()` calls `FeatureState(target_state)` + `sm.transition()`. There is no `pr_reviewed` FeatureState, and adding one would change the state machine for all users. PR review is orthogonal to the feature lifecycle.

**Mechanism in `pr_review.py`**:
```python

    # 3. Return block info for scheduler

def _check_pr_review_resolved(self, feature_id: str) -> bool:
    # Check GitHub: gh pr view {number} --json reviewDecision
    # If reviewDecision == "APPROVED":
    #   - Delete {feature_id}_pr_review.json
    #   - Resolve HUMAN_NEEDED entry via blocker.sh
    #   - Return True
    # Else: Return False
```

The scheduler's `_is_review_blocked()` already globs `{feature_id}_*.json` in `pending_reviews/` — the PR review JSON is picked up automatically. Resolution is via GitHub API check in the polling loop (calls `_check_pr_review_resolved()`), not via `ag review` CLI (which calls `resolve_review()` and would crash on non-existent state).

### Review Outcome Actions (after fix loop exhausted)

| Verdict | Action |
|---------|--------|
| APPROVED | Log to journal. If `review_merge: skip` too → `gh pr merge --squash`. Otherwise PR sits with approval, human merges. |
| REQUEST_CHANGES (after max fix attempts) | Post review on GitHub. Create HUMAN_NEEDED entry. Scheduler marks `review_blocked`. |
| NEEDS_DISCUSSION (after max fix attempts) | Post comment on GitHub. Create HUMAN_NEEDED entry. Scheduler marks `review_blocked`. |

Auto-merge requires **double opt-in**: `review_pr` passes AND `review_merge: skip`. Default formal has `review_merge: human`, so human always merges even after auto-approval.

### Convergence Loop Flow

```
│ Planner │────▶│   Plan   │────▶│ All reviewers (parallel) │
└─────────┘     │ Artifact │     │ Critic + Advocate + ...  │
     ▲          └──────────┘     └───────────┬─────────────┘

                                      └──┬───────┬──┘
                                    YES  │       │  NO + max_iter
                                         ▼       ▼
                                    ┌────────┐ ┌──────────┐
                                    │Present │ │ Escalate │
                                    │to user │ │to human  │
                                    └────────┘ └──────────┘
```

**Interactive sessions**: Converged plan presented to user → user approves/rejects.
**Autonomous sessions** (`ag auto task`): Converged plan → APPROVED, proceed. Not converged after max → ESCALATED, HUMAN_NEEDED, task fails.

### Convergence Detection

A plan is **converged** when ALL of:
1. Critic has **zero High-Confidence Concerns** (parsed from structured output)
2. No expert reviewer has high-severity findings
3. Iteration >= 2 (minimum 2 rounds prevents rubber-stamping)

New output section added to Critic and Advocate agents:

```markdown
### Convergence Signal
- [x] Plan is fundamentally sound (no high-severity concerns remaining)
```

The `ConvergenceDetector` class:
1. Parses Critic's "High-Confidence Concerns" section — empty = strong convergence signal
2. Checks explicit convergence checkbox (`- [x]` pattern)
3. Parses expert outputs for high-severity items
4. `iteration >= 2` guard
5. Returns `(converged: bool, reason: str)`

**Resilient parsing**: Use regex patterns with fallbacks:
- Primary: `### High-Confidence Concerns\n` followed by numbered items → count > 0 means NOT converged
- Fallback: If section header not found, search for `High-Confidence` anywhere in output → if found with numbered items, NOT converged
- Last resort: If parsing fails entirely → NOT converged (safe default, forces another iteration or escalation)
- Convergence checkbox: `r"- \[x\] Plan is fundamentally sound"` — if checkbox not found, ignore (don't block convergence on missing checkbox)
- Tests include: malformed output, missing sections, extra whitespace, section name variations

### Auto-Revision

When not converged, the Planner agent is spawned via `spawn_claude(prompt, print_mode=False)` — NOT print_mode, because the Planner must **write** the revised plan file. The Planner receives:
1. Current plan file path (to read and edit)
2. Full synthesis with all reviewer outputs (inlined in prompt)
3. Revision Guidance section extracted from synthesis (highlighted)
4. Instruction: "Read the plan at {path}. Address all High-Confidence Findings. Defend approach where correct. Increment iteration counter. Set status to REVIEWING. Write changes back to the plan file."

This replaces the "user tells planner what to change" step. The Revision Guidance (already generated by synthesis) serves as the automated direction.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Review agent produces low-quality PR reviews | Uses battle-tested reviewing-code protocol; same model selection as CriticalAgent |
| GitHub API rate limits in parallel epic (N PRs) | Sequential per TaskRunner; natural spacing across worktrees |
| Auto-merge bypasses human | Double opt-in: `review_pr` passes AND `review_merge: skip` |
| Convergence loop never converges (oscillation) | Hard max_iterations (enforced, not advisory); HUMAN_NEEDED escalation |
| Too many reviewer agents = high cost | Only Critic+Advocate by default; experts opt-in; all mid-tier models |
| False convergence (Critic runs out of things to say) | Minimum 2 iterations; explicit convergence signal checkbox; expert findings also block |
| Auto-revision makes plan worse | Full Review History preserved per iteration; traceable; human approves final in interactive sessions |
| No YAML stdlib (catalog format) | Use JSON — zero new dependencies |
| Critic output format drift breaks convergence detection | Resilient regex parsing with fallbacks; safe default = NOT converged; parser tests with malformed output |
| `get_setting()` returns string not list | New `get_setting_list()` helper parses both comma-separated and bracket-list formats |
| `plan_review_max_iterations` enforcement is breaking change | CHANGELOG entry; advisory→enforced is stricter but prevents infinite loops in autonomous mode |
| Fix agent needs file write access | Spawned with `print_mode=False` (not print mode); runs in existing worktree on PR branch |
