# F-0301: Completion Gate — Block New Work When Previous Feature Unfinished

**Status**: APPROVED

## Context

When agents commit directly to main (no PR), they often skip `ag done`, leaving features with merged code but still marked "planned" in FEATURES.md. This was discovered when 3 features were found shipped but still "planned". The PR path triggers `ag done` via `ag merge`, but direct-to-main commits have no enforcement.

F-0301 adds a completion gate at two points:
- **`ag implement`** (hard block): Checks if any prior backlog item has commits on main but no "shipped" status.
- **dashboard / `ag start`** (advisory warning): Surfaces when the current backlog item has merged implementation but is still "planned".

## Implementation Steps

### Step 1: Add `check-completion-gate` to `backlog_helpers.py` (~70 lines)

Add `_get_feature_status(feature_id, features_path) -> Optional[str]` — returns the canonical status string from FEATURES.md. Refactor existing `_is_feature_shipped()` to use it.

Add `cmd_check_completion_gate(args)`:
1. Load backlog, find target feature's position
2. For each backlog item at a position **before** the target (or position 0 if checking current item):
   - Read status via `_get_feature_status()` (AC-3)
   - Skip items where `type != "feature"` (task-type items have no feature ID)
   - If status is "planned" only (AC-6: "partial", "in_progress" don't trigger), check for commits:
     - `git log --oneline --grep="F-YYYY" main -- ':!.agentic/'` (exclude spec/plan/state commits to avoid false positives)
     - `git branch --list "feat/F-YYYY-*" --merged main` (AC-8)
   - If commits found + status "planned" → output `{"blocked": true, "stale_feature": "F-YYYY", "status": "planned", "commit_count": N}`
   - Otherwise → `{"blocked": false}`

Accept optional `_has_commits_fn` callback for testability.

### Step 2: Add completion gate to `implement.sh` (~30 lines)

Insert after backlog gate (section 0b, ~line 93). Add `--force` to flag parsing.

1. Call `backlog_helpers.py check-completion-gate "$feature_id"`, parse JSON
2. If blocked:
   - Print: `BLOCKED: F-YYYY has merged code on main but is still marked "planned".`
   - Print: `Run: ag done F-YYYY`
   - Print: `Or bypass: ag implement --force $feature_id`
   - Exit 1 (unless `--force`)
3. If `--force` + blocked: warn but continue

### Step 3: Fix ag.sh dispatcher (~1 line)

Change `implement)` dispatch from `cmd_implement "${2:-}"` to `shift; cmd_implement "$@"`. Required for `--force` flag; also fixes latent bug with `--skip-clarity`.

### Step 4: Add dashboard warning (~15 lines)

Add `D_COMPLETION_STALE` data collection after stale check (~line 227). Render as:
```
⚠️  Unfinished    F-YYYY has merged code but isn't shipped — run: ag done F-YYYY
```

### Step 5: Add `ag start` advisory (~15 lines)

In `start.sh`, after backlog display (~line 162), check completion gate for current backlog item and print advisory warning if stale.

### Step 6: Unit tests (~100 lines)

In `tests/test_backlog_helpers.py`, add `TestCheckCompletionGate`:

- `test_first_item_no_false_positive` (AC-7)

## Design Decisions

- **Logic in Python (backlog_helpers.py)**: Git subprocess calls + JSON output are more robust in Python. Testable without bash fixtures. Follows existing pattern (bash shells call Python for data queries).
- **Check items "ahead" in backlog, not just position 0**: AC-1 says "any item ahead of F-XXXX." Dashboard only checks current item (most actionable).
- **`--force` flag over env var**: AC-5 specifies `--force`. More user-friendly. `SKIP_BACKLOG=1` already bypasses the entire section.
- **Dispatcher fix is prerequisite**: `ag.sh` currently passes only `"${2:-}"`, so `--force` and `--skip-clarity` flags don't reach the function. This latent bug must be fixed.
