## 1. Control Mechanism: Unix Domain Socket + CLI Command

### Problem
The engine needs to accept commands (pause, resume, stop, feedback) from the user while running. A plain control file has race conditions, no acknowledgments, and parsing fragility.

### Design

**Engine side** (Python):
- On startup, create a Unix domain socket at `.agentic/session/auto.sock`
- Write PID to `.agentic/session/auto.pid`
- Lightweight listener thread (Python `threading` + `socket`, stdlib only)
- Accept newline-delimited JSON commands, respond with JSON ack

**User side** (thin CLI):
- `ag auto pause` — sends `{"cmd": "pause"}`, gets `{"ack": true, "state": "paused"}`
- `ag auto resume` — sends `{"cmd": "resume"}`, gets `{"ack": true, "state": "running"}`
- `ag auto stop` — sends `{"cmd": "stop"}`, gets `{"ack": true, "state": "stopping"}`
- `ag auto feedback AC-003 "use existing auth"` — sends feedback, gets ack
- `ag auto status` — sends `{"cmd": "status"}`, gets full engine state

**Why socket**: Bidirectional, structured, race-free, no network exposure. Falls back to TCP localhost on Windows if ever needed.

**Cleanup**: Engine deletes socket + PID on exit (atexit + signal handlers). Stale socket detected by connection attempt — if refused, clean up and start fresh.

### Files
- `.agentic/lib/auto/engine.py` (socket listener thread)
- `.agentic/lib/auto/control.py` (CLI client)
- `ag.sh` (route `ag auto pause|resume|stop|feedback|status`)
- `.agentic/session/auto.sock`, `.agentic/session/auto.pid` (gitignored)

## 2. Settings.json Template: Scoped Permissions for Tier 2

### Problem
Users running without Docker need a `settings.json` that grants the Claude instance enough autonomy to work without unrestricted system access.

### Template
Stored at `.agentic/lib/auto/settings-template.json`. Generated by `ag auto init` which reads STACK.md to detect the project's package manager and test runner.

### Three-tier model
```
Tier 1: Sandboxed       -> docker run ... claude --dangerously-skip-permissions
Tier 2: Scoped (default)-> claude --settings .claude/settings.json
Tier 3: Interactive      -> claude (normal prompts, engine pauses on approval)
```

### Files
- `.agentic/lib/auto/settings-template.json`
- `.agentic/lib/auto/init.py` (ag auto init logic)

## 3. Handling Oversized ACs: Decompose and Complete

### Problem
Some ACs may require more implementation work than fits in a single Claude context window.

### Approach: Detect, Decompose, Implement All

**Pre-flight estimation** (one prompt per AC):
Ask Claude for SMALL/MEDIUM/LARGE estimate.

**LARGE ACs — auto-decompose**:
1. Engine asks Claude to break the AC into 2-5 sequential sub-tasks (via `decompose-ac.md` prompt)
2. Each sub-task gets its own fresh Claude instance
3. All sub-tasks must pass for the parent AC to be marked complete
4. If a sub-task itself exhausts context, one more level of decomposition is attempted
5. The AC spec itself is NOT modified — sub-tasks are internal to the engine

**Runtime detection** (deterministic):
After a SMALL/MEDIUM implementation attempt — if tests fail AND >80% context used, the AC is re-routed through decomposition (same as LARGE path).

**Key design point**: Sub-tasks are engine-internal work items, not spec changes. The acceptance criterion stays as written. The engine just breaks the work into smaller bites.

### Files
- `.agentic/lib/auto/engine.py` (complexity estimation, decomposition, sub-task loop)
- `.agentic/lib/auto/prompts/estimate-complexity.md`
- `.agentic/lib/auto/prompts/decompose-ac.md`
