## Context

Currently `ag done` checks AC completion, FEATURES.md registration, and docs drift — but there's no verification that smoke testing actually happened. This feature adds an evidence-based gate: `ag done` checks for a file at `.agentic/journal/evidence/F-XXXX-smoke.*`. A new setting `smoke_test_evidence` (required|recommended|off) controls behavior. Additionally, `ag auto verify --visual` gains a `--feature` flag to auto-save its output as evidence.

## Approach

Follow the pattern established by the `docs_gate` in `ag.sh` cmd_done. Three-value setting with profile defaults. Evidence directory parallels existing journal subdirectories (plans, lessons, manifests).

## Naming Convention Decision

The `docs_gate` uses `off|warning|blocking`. This feature uses `off|recommended|required` instead because:
- `recommended` communicates intent better than `warning` — it tells users what the framework _suggests_, not just that something is missing
- `required` is clearer than `blocking` for a new-to-the-framework user — "your evidence is required" vs "your evidence is blocking"
- The three values map semantically: `off` = skip, `recommended` = warn but proceed, `required` = block

This is a conscious divergence from docs_gate naming, documented here for future contributors.

## Gate Logic (ag.sh insertion after docs gate, before Feature Complete Check)

```bash
# Smoke test evidence gate
local smoke_evidence_mode
smoke_evidence_mode=$(get_setting "smoke_test_evidence" "off")

if [ "$smoke_evidence_mode" != "off" ] && [ -n "$feature_id" ] && echo "$feature_id" | grep -qE '^F-[0-9]{4}$'; then
    echo -e "${BOLD}=== Smoke Test Evidence Check ===${NC}"
    mkdir -p "$ROOT_DIR/.agentic/journal/evidence"
    local evidence_found=""
    for f in "$ROOT_DIR/.agentic/journal/evidence/${feature_id}-smoke".*; do
        [ -e "$f" ] && evidence_found="$f" && break
    done
    if [ -n "$evidence_found" ]; then
        echo -e "${GREEN}✓ Evidence found: $(basename "$evidence_found")${NC}"
    elif [ "$smoke_evidence_mode" = "required" ]; then
        if [ "${SKIP_SMOKE_EVIDENCE:-0}" = "1" ] || [ ! -t 0 ]; then
            echo -e "${YELLOW}smoke_test_evidence: required — skipped (non-interactive)${NC}"
        else
            echo -e "${RED}BLOCKED: No smoke test evidence for $feature_id${NC}"
            echo "  Expected: .agentic/journal/evidence/${feature_id}-smoke.*"
            echo "  Create manually, or run: ag auto verify --visual --feature $feature_id"
            exit 1
        fi
    else
        echo -e "${YELLOW}⚠ No smoke test evidence for $feature_id${NC}"
        echo "  Tip: Create .agentic/journal/evidence/${feature_id}-smoke.md manually"
        echo "  Or run: ag auto verify --visual --feature $feature_id (requires E2E screenshots config)"
    fi
    echo ""
fi
```

## Profile Defaults

| Profile | Value | Rationale |
|---------|-------|-----------|
| discovery | `off` | No barriers in exploratory mode |
| formal | `recommended` | Encourages evidence without blocking |
| autonomous_formal | `recommended` | Same default — teams can escalate to `required` |

## verify.py Evidence Auto-Save

- New `--feature F-XXXX` CLI argument (optional)
- When both `--feature` and `--visual` are set, saves structured markdown to `.agentic/journal/evidence/F-XXXX-smoke.md`
- When `--feature` is passed WITHOUT `--visual`, print warning to stderr: "Warning: --feature requires --visual to generate evidence. No evidence saved."
- Content: timestamp, test pass/fail counts, visual review summary, concerns list
- Uses `paths.py` `evidence_dir` for path resolution

## paths.py Fallback

Evidence dir follows the same `_resolve` pattern as all other journal subdirectories:

## Edge Cases Handled

- No feature_id → gate skipped (correct for discovery)
- Evidence dir doesn't exist → `mkdir -p` before glob
- Multiple evidence files → first match suffices
- `--feature` without `--visual` → warning printed to stderr, no evidence saved
- Older projects without the setting → falls through to profile default (safe)
- Gate tip mentions both manual creation and `--visual` (not all projects have screenshot config)
- Invalid `ag set` value → validator rejects with clear error message
