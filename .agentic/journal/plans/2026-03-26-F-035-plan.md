**Status**: APPROVED

## Title
F-035: Protected Main Branch Support

## Context
`ag flush` and `ag done` assume direct push access to main. In organizations with GitHub branch protection (required reviews, status checks, no direct pushes), these commands fail. The framework needs an alternative path that creates ephemeral branches and auto-creates PRs for state-only changes.

## Scope

**In scope:**
- New `main_branch_mode` setting (`direct` | `protected`)
- Protected-mode path in `state-commit.sh` (branch + PR instead of direct push)
- VERSION bump routing in `done.sh` for protected mode
- Graceful fallback when `gh` unavailable
- Stale ephemeral branch cleanup
- Instruction file updates (CLAUDE.md template, memory-seed, DEVELOPER_GUIDE, HOW_IT_WORKS)
- Structural tests

**Out of scope (v2):**
- `auto` detection mode via GitHub API (deferred — adds disproportionate complexity, requires admin access, unreliable for collaborators)
- Auto-merge configuration (documentation pointer only)
- Functional integration tests (require git remote)

## Approach

### Phase 1: Setting Infrastructure (~10 lines)

**`.agentic/lib/presets/profiles.conf`** — Add `main_branch_mode=direct` to all three profiles (discovery, formal, autonomous_formal). Default `direct` = zero-impact upgrade.

**`.agentic/lib/tools/commands/settings.sh`** — Add validation case:
```bash
main_branch_mode)
    if [[ ! "$value" =~ ^(direct|protected)$ ]]; then
        echo "Error: must be 'direct' or 'protected'"
        exit 1
    fi
    ;;
```

**`.agentic/lib/settings.sh`** — Add `main_branch_mode` to `show_all_settings()`.

### Phase 2: Protected Mode in state-commit.sh (Core Change, ~100 lines)

**Design principle**: `state-commit.sh` is the single chokepoint for all state-file commits. All callers (`ag flush`, `_try_flush()` in todo.sh/feedback.sh, `ag done` flush) go through it.

**Source settings.sh** (required for `get_setting` — state-commit.sh currently only sources `paths.sh`):
```bash
source "$SCRIPT_DIR/../settings.sh"
```

**New function `_get_branch_mode()`** (simple, no API):
```bash
_get_branch_mode() {
    local mode
    mode=$(get_setting "main_branch_mode" "direct")
    echo "$mode"
}
```

**Modified flow**: After step 9 (multi-agent advisory), branch on mode:

**Direct mode** (current steps 10-12, unchanged): stage → commit → rebase → push.

**Protected mode** (new steps 10p-16p):
```
10p. Stage dirty files (same as current)
11p. Build commit message (same as current)
12p. Create ephemeral branch: state/flush-$(date +%Y%m%d-%H%M%S)-$$
     git checkout -b "$EPHEMERAL_BRANCH"
13p. Commit on ephemeral branch (same --no-verify, same justification)
14p. Push ephemeral branch to origin
     git push -u origin "$EPHEMERAL_BRANCH"
15p. Create PR via gh (if available):
     gh pr create --base "$BRANCH" --head "$EPHEMERAL_BRANCH" \
       --title "$COMMIT_MSG" --body "Auto-generated state-only flush.\n\nFiles:\n$FILE_LIST"
     Attempt: gh pr merge --auto --squash --delete-branch (best-effort)
16p. Return to trunk: git checkout "$BRANCH"
17p. Clean up local state (CRITICAL — see below)
```

**Solving the dirty-state-after-checkout problem (Critic C1)**:

After checking out main at step 16p, the state files reappear as dirty because main still has old versions. Two scenarios:

- **If auto-merge succeeded** (rare — requires repo to have auto-merge + passing checks): `git pull --rebase origin "$BRANCH"` to get the merged changes. Files are now clean.
- **If PR is pending** (common): Reset the dirty files to main's version: `git checkout "$BRANCH" -- "${DIRTY_STATE[@]}"`. This discards the local modifications that are now captured in the PR. Print message: "State PR created — local state will update when PR merges and you run `git pull`."

This is safe because the modifications are preserved in the PR branch. The user's local state temporarily reverts to pre-flush, which is better than:
- Leaving them dirty (causes duplicate PRs from `_try_flush`)
- Leaving the user confused about why files are still dirty after flushing

**Error recovery** (addresses Critic M1, refined per Critic N1):

The protected path uses a function with an ERR trap that is **explicitly cleared** before returning. This prevents the trap from leaking into the calling scope (bash functions don't scope traps — only subshells do):
```bash
_cleanup_ephemeral() {
    git checkout "$BRANCH" 2>/dev/null || true
    git branch -D "$EPHEMERAL_BRANCH" 2>/dev/null || true
    git reset HEAD -- "${DIRTY_STATE[@]}" 2>/dev/null || true
}

_do_protected_flush() {
    trap '_cleanup_ephemeral; exit 1' ERR

    git checkout -b "$EPHEMERAL_BRANCH"
    git commit --no-verify -m "$COMMIT_MSG"
    git push -u origin "$EPHEMERAL_BRANCH"
    # ... PR creation, auto-merge attempt ...
    git checkout "$BRANCH"
    # Reset dirty files to main's version
    for f in "${DIRTY_STATE[@]}"; do
        git checkout "$BRANCH" -- "$f" 2>/dev/null || git rm -f "$f" 2>/dev/null || true
    done

    # CRITICAL: Clear ERR trap before returning — bash functions don't scope traps
    trap - ERR
}

_do_protected_flush
```

Note: the file reset loop uses `git checkout "$BRANCH" -- "$f"` for modified files, with `git rm -f` fallback for newly-created files that don't exist on main (addresses Critic N2).

**Fallback chain**:
- `gh` not available → push branch, print manual PR instructions with URL
- Push fails → `cleanup_ephemeral`, warn user, exit 1
- `gh pr create` fails → branch already pushed, print "create PR manually at: <remote-url>"

**Branch name uniqueness** (addresses Critic M3): `state/flush-$(date +%Y%m%d-%H%M%S)-$$` includes PID to prevent same-second collisions.

### Phase 3: `_try_flush()` Behavior in Protected Mode

**Decision**: `_try_flush()` callers (todo.sh, feedback.sh) should **skip** protected mode. Creating a PR from `ag todo` is surprising and noisy.

**Implementation** (addresses Critic N3 — `[ -t 1 ]` heuristic is unreliable because `_try_flush()` stdout is still a terminal):

Add explicit `--auto-flush` flag to `state-commit.sh`:
```bash
# In flag parsing section:
AUTO_FLUSH=false
for arg in "$@"; do
    case "$arg" in
        --auto-flush) AUTO_FLUSH=true ;;
        # ... existing flags ...
    esac
done

# After resolving branch mode, before step 10:
if [[ "$BRANCH_MODE" == "protected" ]] && $AUTO_FLUSH; then
    echo "Protected mode: skipping auto-flush (use 'ag flush' explicitly)" >&2
    exit 0
fi
```

Then update `_try_flush()` callers in todo.sh and feedback.sh to pass `--auto-flush`:
```bash
bash "$SCRIPT_DIR/state-commit.sh" --auto-flush 2>/dev/null || true
```

This is explicit, self-documenting, and works regardless of terminal state or piping context.

### Phase 4: VERSION Bump Routing in done.sh (~15 lines)

**The problem** (Critic C2): `done.sh` at line 851 calls `state-commit.sh --features`. In protected mode, this creates a PR. But `dogfood-sync.sh` at line 860 runs *after* flush and may produce additional changes needing a second PR.

**Solution**: Reorder in done.sh — run dogfood-sync *before* the flush call:
```bash
# 1. VERSION bump (writes to disk, same as current)
# 2. Dogfood sync (framework-dev only, produces changes)
# 3. Flush ALL state files in one call (captures VERSION + dogfood changes)
```

This ensures a single flush (and single PR in protected mode) captures everything. In direct mode, behavior is identical — the flush pushes all dirty state files regardless of when they were modified.

**Additional done.sh change**: After the flush call in protected mode, print guidance:
```bash
if [[ "$(_get_branch_mode)" == "protected" ]]; then
    echo "  Note: State changes sent as PR. Merge it to complete the version bump."
fi
```

### Phase 5: Stale Branch Cleanup (~10 lines)

**In state-commit.sh**, clean up merged `state/flush-*` branches using locally-known remote refs (no fetch — addresses Critic N4 about `git fetch --prune` latency):
```bash
# Clean up merged state/flush branches (best-effort, no network call)
for ref in $(git branch -r --merged "origin/$BRANCH" 2>/dev/null | grep 'origin/state/flush-' || true); do
    remote_branch="${ref#origin/}"
    git push origin --delete "$remote_branch" 2>/dev/null || true
done
```

This uses already-fetched remote tracking refs — no `git fetch --prune` needed. Stale refs get cleaned up naturally when the user does `git fetch` or `git pull`. Best-effort — failures don't block the flush.

## Acceptance Criteria

- **AC-001**: `ag flush` creates `state/flush-{timestamp}-{pid}` branch when `main_branch_mode: protected`
- **AC-002**: PR auto-created with title `chore(state): update <filenames>` when `gh` available
- **AC-003**: `ag done` VERSION bump + dogfood-sync changes included in single state PR when protected
- **AC-004**: Graceful fallback when `gh` unavailable (branch pushed, manual PR instructions printed)
- **AC-005**: state-commit.sh allowlist enforcement unchanged (same files, same validation)
- **AC-006**: `ag flush --dry-run` and `--check` work identically in both modes
- **AC-007**: Default is `direct` for all profiles (zero-impact upgrade)
- **AC-008**: `ag set main_branch_mode protected` validates input correctly
- **AC-009**: `_try_flush()` callers skip protected mode (no surprise PRs from `ag todo`)
- **AC-010**: Local state files reset to main's version after PR creation (no duplicate flushes)
- **AC-011**: Error recovery cleans up ephemeral branch on failure (user not stranded)
- **AC-012**: Merged `state/flush-*` branches cleaned up on next flush

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `gh` not installed/authenticated | Can't create PR | Fallback: push branch, print manual PR instructions |
| Two agents flush simultaneously | Two PRs with conflicting state | Unique timestamps + PID; second PR shows merge conflict (better than push rejection) |
| Stale `state/flush-*` branches | Branch accumulation | Auto-cleanup of merged branches before each flush |
| User edits state files between PR creation and merge | Local changes lost on next pull | Print clear warning; state files are machine-managed, manual edits rare |
| `set -euo pipefail` error mid-ephemeral-branch | User stranded on wrong branch | ERR trap calls `cleanup_ephemeral()` to restore main |
| Dogfood-sync after flush (done.sh) | Two PRs instead of one | Reorder: dogfood-sync before flush |
