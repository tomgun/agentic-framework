# F-0242: Simulation Testing (Phase + Sequence)

**Status**: APPROVED

## Context

Current LLM tests (`tests/llm/`) use `claude --print` — single-shot, no tools. They're knowledge quizzes: the agent reads CLAUDE.md and says the right thing. This proves nothing about actual behavior under real execution (context compression, tool friction, multi-turn drift, step-skipping).

F-0242 adds **behavioral verification** to the existing scenario runner (`framework_verify.py`), which already spawns real agents with full tool access for minutes. The gap: the runner checks end-state (files exist, tests pass) but not **intermediate workflow compliance** (was plan created before code? did review happen before implementation?).

## What This PR Delivers

1. **PhaseChecker** — parses `framework.log` to verify intermediate workflow phases occurred with expected artifacts
2. **violations.yaml** — migrates 3 hard-coded violation detectors to YAML-declared metadata with Python handler dispatch
3. **Scenario YAML extensions** — `phase_expectations` key for intermediate state verification

**Descoped (follow-up):** `tool_call_expectations` / JSONL SequenceChecker — blocked because `log_file` in `run_scenario()` is plain-text stdout, not JSONL. Claude Code stores JSONL in `~/.claude/projects/<hash>/`, inaccessible to the scenario runner. The existing `_wf_spec_before_code` workflow check (git commit ordering) covers this need until JSONL access is solved.

## Dependency: F-0240

F-0240 (framework.log) is implemented: `fwlog.sh` exists, `ag.sh` sources it with start/EXIT trap, pre-commit sources it, Claude hooks call `flog()`, paths defined in `paths.sh`/`paths.py`. PhaseChecker can use framework.log directly.

### Step 2: Create violations.yaml
**Create** `.agentic/lib/auto/violations.yaml`

YAML holds **metadata and configuration** for each violation pattern. Detection logic stays in Python as named handler functions. This is explicitly NOT a DSL — it's a declarative catalog.

```yaml
violations:
  - name: stopped_after_plan_exit
    description: "Agent stopped after ExitPlanMode instead of auto-continuing to review"
    handler: _detect_stopped_after_plan_exit
    config:
      trigger_tool: ExitPlanMode
      expect_tool_within: 3  # tool calls
      expect_tool: Agent

  - name: code_before_review
    description: "Writing code before plan APPROVED"
    handler: _detect_code_before_review
    config:
      trigger_tools: [Write, Edit, MultiEdit]
      group_by: draft_phase
      max_files_reported: 20
      allowlist_prefixes:
        - "spec/"
        - "tests/"
        - "test/"
        - "journal/"
        - ".agentic/session/"
        - "memory/"
      allowlist_substrings:
        - "backlog.json"
        - "features.md"
        - "issues.md"
        - "changelog"
        - "stack.md"
        - "overview.md"
        - ".claude/plans/"
        - ".cursor/plans/"
      allowlist_suffixes:
        - "-plan.md"

  - name: skipped_planning
    description: "ag implement called without prior plan mode entry"
    handler: _detect_skipped_planning
    config:
      trigger_tool: Bash
      command_patterns: ["ag implement", "ag.sh implement"]
      precondition_absent: EnterPlanMode
```

```python
class PhaseChecker:
    """Check intermediate workflow phases via framework.log.

    Parses framework.log (pipe-delimited: TIMESTAMP|SCRIPT|VERB|ARGS|RESULT)
    and checks that expected phases occurred, optionally verifying filesystem
    state at each detected phase.

    Matching semantics: "at some point, this phase was attempted."
    Matches on 'start' entries by default. A phase that was attempted but
    failed (end:1) still counts as "phase occurred" — the failure is
    separately detectable via the result field.
    """

    def __init__(self, project_root: Path):
        self.root = project_root
        self.log_path = project_root / ".agentic" / "session" / "framework.log"
        self._entries = None

    def _parse_log(self) -> list[dict]:
        """Parse framework.log into structured entries.
        Returns empty list if file missing or empty.
        Handles entries with empty fields gracefully."""
        # TIMESTAMP|SCRIPT|VERB|ARGS|RESULT → split('|', maxsplit=4)

    def _find_phase(self, detect_via: dict, require_result: str | None = None) -> dict | None:
        """Find a log entry matching the detection criteria.
        detect_via.framework_log format: "script|verb" (matched as substrings).
        If require_result is set, only match entries with that result (e.g. "ok")."""

    def check_all(self, phase_expectations: list[dict]) -> list[MilestoneResult]:
        """Check all phase expectations. Returns one MilestoneResult per phase.
        Missing phases produce failing results with descriptive detail."""

    def _check_state(self, state: dict) -> tuple[bool, str]:
        """Verify filesystem state conditions.
        - files_exist: glob patterns (at least one match required per pattern)
        - file_contains: list of {path, pattern} dicts (regex match)"""
```

## What This Proves (vs. the old LLM tests)

The old tests asked "do you know you should plan before coding?" and checked the text response.

With F-0242, when `ag auto verify-framework --project todo-app` runs the autonomous_formal matrix:
- A real agent gets a vision prompt and runs for up to 2 hours with full tool access
- **PhaseChecker** verifies: after `ag kickoff`, FEATURES.md has F-XXXX entries; after `ag implement`, acceptance criteria files exist
- Existing workflow expectations verify: plan exists and is APPROVED, AC files are fully checked, features have shipped status

If the agent skips planning, context-compresses away the review loop, or writes code before specs — these checks **fail on artifacts**, not on what the agent said.
