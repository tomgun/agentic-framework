# Stack-Specific Quality Assurance System
**Status**: APPROVED
**Feature**: F-008

## Context

The framework had ~17K lines of project-type-specific quality knowledge (quality guidelines, workflow docs, shared guidelines) that were deleted during v2 refactoring (commits `cfc7d667` and `d24ab3d5`, March 2026). The commit messages said "content absorbed into conventions.md and v2 role prompts" — but in reality, `conventions.md` absorbed only ~83 lines of generic standards. The deep domain knowledge (stack-specific failure modes, testing strategies per project type, library selection heuristics, compliance checks for audio plugins, game-specific anti-patterns) was lost.

What survives: 6 quality profile shell scripts in `.agentic/lib/quality_profiles/` (886 total lines), referenced by `init_playbook.md`, `doctor.py`, `DEVELOPER_GUIDE.md`, and `STACK.md` template — but **nothing generates, invokes, or enforces them**. They're completely disconnected from the hook/gate/CLI pipeline.

**Goal**: Rebuild stack-specific quality assurance that (a) recaptures the lost domain knowledge, (b) auto-generates at init based on detected stack, (c) is structurally enforced via the existing hook/gate pipeline, and (d) works across all AI tools (Claude, Cursor, Copilot, Codex).

## Architecture: Three Layers

### Layer 1 — Quality Knowledge Base (`.agentic/lib/quality_knowledge/`)

**Hybrid format**: YAML for machine-actionable data + markdown companion for deep knowledge.

```
.agentic/lib/quality_knowledge/
  _schema.yaml                     # Schema definition + docs
  web_fullstack.yaml               # Next.js, Nuxt, Remix, SvelteKit
  web_fullstack.knowledge.md       # Deep guidance: SSR patterns, hydration, library selection
  backend_python.yaml              # Django, FastAPI, Flask
  backend_python.knowledge.md      # ORM patterns, async pitfalls, deployment
  backend_node.yaml                # Express, Fastify, Hono
  backend_node.knowledge.md        # Event loop, memory leaks, streaming
  mobile_react_native.yaml         # React Native, Expo
  mobile_react_native.knowledge.md # Native modules, performance, app store
  audio_dsp.yaml                   # JUCE, VST3, AU, AUv3
  audio_dsp.knowledge.md           # Real-time safety, DSP validation, pluginval
  game_2d_web.yaml                 # Phaser, PixiJS
  game_2d_web.knowledge.md         # Frame independence, physics, asset loading
  game_unity.yaml                  # Unity C#
  game_unity.knowledge.md          # MonoBehaviour, asset pipeline, build targets
```

**YAML structure** (machine-actionable parts):

```yaml

  languages: [C++]

  markers: [pluginval, "juce_audio_processors"]

failure_modes:
  - id: FM-001
    name: "NaN/Inf in audio output"
    severity: blocking
    check: "python3 scripts/test_dsp_validation.py --check-nan-inf"
  - id: FM-002
    name: "CPU overload in processBlock"
    severity: warning  # full mode only
    check: "python3 scripts/test_realtime_performance.py --max-cpu-percent 50"

quality_checks:
  pre_commit:  # Fast checks (<30s)
    - name: "Build"
      command: "cmake --build build --config Release"
      required: true
    - name: "Unit tests"
      command: "ctest --test-dir build --output-on-failure"
      required: true
    - name: "Pluginval (smoke)"
      command: "pluginval --validate {plugin_path} --strictness-level 3"
      required: false  # may not be installed
  full:  # Comprehensive checks
    - name: "Pluginval (strict)"
      command: "pluginval --validate {plugin_path} --strictness-level 8"
      required: true
    - name: "DSP validation"
      command: "python3 scripts/test_dsp_validation.py"
      required: false
    - name: "Realtime performance"
      command: "python3 scripts/test_realtime_performance.py --duration 60"
      required: false

testing_strategy:
  unit: { framework: "GoogleTest or Catch2", focus: "DSP algorithms, parameter mapping" }
  integration: { framework: "pluginval", focus: "Host compatibility, state save/restore" }
  e2e: { framework: "Playwright (UI) + DSP scripts", focus: "Full signal chain, automation" }

conventions:
  - "Never allocate memory in processBlock — all buffers pre-allocated in prepareToPlay"
  - "Use juce::dsp:: processors over raw pointer arithmetic"
  - "Parameter smoothing on all user-facing controls to prevent zipper noise"
```

**Why hybrid**: YAML is what generators parse to produce `quality_checks.sh`. Markdown is what agents read for domain expertise during implementation. Neither format does both jobs well. The downside is ~2 files per stack instead of 1, but since we're recapturing thousands of lines of domain knowledge, the readable companion is essential.

### Layer 2 — Quality Profile Generator

**New file**: `.agentic/lib/tools/generate-quality-profile.sh`
**New file**: `.agentic/lib/tools/quality_profile_generator.py`

Takes detected stack info (from `discover.py` output or STACK.md) and produces three outputs:

| Output | Location | Purpose |
|--------|----------|---------|
| `quality_checks.sh` | Project root | Stack-specific checks (`--pre-commit` and `--full` modes) |
| `conventions-stack.md` | `.agentic/local/` | Stack conventions loaded by agents alongside `conventions.md` |
| `quality-gate.sh` | `.agentic/local/extensions/gates/` | Thin wrapper calling `quality_checks.sh`, wires into Check 17 of pre-commit |

**Multi-stack handling**: Projects matching multiple knowledge files (e.g., React frontend + Python backend) get a composite `quality_checks.sh` with sections per stack, and a merged `conventions-stack.md` with clear headers.

**Invocation points**:
1. `scaffold.sh` — after `discover.sh` completes during `ag init`
2. `upgrade.sh` — regenerates if framework knowledge files updated
3. `ag quality setup` — manual trigger (new subcommand)

### Layer 3 — Enforcement Wiring

**All enforcement uses existing mechanisms — no new hook types or gate infrastructure.**

| Integration Point | Mechanism | Change Required |
|---|---|---|
| Pre-commit (Check 17) | Generated `extensions/gates/quality-gate.sh` | None — existing extension system |
| `ag commit` | Call `quality_checks.sh --pre-commit` after doctor.sh | ~10 lines in `commit.sh` |
| `ag verify` | Call `quality_checks.sh --full` | New gate in `gate.py` |
| `ag implement` | Include stack conventions in `.impl-brief.md` | ~5 lines in `implement.sh` |
| `doctor.py` | Suggest `ag quality setup` when stack detected but no `quality_checks.sh` | Update existing `validate_quality_setup()` |
| Init playbook | Fix broken references, document auto-generation | Update `init_playbook.md` |
| PostToolUse | One-time nudge: "Stack conventions available" on first code edit | ~8 lines in PostToolUse.sh |

**Default enforcement**: `quality_checks: blocking` in STACK.md settings. During init, user is asked to confirm. Setting controls whether Check 17 gate and `ag commit` integration block or warn.

## Key Design Decisions

1. **Hybrid YAML+markdown over pure YAML or pure markdown** — generators need structure, agents need prose. Two files per stack is acceptable overhead for the amount of domain knowledge being recaptured.

2. **Blocking by default, setting-controlled** — `quality_checks: blocking` is the default in STACK.md. Init asks user to confirm. No profile-based logic — just a setting.

3. **Extensions/gates for pre-commit wiring** — uses existing Check 17 mechanism in `pre-commit-check.sh`. Zero changes to pre-commit infrastructure.

4. **Keep existing quality_profiles/*.sh** — they're working reference implementations. The new system supersedes them for generation but doesn't delete them.

5. **Generator in Python** — consistent with `discover.py`, `gate.py`, `doctor.py`. Parses YAML, produces bash. Shell wrapper for `ag quality` CLI.

6. **`.agentic/local/` for generated artifacts** — survives framework upgrades. User can customize thresholds. Extensions/gates mechanism already wired.

7. **Multi-stack compositing** — generator detects all matching knowledge files and produces a composite `quality_checks.sh` with sections. Handles React+Python, Unity+backend, etc.

## Dialectical Review (2026-04-10)

### Critic verdict: REVISE | Advocate verdict: PROCEED

### Revisions Applied (from Critic feedback)

**C1 (Scope)**: Kept as single F-008 but with explicit commit milestones. Steps 1-3 are the shippable core (generator + enforcement + 1 stack proof of concept). Steps 4-5 are content expansion. Each step is a separate commit.

**C2 (PyYAML dependency)**: Added graceful fallback — if PyYAML is not available, the generator falls back to copying the best-matching existing `quality_profiles/*.sh` script directly (no YAML parsing). This is already how the framework handles PyYAML elsewhere (`doctor.py` has `HAS_YAML` guard).

**C3 (Discover-to-generator interface)**: Generator reads STACK.md directly (the `## Tech Stack` section that `discover.py` populates). The `match_knowledge_files()` function parses STACK.md for framework/language fields and matches against YAML `matches` section. No intermediate JSON format — STACK.md IS the contract.

**W1 (Pre-commit timeout)**: Generated `quality-gate.sh` wraps `quality_checks.sh` call in `timeout 60` (configurable via STACK.md `quality_checks_timeout` setting, default 60s). Prevents indefinite blocking.

**W3 (Backward compatibility)**: If `quality_checks.sh` already exists at project root:
- `ag quality setup` warns and writes to `quality_checks.sh.generated` instead
- `scaffold.sh` (during init) only generates if no existing `quality_checks.sh`
- `upgrade.sh` never overwrites existing `quality_checks.sh`

**W4 (ag verify scope)**: `check_quality_profile()` is a project-wide gate, not feature-scoped. Placed in `gate_stop()` (formal only) and available via standalone `ag quality run`, NOT embedded in `gate_verify()` which is feature-scoped.

**S3 (Dry-run)**: Added `ag quality setup --dry-run` that shows what would be generated without writing.

**S4 (ag quality run vs ag verify)**: `ag quality run` = direct execution of quality_checks.sh (user-facing). `ag verify` = feature contract verification (includes quality as one gate among many). Different purposes, kept separate.
