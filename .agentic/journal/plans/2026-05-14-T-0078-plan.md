# T-0078 — `ag done` verification subprocess leaks sourced env into `bash -c`

**Status**: APPROVED
**Owning feature**: F-003 (Feature Tracking & Lifecycle, shipped) — hardening, not a new capability. No F-XXXX promotion (no-feature-inflation rule).

## Problem

`.agentic/lib/paths.sh:36-42` prefers `${ROOT_DIR:-}` over its own resolution. `paths.sh:162-163` exports `ROOT_DIR`, `PROJECT_ROOT`, `MAIN_PROJECT_ROOT`, `AGENTIC_ROOT`, `AGENTIC_LIB`, `AGENTS_JSON`. Any subprocess `ag` spawns inherits them. When that subprocess is a framework-aware script that sources `paths.sh`, the inherited `ROOT_DIR` wins, so a sandboxed verify command ends up running against the caller's project root → phantom passes/failures (5 in the current reproducer).

## Leak points (both reached via `ag done`'s verification step)

1. **`.agentic/lib/tools/commands/operations.sh:546`** — legacy-markdown branch of `cmd_verify`:
   ```bash
   _verify_output=$(bash -c "$cmd" 2>&1)
   ```
   No env scrubbing. The `bash -c` inherits all six exported agentic vars.

2. **`.agentic/lib/contracts.py:513-516`** — `verify_assertion`:
   ```python
   env = {"PROJECT": str(project_root), "PROJECT_ROOT": str(project_root)}
   full_env = {**os.environ, **env}
   subprocess.run(..., env=full_env)
   ```
   Correctly overrides `PROJECT_ROOT`, but `ROOT_DIR` (and siblings) still ride through `os.environ` to the assertion's `shell=True` subprocess.

## Fix

### 1. `operations.sh:546` — env-scrub the bash subprocess

```bash
_verify_output=$(env -u ROOT_DIR -u PROJECT_ROOT -u MAIN_PROJECT_ROOT \
                     -u AGENTIC_ROOT -u AGENTIC_LIB -u AGENTS_JSON \
                     -u FRAMEWORK_ROOT \
                     bash -c "$cmd" 2>&1)
```

Strips all six exported agentic vars plus a defensive `FRAMEWORK_ROOT`. CWD is correct (test harness `cd`s into the sandbox), so verify commands resolve project root from `pwd` rather than a leaked env var.

### 2. `contracts.py:514` — filter os.environ before merging override

```python
_LEAK_VARS = ("ROOT_DIR", "MAIN_PROJECT_ROOT", "AGENTIC_ROOT",
              "AGENTIC_LIB", "AGENTS_JSON", "FRAMEWORK_ROOT")
base_env = {k: v for k, v in os.environ.items() if k not in _LEAK_VARS}
env_overrides = {"PROJECT": str(project_root), "PROJECT_ROOT": str(project_root)}
full_env = {**base_env, **env_overrides}
```

`PROJECT_ROOT` is explicitly re-injected with the assertion's sandbox root, so it's NOT in the filter list. The remaining six are scrubbed.

## Notable non-fix (and follow-up)

Don't strip env around the `bash "$SCRIPT_DIR/verify-contracts.sh"` call at `operations.sh:511` — that script sources `paths.sh` and relies on `ROOT_DIR` being a meaningful override for cross-checkout invocations (parent ag explicitly setting `ROOT_DIR=$TEST_DIR` to point the framework at a sandbox). Stripping there would break legitimate use.

**Critic raised a related concern**: `verify-contracts.sh:66` substitutes `$ROOT_DIR` into the Python heredoc as `project_root`. If the parent ag was itself booted with a wrong `ROOT_DIR` (e.g., inherited from an outer shell rather than self-resolved), the YAML-contract path would still verify against the wrong root even after the fix. **Filing as follow-up TODO** rather than expanding scope here — it's a different failure mode (parent-boot poisoning) with broader ripple effects across `paths.sh` precedence rules. The two-point fix closes the documented 5 phantom failures; the follow-up addresses the parent-boot case if reproducible.

## Scoping decisions (recorded)

- **Strip `PROJECT_ROOT` at `operations.sh:546` but NOT at `contracts.py:514`** — asymmetry is intentional. `contracts.py` re-injects `PROJECT_ROOT=str(project_root)` from the explicit `project_root` argument (the assertion's sandbox root). The legacy-markdown branch has no such override path; stripping `PROJECT_ROOT` forces verify commands to use `pwd`, which is correct.
- **`FRAMEWORK_ROOT` defensive strip** — verified `grep` shows it's never exported in `.agentic/lib/`, only a local var in test scripts. Cost: one `-u` flag and one tuple entry. Benefit: forward defense against future leakage. Matches the task description.
- **No instruction-file updates** — this is a bug fix on shipped F-003, not a new command/gate/workflow. The framework-dev "instruction files are part of the feature" rule doesn't fire.

## Out of scope (explicit non-goals)

- **`ag auto verify` (`.agentic/lib/auto/framework_verify.py`)** — has ~30 `subprocess.run` sites, separate verification surface. The 5 phantom failures are in `ag done`'s `cmd_verify`, not `ag auto verify`. If similar leaks exist there, a follow-up task targets that path specifically.
- **Refactoring `paths.sh:36-42` precedence** — public-ish surface, many callers rely on `ROOT_DIR` override semantics (R-209 baseline-integrity territory).
- **Renaming `ROOT_DIR` to a less collision-prone name** — breaking change.
- **HMAC/signing of paths state** — different threat model (tamper, not leak).
- **Removing `ROOT_DIR` export from `paths.sh:163`** — many subprocesses legitimately need it.
