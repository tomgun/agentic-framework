# Plan: Configurable Definition of Done per Task Type

**Status**: APPROVED
**Feature**: F-0210 (improvement to F-002)
**Date**: 2026-03-29
**Review**: Dialectical review completed 2026-03-29. Critic+Advocate converged. Revisions incorporated.

## Context

The framework currently enforces one implicit DoD ("spec + code + tests + docs = done") uniformly across all features. This is hardcoded in `done.sh` (lines 717-732), `feature-complete.sh` (6 checks), and `gates.py` (8 gates). A spike/research feature goes through identical gates as a production capability — blocking on tests that don't apply.

This improvement (to F-002) makes DoD explicit, configurable, and task-type-aware. Users define which checks apply per task type. Default "implementation" type preserves exact current behavior.

## Design Decisions

**D1: DoD definitions live in `.agentic/lib/presets/dod.conf`** — follows `profiles.conf`/`constraints.conf` convention. Structured config, LLM-readable, not STACK.md (which is scalar key-value only).

**D2: Task type resolution cascade** — explicit `--type` flag > contract `task_type` field > FEATURES.md Type field (with alias mapping) > default "implementation". Alias mapping: `research` → `spike`, `capability` → `implementation`, `meta` → `implementation`. Unknown types fall through to `implementation`.

**D3: Gates skip via internal type check** — gate functions call `_resolve_feature_type()` internally (follows `_read_feature_component()` pattern) and return `GateResult.ok()` with advisory when skipped. No GateFunc signature change. Uses module-level cache to avoid redundant I/O.

**D4: Four default types** — `implementation` (full DoD, default), `spike` (skip test gates + docs gate), `bugfix` (full, docs advisory), `docs` (skip test + smoke gates). Dropped `infrastructure` (identical to `implementation` — no value).

## Backward Compatibility

- All existing features resolve to "implementation" type (no task_type set anywhere)
- "implementation" type = all checks `required` = identical to current behavior
- `dod.py` failure → falls back to current hardcoded checklist in done.sh
- Contract schema change is additive (optional field with default None)
- FEATURES.md `Type: research` → aliases to `spike` (new behavior — intentional improvement, not regression)
- FEATURES.md `Type: infrastructure`/`capability`/`meta` → aliases to `implementation` (no behavior change)
- Unknown types → `implementation` with advisory warning
