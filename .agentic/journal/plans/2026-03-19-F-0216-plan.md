# Plan: F-0216 — NFR Auto-Generation at Lifecycle Moments

**Status**: APPROVED
**Feature**: F-0216
**Date**: 2026-03-19

## Context

`ag nfr discover` currently dumps ALL matching catalog entries (8-20+) with agent instructions to manually assign IDs and write to NFR.md. No batch write tool exists. No integration with `ag kickoff`. The user experience is passive — too many choices, no tooling to write them, no lifecycle integration.

Most ACs are already satisfied by existing infrastructure. The remaining 5 ACs need targeted changes to 2 existing scripts + 1 new script.

## Gap Analysis

**Already satisfied (no changes):** AC-001 through AC-004 (generation tool), AC-010 through AC-012 (catalog expansion), AC-013-014 (component scoping).

**Needs implementation:**
- **AC-005**: Present 4-8 pre-selected (not all) recommendations
- **AC-006**: Batch write selected NFRs to NFR.md with collision-free IDs
- **AC-007**: Merge with existing NFRs (append, don't overwrite)
- **AC-008**: `cmd_kickoff` calls `nfr-generate.sh` at ag.sh layer
- **AC-009**: NFR suggestions appear in kickoff staging area

## Implementation

### 1. nfr-generate.sh — Add `--limit` and `--machine` flags

**File**: `.agentic/lib/tools/nfr-generate.sh` (~35 lines changed)

Add two new flags to argument parsing:
- `--limit N`: Cap output at N entries post-filter. Applied after priority/component filtering so users always get the top N most relevant entries, not the first N catalog rows.
- `--machine`: Output one pipe-delimited line per entry (`ID|category|statement|measure|enforced|priority|section`), no header, no footer, no ANSI codes. Essential for piping to `nfr-write-batch.sh`.

**Selection heuristic for `--limit` (revised — no awk sorting):**
Instead of sorting with awk, reorder `map_type_to_sections()` output: type-specific sections FIRST, then "Universal", then "Framework Promises". Since catalog tables already list P1 entries before P2, the natural iteration order matches desired priority. `--limit` is a simple counter in the output loop: `[[ $count -ge $LIMIT ]] && break`. No awk, no sort, fully portable.

**`--machine` implementation:** Guard the header block (lines 198-200), the formatted output loop (lines 220-232), and the footer (lines 234-235) with conditionals. In machine mode, the output loop emits raw pipe-delimited lines instead of formatted blocks.

**`--help` text updated** to document both new flags.

Without these flags, behavior is unchanged (backward compatible).

### 2. nfr-write-batch.sh — New batch writer (~110 lines)

**File**: `.agentic/lib/tools/nfr-write-batch.sh` (CREATE)

Accepts pipe-delimited entries from stdin (one per line, same format as `nfr-generate.sh --machine`).

**Atomic reads:** Read ALL stdin into a variable first, validate line count > 0, then write. Prevents partial writes on pipe errors.

Flow:
1. Read all stdin into variable; exit 1 if empty
2. Multi-agent safety check (reuse `agents_helpers.py count-others` pattern from `nfr-capture.sh:51-59`)
3. Create NFR.md from template if doesn't exist (reuse pattern from `nfr-capture.sh:66-77`)
4. Find max NFR-XXXX ID in existing NFR.md (reuse `nfr-capture.sh:62-65`)
5. Append each entry with incrementing IDs, standard NFR.md format
6. Print summary of written NFRs

**Field mapping (catalog → NFR.md template — matches nfr-capture.sh format exactly):**
- `statement` → `## NFR-XXXX: {statement}` + `- Statement: {statement}`
- `category` → `- Category: {category}`
- `section` → `- Applies to: {section} projects`
- `measure` → `- How to measure: {measure}`
- `enforced` → `- Where enforced:` with sub-items parsed (case-insensitive grep):
  - If contains "tests" (case-insensitive) → `  - Tests: yes`; else `  - Tests: none`
  - If contains "ci" (case-insensitive) → `  - CI: yes`; else `  - CI: none`
- Fixed: `- Current status: proposed` and `- Notes: Auto-generated from NFR catalog ({catalog_id}, {priority})`
- **No `Priority:` field** — matches nfr-capture.sh format; catalog priority stored in Notes for traceability

Usage: `nfr-generate.sh --machine --limit 8 | nfr-write-batch.sh`
