# F-0205: Discovery-to-Formal Migration (`ag formalize`) — Implementation Plan

**Status**: APPROVED
**Date**: 2026-03-13
**Revised**: 2026-03-13 (post-dialectical review)

## Context

Projects in discovery mode accumulate ideas in TODO.md (T-XXXX items), decisions in JOURNAL.md, and plans in `.agentic/journal/plans/`. When a project matures, there's no automated way to promote this content into formal spec structure. Users must manually copy, reformat, assign F-IDs, and create acceptance criteria stubs — tedious and error-prone.

`ag formalize` bridges this gap. It is distinct from:
- `enable-formal.sh` — creates directory structure only (spec/, acceptance/, adr/)
- `ag set profile formal` — changes STACK.md settings only
- `migration.sh` — evolves shipped spec contracts

F-0205 migrates **content**: TODO items → FEATURES.md entries + AC stubs.

## Approach

**A standalone bash script `formalize.sh`** called from ag.sh's dispatch table. This follows the established pattern (todo.sh, quick_feature.sh, enable-formal.sh are all standalone scripts).

**Core principle: reuse existing tools, don't rewrite.**
- `quick_feature.sh` for FEATURES.md entry creation (auto-assigns F-ID)
- `todo.sh triage` for marking items promoted
- `mkdir -p` for directory creation (lighter than full enable-formal.sh)

**Per ADR-002 §2**: `ag formalize` does NOT change the profile. It migrates content only. The user separately decides whether to switch profile.

## Files to Create

### `.agentic/lib/tools/formalize.sh` (~180-250 lines)

```
#!/usr/bin/env bash
# formalize.sh — Promote TODO items to formal spec structure
#
# Usage:
#   bash formalize.sh                    # List promotable items
#   bash formalize.sh T-XXXX [T-YYYY]   # Promote specific items
#   bash formalize.sh --all              # Promote all open items
#   bash formalize.sh --dry-run [...]    # Preview without changes
```

**Bootstrap:**
- Source `paths.sh` for `$TODO_FILE`, `$FEATURES_FILE`, `$ACCEPTANCE_DIR`, `$SPEC_DIR`, `$ADR_DIR`
- `cd "$PROJECT_ROOT"` immediately — `quick_feature.sh` uses relative paths internally

**Functions:**

1. **`ensure_spec_structure()`** — `mkdir -p "$SPEC_DIR" "$ACCEPTANCE_DIR" "$ADR_DIR"`. Create minimal FEATURES.md from quick_feature.sh's pattern if `$FEATURES_FILE` missing. Does NOT call enable-formal.sh (avoids profile change side effects). Uses paths.sh variables throughout.

2. **`list_promotable()`** — Parse `$TODO_FILE` inbox: extract `### T-XXXX: Title` lines between `## Inbox` and `## Done`, filtering out struck-through (`### ~~T-`) and closed items. Output: `T-ID|Title` pairs, one per line.

3. **`promote_one(T_ID)`** — Core promotion logic:
   - Extract title from `$TODO_FILE` for T_ID
   - Call `quick_feature.sh "Title"` → capture output, **strip ANSI escape codes** (`sed 's/\033\[[0-9;]*m//g'`), parse F-ID from `✓ Created F-XXXX:` line
   - Create AC stub at `$ACCEPTANCE_DIR/F-XXXX.md`:
     ```markdown
     # F-XXXX: Title

     **Promoted from**: T-XXXX (YYYY-MM-DD)

     ## Acceptance Criteria

     - [ ] **AC-001**: [TODO: Define acceptance criterion]
     ```
   - Call `todo.sh triage T-XXXX feature "Promoted to F-XXXX"`
   - Print: `✓ T-XXXX → F-XXXX: Title`
   - Return non-zero on failure (does NOT abort — caller decides)

4. **`print_summary(promoted, failed)`** — Count promoted/failed, list created files, print settings advisory if `spec_directory` or `feature_tracking` not enabled in STACK.md.

**Argument parsing:**
- No args → call `list_promotable()`, print numbered list
- `--help` / `-h` → usage text
- `T-XXXX [T-YYYY ...]` → promote each item (multi-ID is P1, trivial loop)
- `--all` → promote all from `list_promotable()`
- `--dry-run` → set flag, wrap writes in conditional, print "would promote" instead

**Error handling in batch mode:**
- Do NOT use `set -e` inside the promotion loop
- Track successes and failures per item
- On failure: print which item failed, continue to next
- Summary at end: "Promoted N/M items. Failed: T-XXXX (reason)"

**Idempotency guard:** `list_promotable()` only returns items in the Inbox section. Once `todo.sh triage` moves an item to Done, it won't appear again.

**Output in batch mode:** Suppress `quick_feature.sh` verbose output (capture to variable, extract F-ID only). Only print the `✓ T-XXXX → F-XXXX: Title` summary line per item.

**Auto-flush:** Accept that `todo.sh triage` calls `_try_flush()` per item. Known limitation for `--all` mode — may create multiple commits. Not worth working around in v1.

## Acceptance Criteria

### P1 — Core (MVP)

- AC-001: `ag formalize T-XXXX` creates FEATURES.md entry (status: planned) with auto-assigned F-ID
- AC-002: `ag formalize T-XXXX` creates acceptance criteria stub at `$ACCEPTANCE_DIR/F-XXXX.md`
- AC-003: `ag formalize T-XXXX` marks the TODO item as triaged via `todo.sh triage`
- AC-004: Cross-references preserved: TODO Done section shows "Promoted to F-XXXX", AC stub shows "Promoted from T-XXXX"
- AC-005: `ag formalize --all` promotes all open inbox items
- AC-006: `ag formalize --dry-run` previews without modifying files
- AC-007: Ensures spec directory structure exists (mkdir -p) before promoting
- AC-008: Skips struck-through/closed items (idempotent)
- AC-009: `ag formalize` (no args) lists promotable inbox items
- AC-010: Prints settings advisory if `spec_directory` or `feature_tracking` not enabled
- AC-011: Reuses `quick_feature.sh` and `todo.sh triage` (no duplicated logic)
- AC-012: Multiple T-IDs in one call: `ag formalize T-0001 T-0003 T-0005`
- AC-013: Partial failure in `--all` mode reports per-item success/failure, doesn't abort

## Risks

1. **F-ID collision** — `quick_feature.sh` scans FEATURES.md for max ID. Running formalize with `--all` calls it repeatedly; each call re-scans so IDs increment correctly. No new concurrency risk beyond what already exists. Known limitation: concurrent agents could collide (tracked in T-0045).

2. **Output parsing** — We parse `quick_feature.sh` output (`✓ Created F-XXXX:`) to get the assigned ID. **ANSI color codes must be stripped** before parsing (`sed 's/\033\[[0-9;]*m//g'`). Mitigation: we control both scripts; add a comment in quick_feature.sh noting the output is parsed by formalize.sh.

3. **TODO.md format variations** — Some items have `~~strikethrough~~`, some have `**OBSOLETE**`/`**DONE**` markers. The filter needs to handle both. Mitigation: filter on `### ~~T-` prefix pattern (which covers all closed items in current TODO.md).

4. **CWD dependency** — `quick_feature.sh` uses relative path `".agentic/spec/FEATURES.md"`. `formalize.sh` must `cd "$PROJECT_ROOT"` before calling it. Also note: `quick_feature.sh` has a pre-existing bug where it creates `mkdir -p spec` (not `.agentic/spec`). Our `ensure_spec_structure()` runs first with correct paths, so this is a non-issue in practice.

5. **Auto-flush storm** — `todo.sh triage` calls `_try_flush()` per invocation. In `--all` mode with N items, that's N auto-commit attempts. Accepted limitation for v1 — `_try_flush()` is best-effort and only runs on main branch.
