# F-0206: Feedback Capture System — Implementation Plan

**Status**: DRAFT
**Feature**: F-0206 (child of F-0188, depends on F-0202 which is shipped)
**ADR**: ADR-002 §5.2

## Context

Users test working software (via `ag run`) and give feedback — but there's no structured way to capture, classify, and route that feedback. Currently feedback stays in chat, unstructured, and agents must manually decide whether to create a TODO, issue, or AC adjustment. The autonomous engine has in-flight feedback (`EngineState.add_feedback()`) but it's memory-only and lost when the engine stops.

All the routing targets already exist (`todo.sh`, `quick_issue.sh`, `feature.sh`). What's missing is the classification layer that connects feedback to the right target, and persistence.

## Approach

**`ag feedback` is a routing mechanism, not a data-entry form.** Users give feedback naturally (chat or `ag auto feedback`). The agent calls `ag feedback` to classify and persist it. Keyword heuristics classify feedback (no LLM call needed). Routing reuses existing tools.

### New command: `ag feedback`

```
ag feedback "text"                                    # Classify + persist (default: add)
ag feedback --bug "text" [--feature F-XXXX]           # Direct route to ISSUES.md
ag feedback --feature "text"                          # Direct route to TODO.md
ag feedback --ac F-XXXX AC-XXX "text"                 # AC adjustment reference
ag feedback log [--pending]                           # Show feedback log
ag feedback route FB-XXXX                             # Route a pending item
ag feedback classify FB-XXXX bug|feature|ac-adjust    # Reclassify
ag feedback done FB-XXXX ["resolution"]               # Mark resolved
```

### Persistent log: `.agentic/FEEDBACK_LOG.md`

FB-XXXX IDs (sequential, like T-XXXX, I-XXXX, HN-XXXX). Two sections: Pending + Routed. Each entry has: Added date, Type (bug/feature/ac-adjust/unclear), Feature ref, Routed-to target.

### Classification heuristics (keyword-based)

- **bug**: "broken", "crash", "error", "fails", "regression", "not working", "bug", "wrong"
- **feature**: "would be nice", "add", "new feature", "could you", "wish", "request"
- **ac-adjust**: contains "AC-" or references specific criteria
- **unclear**: anything else → routed to TODO.md as unclassified

### Routing targets

| Type | Tool called | Target |
|------|-------------|--------|
| bug | `quick_issue.sh "$title" "$priority"` | ISSUES.md |
| feature | `todo.sh add "$text"` | TODO.md |
| ac-adjust | Log with AC ref; agent updates AC file | FEEDBACK_LOG.md |
| unclear | `todo.sh add "$text" "Unclassified FB-XXXX"` | TODO.md |

### `feedback_mode` setting

Added to `profiles.conf`:
- `discovery` / `formal`: `pr_review` (agent logs, human classifies)
- `autonomous_formal`: `working_software` (agent auto-classifies, human confirms)

In `automated` mode (set manually), route immediately without confirmation.

### Autonomous engine integration

1. `engine.py._cleanup()`: flush remaining `EngineState._feedback` to `FEEDBACK_LOG.md` via `feedback.sh add`
2. `control.py`: when engine is not running, `ag auto feedback` falls back to `feedback.sh add` directly

### Iteration loop (MVP = manual)

Agent suggests next steps after routing feedback. No auto-iteration into scheduler. The loop is conversational: feedback → route → agent suggests "fix it now?" → user decides → implement → `ag run` again.

## Acceptance Criteria

- **AC-001**: `ag feedback "text"` classifies via keyword heuristics, persists to FEEDBACK_LOG.md with FB-XXXX ID
- **AC-002**: `--bug` routes to ISSUES.md via quick_issue.sh; `--feature` routes to TODO.md via todo.sh
- **AC-003**: `--ac F-XXXX AC-XXX "text"` logs AC adjustment with feature/AC cross-reference
- **AC-004**: `ag feedback log` shows entries; `--pending` filters to unrouted
- **AC-005**: `feedback_mode` setting in profiles.conf, resolved by get_setting
- **AC-006**: Engine cleanup flushes in-flight feedback to FEEDBACK_LOG.md
- **AC-007**: `ag auto feedback` falls back to feedback.sh when engine not running
- **AC-008**: All instruction files updated (CLAUDE.md template, cursorrules, copilot, codex, memory-seed, auto_orchestration, agent_operating_guidelines)
