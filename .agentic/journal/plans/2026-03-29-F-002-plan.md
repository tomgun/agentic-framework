# Implementation Plan: Configurable Definition of Done per Task Type

**Task**: Improvement to F-002 (Spec-Driven Development), originally F-0210  
**Scope**: Make DoD explicit, configurable, and task-type-aware  
**Approach**: Minimal viable change with configuration-over-code philosophy

---

## Design Decisions

### D1: Where DoD definitions live — `.agentic/lib/presets/dod.conf`

**Decision**: New file `.agentic/lib/presets/dod.conf`, following the exact pattern of `profiles.conf` and `constraints.conf`.

**Rationale**:
- STACK.md settings are key-value primitives (scalar values). DoD checklists are multi-item lists per type — STACK.md cannot express this cleanly.
- A dedicated `.agentic/spec/DOD.md` is user-facing markdown, tempting but wrong: agents and code need structured, parseable data, not prose.
- `presets/dod.conf` follows the established convention (profiles.conf, constraints.conf live here). It is a framework-owned default that users can override via `.agentic/local/extensions/done-checks/` scripts or a future STACK.md setting.

**Format** (similar to profiles.conf):
```
# format: dod-v1.0
# Definition of Done checklists per task type.
# Format: type.item_key=label | enforcement
# enforcement: required | advisory | skip_for_type
# 
# Users override per-project via STACK.md setting:
#   - dod_type: spike   (force a specific DoD type for current work)
#
# Default task type = "implementation" (preserves current behavior exactly)

# --- implementation (default — current behavior preserved) ---
implementation.ac_met=All acceptance criteria met | required
implementation.tests_passing=Tests written and passing | required
implementation.features_updated=FEATURES.md updated (status: shipped) | required
implementation.docs_updated=Docs updated (if behavior changed) | advisory
implementation.code_reviewed=Code reviewed (self-review at minimum) | advisory
implementation.smoke_tested=Smoke tested (actually RUN it) | advisory
implementation.journal_updated=JOURNAL.md updated | advisory

# --- spike (research/investigation) ---
spike.findings_documented=Findings documented | required
spike.decision_recorded=Decision/conclusion recorded | required
spike.next_steps=Next steps captured | required
spike.ac_met=Acceptance criteria met (if any) | advisory
spike.tests_passing=Tests written and passing | skip_for_type
spike.journal_updated=JOURNAL.md updated | advisory

# --- bugfix ---
bugfix.failing_test=Failing test written first | required
bugfix.fix_implemented=Fix implemented and test passes | required
bugfix.regression_test=Regression test added | required
bugfix.ac_met=All acceptance criteria met | advisory
bugfix.docs_updated=Docs updated (if behavior changed) | advisory
bugfix.journal_updated=JOURNAL.md updated | advisory

# --- docs ---
docs.content_written=Documentation content written | required
docs.reviewed=Content reviewed for accuracy | required
docs.registered=Doc registered in STACK.md (if new) | advisory
docs.tests_passing=Tests passing | skip_for_type
docs.code_quality=Code quality check | skip_for_type

# --- infrastructure ---
infrastructure.ac_met=All acceptance criteria met | required
infrastructure.tests_passing=Tests written and passing | required
infrastructure.features_updated=FEATURES.md updated (status: shipped) | required
infrastructure.docs_updated=Docs updated (if behavior changed) | advisory
infrastructure.code_reviewed=Code reviewed | advisory
infrastructure.smoke_tested=Smoke tested | advisory
infrastructure.journal_updated=JOURNAL.md updated | advisory
```

### D2: How task type is resolved — cascade with explicit override

**Resolution order** (mirrors the 3-level settings pattern):
1. **Explicit flag**: `ag done F-XXXX --type spike` (highest priority)
2. **STACK.md setting**: `- dod_type: spike` in `## Settings` (project-wide override)
3. **Contract metadata**: `tags: [spike]` or `category: research` in the YAML contract
4. **FEATURES.md type**: `**Type**: research` field parsed from the feature block
5. **Default**: `implementation` (preserves current behavior)

**Mapping from existing metadata to DoD types**:
- `tags: [spike]` or `tags: [research]` -> `spike`
- `tags: [bugfix]` or `tags: [fix]` -> `bugfix`  
- `tags: [docs]` or `tags: [documentation]` -> `docs`
- `category: research` or FEATURES.md `**Type**: research` -> `spike`
- `category: dev-infrastructure` or FEATURES.md `**Type**: infrastructure` -> `infrastructure`
- Everything else -> `implementation`

### D3: How gates become type-aware — gate skip-lists per type

Rather than threading `task_type` through every gate function signature (high blast radius), we add a **skip-list resolver** that checks which gates to skip based on task type. The state machine's `check_gate` method consults the DoD config and auto-allows gates marked `skip_for_type` for the resolved task type.

Concretely:
- `spike` skips gate 3 (criteria_set -> tests_written) and gate 5 (implementing -> verified) test requirement
- `docs` skips gate 3 and gate 5 test requirement
- `bugfix` and `implementation` run all gates (no skips)

### D4: Default task types

| Type | DoD Focus | Gates Skipped |
|------|-----------|---------------|
| `implementation` | Full ceremony (current behavior) | None |
| `spike` | Findings + decision + next steps | tests_written, verified (test check) |
| `bugfix` | Failing test first, regression test | None (stricter on test ordering) |
| `docs` | Content written + reviewed | tests_written, verified (test check) |
| `infrastructure` | Same as implementation | None |

**Files changed**: 2 new, 0 modified

#### 1b. Create `/workspace/.agentic/lib/dod.py` — DoD parser and resolver
- ~120 lines Python module
- `parse_dod_conf(path: Path) -> dict[str, list[DodItem]]` — parse dod.conf into structured data
- `DodItem` dataclass: `key: str, label: str, enforcement: str` (required/advisory/skip_for_type)
- `get_dod_items(task_type: str, project_root: Path) -> list[DodItem]` — returns items for a type
- `resolve_task_type(feature_id: str, project_root: Path, explicit_type: str | None = None) -> str` — cascade resolution per D2
- `get_skipped_gates(task_type: str, project_root: Path) -> set[str]` — returns gate names to skip
- Follow the exact pattern of `settings.py`: module-level cache, `_LIB_DIR` setup, import from `paths`
- `resolve_task_type` implementation:
  1. Check `explicit_type` argument (from CLI flag)
  2. Check `get_setting(root, "dod_type", "")` for STACK.md override
  3. Load contract YAML, check `tags` for spike/bugfix/docs keywords
  4. Read FEATURES.md block, check `**Type**` field
  5. Return "implementation" as default

**Key code locations to follow as patterns**:
- `/workspace/.agentic/lib/settings.py` — for module structure, caching, path setup
- `/workspace/.agentic/lib/presets/profiles.conf` — for conf file format convention
- `/workspace/.agentic/lib/auto/gates.py` lines 73-100 — for `_read_feature_block` / `_read_feature_component` pattern (reuse for `_read_feature_type`)

Add a `_read_feature_type` helper (following `_read_feature_component` pattern at lines 89-100):
```python
def _read_feature_type(feature_id: str, project_root: Path) -> str | None:
    """Extract the Type field from a feature block, or None."""
    block = _read_feature_block(feature_id, project_root)
    if not block:
        return None
    m = re.search(r"\*\*Type\*\*:\s*(\S+)", block)
    if not m:
        m = re.search(r"-\s*Type:\s*(\S+)", block)
    if m:
        val = m.group(1).strip().lower()
        return val if val != "none" else None
    return None
```

Modify `gate_criteria_set_to_tests_written` (lines 180-223) and `gate_implementing_to_verified` (lines 254-338) to be type-aware:

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| dod.py import failure in done.sh | DoD checklist reverts to hardcoded | Explicit fallback in bash: `|| { hardcoded list }` |
| Gate skip changes break formal workflow | Users lose test enforcement | "implementation" type = no skips = current behavior. Skips only for explicitly-set types. |
| Contract schema change breaks existing contracts | YAML parse errors | Field is optional, defaults to null, old contracts unchanged |
| settings.py cache stale after dod_type change | Wrong DoD displayed | dod.py uses its own cache keyed on project root (same pattern as settings.py) |

## What This Does NOT Do (Intentional Scope Limits)

1. **No custom user-defined types** — the 5 built-in types cover known use cases. Custom types can be added later by extending dod.conf.
2. **No per-feature DoD override in contract YAML** — the `task_type` field on contracts maps to one of the 5 types, not an arbitrary checklist. True per-feature customization is out of scope.
3. **No runtime DoD editing** — no `ag dod edit` command. Users modify dod.conf directly or override via settings/tags.
4. **No skip-transition changes** — the state machine's `SKIP_TRANSITIONS` table is not modified. Type-awareness is handled entirely through gate function behavior.
5. **No BACKLOG.json type changes** — backlog items have `type: task | feature` which is orthogonal to DoD task types.
