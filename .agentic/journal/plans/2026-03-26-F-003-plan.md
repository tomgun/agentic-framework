# Plan: Fix Post-Plan-Mode-Exit Behavior

**Feature**: F-003 (Feature Tracking & Lifecycle) — plan-scan + hook + session-start safety net

## Context

When an agent exits plan mode, the PostToolUse hook fires `on-plan-mode-exit.sh` → calls `plan-scan.sh` to save the plan durably → prints auto-continue instructions. This chain is fragile at multiple points:

**Bug 1 — plan-scan can't extract F-ID**: `extract_primary_id()` has 4 patterns but none match plans where the F-ID appears in body text (e.g., `**Task**: ... F-003`). Returns empty → plan silently skipped.

**Bug 2 — hook failure path gives wrong instructions**: When plan-scan fails, the hook says "save manually" instead of auto-continue instructions. Contradicts CLAUDE.md.

**Structural gap — no session-boundary safety net**: The ExitPlanMode hook is a "push" mechanism — it tries to inject instructions at the moment of exit. If it fails (session ends, plan-scan bug, hook doesn't fire), there's NO "pull" mechanism at the next session start to catch it. The dashboard shows orphan plans, but that relies on the same broken plan-scan, and the agent has to behaviorally choose to run the dashboard. The SessionStart hook (`SessionStart.sh`) doesn't check for orphan plans at all.

## Changes

### 1. Add fallback pattern to `extract_primary_id()` (~8 lines)

**File**: `.agentic/lib/tools/plan-scan.sh` lines 140-147

After Pattern 3 (Feature metadata), before the empty return, add Pattern 4 — any F-ID in the first 10 lines:

```bash
# Pattern 4: Any F-XXXX in the first 10 lines (broad fallback)
fid=$(echo "$header" | grep -oE "$FEATURE_ID_ERE" | head -1 || true)
if [[ -n "$fid" ]]; then
    echo "$fid"
    return
fi
```

Intentionally last — safety net, not primary path. The known-features check at line 165 still prevents cross-project pollution.

### 2. Fix hook failure path in `on-plan-mode-exit.sh` (~20 lines)

**File**: `.agentic/lib/hooks/shared/on-plan-mode-exit.sh` lines 103-111

Replace "save manually" with profile-aware auto-continue instructions matching the success path. The agent gets the same behavioral guidance regardless of whether plan-scan succeeded.

### 3. Add orphan-plan check to SessionStart hook (~15 lines)

**File**: `.agentic/lib/claude-hooks/SessionStart.sh`

After the git status check (section 6, ~line 92), add:

```bash
# 6.5. Orphan plan detection (session-boundary safety net)
if [[ -x ".agentic/lib/tools/plan-scan.sh" ]]; then
    ORPHAN_COUNT=$(bash .agentic/lib/tools/plan-scan.sh --check 2>/dev/null | grep -oE '[0-9]+ unsaved' | grep -oE '[0-9]+' || echo "0")
    if [[ "$ORPHAN_COUNT" -gt 0 ]]; then
        echo -e "${YELLOW}📝 $ORPHAN_COUNT unsaved plan(s) found in ephemeral locations${NC}"
        echo "  FIRST ACTION: run plan-scan to save, then review before implementing"
        echo "  bash .agentic/lib/tools/plan-scan.sh"
    fi
fi
```

This is the "pull" mechanism: every new session checks for plans that were never saved durably. Even if the ExitPlanMode hook failed, the next session catches it.
